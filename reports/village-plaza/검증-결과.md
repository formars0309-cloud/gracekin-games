설치된 Codex 런타임의 Playwright와 Google Chrome을 사용했다. 프로젝트 의존성으로 브라우저 도구를 추가하지 않았다. 격리 임시 DB·시험 회원·쿠키만 사용하며 직접 시작한 서버·브라우저와 임시 DB는 종료·정리한다.

## 서버에서 검증한 동작

- 서울 2월 말·3월 1일 경계, 2026·2027학년도에 따른 초등학생·중학생·고등학생·성인 마을 배정, 미취학 거부와 선택 가능 연도 범위를 확인했다.
- 출생연도는 확인 표시가 있어야 최초 1회 저장되고 재저장은 409다. 본인의 수정·삭제 API는 없으며, 출생연도 확정 전에는 옷장 저장·WebSocket 입장이 거부된다. 출생연도는 다른 회원에게 방송하지 않는다.
- `under14`의 과거 연도와 `14plus`·`legacy`의 어린이 연도를 거부한다. 특히 2월 경계에서 연령 일관성 검사를 통과하는 해라도 보호자 동의 없는 초등학생 입장을 별도로 거부한다. 저장소에 잘못된 배정 값이 있어도 출입 단계에서 차단한다. v4·동의 철회 계정의 입장 차단은 유지한다.
- 네 마을에 같은 채널 번호를 사용해도 이동·채팅·감정·입장자·채널 목록이 전달되지 않는다. 다른 마을 채널 요청·운영자 둘러보기 우회·다른 마을/채널 회원 신고를 거부한다. 같은 마을 신고는 그 버퍼만 스냅숏으로 저장한다.
- 성인·초등학생 마을에 각각 51명을 동시에 연결하여 두 마을 모두 50명까지 1번, 51번째는 자기 마을 2번 채널로 배정됨을 확인했다.
- 중학생 마을 안에서도 어린이는 자유 채팅을 받지 않고 정해진 문구·감정을 받는다. 기존 발신 제한·차단·도배·신고·금지·종료·아바타 시험도 유지했다.
- 운영자만 출생연도를 조회·수정할 수 있고 사유·revision이 필요하다. 동시 수정은 200/409, 감사 저장 실패는 프로필까지 롤백한다. 수정 전후 연도·사유·운영자 기록과 수정 후 연결 종료·새 마을 입장을 확인했다.
- 서울 새 학년도 검사 뒤 초등→중학, 고등→성인으로 연결을 종료하고 재접속시켰다. 입장 마을과 학년도는 같은 시각으로 계산하고 현재 배정도 다시 비교해 경계 순간의 일관성을 지킨다.
- 운영자가 네 마을을 둘러보며 운영자 표시를 받는다. 신고·채팅 제한의 관리자 응답에는 마을 이름을 포함한다.
- 이전 통합 광장 DB를 이관해도 기존 신고는 `legacy`로 남기고 회원의 출생연도를 추정하지 않는다. 출생연도 프로필 탈퇴 삭제, 기존 1년 정리와 보호자 동의 원문 보존도 전체 회귀시험에 포함한다.

## 결정에서 벗어난 점과 남은 위험

지시한 네 마을·학년도 계산·입력 조건·보호자 동의·시행 잠금을 유지했다. 재위임 없이 같은 브랜치에서 직접 구현했다. 지도는 현재 같은 파일을 사용하고 마을 레지스트리에서 교체할 수 있도록 했다. 기존 출생연도는 추정·이관하지 않았다.

출생연도는 자기 입력이라 실제 연령을 검증하지 못한다. 성인이 출생연도를 속여 중·고등학생 마을에 입장할 위험이 남는다. 초등학생 마을만 어린이 가입·v5 동의 조건을 추가로 강제하지만 기존 이메일 동의가 실제 가족관계·나이를 인증하는 것은 아니다. 조기입학·유예·실제 재학 여부는 반영하지 않는다. 입력 일관성 조건은 요청대로 `under14 ≥ 올해−14`, `14plus/legacy ≤ 올해−13`이며 생일을 모르는 한 정확한 만 나이를 판정하지 않는다.

기존 `ageBand`를 출생연도에서 자동으로 바꾸지 않는다. 학년도에 따른 마을은 자동 변경하지만 어린이 계정의 자유 채팅·보호자 동의 제한은 기존 가입 구분을 유지한다. 기존 v4 어린이 재동의 흐름, 운영자 문의 확인 절차, 실제 운영 부하·다중 인스턴스·백업 삭제, 캐릭터 렌더러 교체는 후속 과제다.

공고·배포는 별도 지시 뒤에 진행한다. 기존 약관의 고지 기준과 개정 성격·공고 일정을 먼저 대조하고, v5 문서와 서버 잠금·보존·연령 분리가 같은 버전으로 준비된 후 운영자가 배포·시행 순서를 검증해야 한다. 이번에는 main 커밋·푸시·배포·공지 게시를 하지 않았다. 이전 단계 결과는 1차 215/215, 2차 223/223이며 이번 보고서가 최신이다.
