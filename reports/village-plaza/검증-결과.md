필수 최종 검증의 실패·건너뜀은 없다. 초기 새 시험의 회원가입 400 오류는 시험용 이메일에 한글 식별자를 넣은 데서 생겼으며 ASCII 시험 주소로 고쳐 해결했다. 운영 코드에서 이메일 검증을 완화하지 않았다. 의존성 변경이 없어 이번에는 다시 설치하지 않았다. 1차의 `npm ci --ignore-scripts`는 성공했고, 당시 추가 감사에서 기존 mailparser·nodemailer의 중간 등급 2건을 확인했다. 이번에 해당 의존성을 바꾸거나 새 감사를 실행하지는 않았다.

브라우저 재현 명령:

```sh
PLAYWRIGHT_MODULE=/Users/app/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules/playwright/index.mjs PLAYWRIGHT_EXECUTABLE_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' node test/village-browser.mjs
```

프로젝트에 Playwright를 의존성으로 추가하지 않았다. 설치된 Codex 런타임의 Playwright와 기존 Google Chrome으로 실행했다. 스크립트는 격리된 임시 DB·시험 회원·쿠키만 사용하고 직접 띄운 서버·브라우저와 임시 자료를 정리한다. 일반 환경에서는 설치한 `playwright`와 Chromium을 사용하거나 위 두 경로를 해당 환경에 맞게 지정할 수 있다.

## 실제 확인한 동작

- 어린이 수신자에게 자유 채팅 프레임을 보내지 않는다. 정해진 문구·감정은 전달하고 어른은 둘 다 받는다. 접속 중 연령이 바뀌어도 현재 DB 연령을 다시 확인한다. 어린이의 신고 스냅숏에는 기존대로 서버 기록의 대상 자유 대화도 들어간다.
- 시행 직전 일반 회원의 세션·WebSocket 입장·아바타 저장·새 차단 추가는 403, 운영자의 입장·저장은 허용한다. 시행 시각부터 일반 회원을 허용하고 설정 시각 변경도 안내 날짜에 반영한다. 시간대 없는 설정은 서버 시작에서 거부한다.
- v4 동의 어린이는 마을 입장·아바타 저장을 거부하고 추가 동의를 안내한다. 새 차단 추가도 입장·동의 조건을 검사하되 기존 차단 조회·해제는 허용한다. 기존 계정 로그인과 당시 동의 본문·판을 보존한다. v5 어린이는 입장한다. 기존 자동 회신 검증은 새 판에서도 전체 시험을 통과했다.
- 실제 서버 재시작에서 생성 후 달력상 1년이 지난 신고·스냅숏·제한·감사를 삭제하고 경계 안 자료는 유지한다. 같은 정리 함수를 24시간 간격으로 예약하고 실행하는 시험과 윤년 경계 시험을 포함한다. 탈퇴 외래키 CASCADE와 본인 차단 해제의 즉시 삭제도 확인했다.
- Pages·다른 마을 출처는 고정된 커뮤니티 출처로 이동한다. 정식 출처·localhost·127.0.0.1·IPv6 로컬은 유지한다. Playwright에서도 Pages 주소를 재현하여 API 요청·WebSocket 없이 이동함을 확인했다. 쿼리·해시도 기존 방식대로 보존한다.
- 기존 데스크톱·390px 옷장, 실제 클릭 A* 이동, 두 회원 채팅·감정, 방향키·로그인 안내를 다시 확인했다. 어린이 화면은 자유 입력을 숨기고 기록 창 위 안내와 문구·감정만 표시한다. 시행 전 화면에는 서버가 계산한 날짜를 표시하며 WebSocket을 시작하지 않는다.
- 개인정보처리방침 정본, 이용약관, `/privacy/` 안내를 각각 데스크톱·390px에서 열어 가로 넘침·제목 구조·시행일을 검사하고 화면을 직접 열어 확인했다.

## 결정에서 벗어난 점과 남은 일

확정한 어린이 수신 제한, Pages 전환, 보존 기간·시행일·v5 조건을 유지했다. 재위임·하위 워크트리 생성 없이 같은 브랜치에서 직접 구현했다. 기존 공용 출처 스크립트를 재사용·확장했으며 새 출처 스크립트나 재동의 흐름을 만들지 않았다.

기존 보호자 API는 신규 가입용 일회성 신청·승인·가입만 제공하고, 이미 가입한 계정과 새 동의를 연결하는 API·화면은 없다. 따라서 기존 v4 어린이는 후속 재동의 기능과 실제 동의 확인 전까지 마을 이용이 계속 막힌다. DB 판 번호를 일괄 변경하거나 새 계정으로 다시 가입하도록 안내하지 않는다.

배포 순서는 (1) 개정 문안과 기존 약관 3절의 중요 변경 30일·개별 고지 기준 적용을 확인, (2) 별도 지시에 따라 공고일의 개정 공지를 실제 게시, (3) 별도 배포 지시를 받은 뒤 방침·서버 v5·입장 잠금·정리를 같은 버전으로 준비·검증, (4) 2026-11-27 00:00 KST부터 일반 회원 허용이다. 공고·배포가 늦어지면 운영자가 고지 일정과 서버 설정을 다시 대조해야 한다. 이번에는 공지 게시·main 푸시·배포를 하지 않았다.

운영 부하·프록시·다중 인스턴스·백업 사본 삭제, 캐릭터 만들기 렌더러 교체는 후속 확인·구현 대상이다. 1차 검증은 전체 215/215·브라우저 8/8이었으며 이번 결과가 최신이다.
