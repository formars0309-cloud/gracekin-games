필수 검증의 실패·건너뜀은 없다. 별도 의존성 감사는 위 기존 항목으로 종료 코드 1을 반환했다. Playwright 기본 브라우저 버전이 설치되어 있지 않아 설치된 Google Chrome을 명시해 실행했다. 최초 시험 작성 중 내장 WebSocket의 Host 덮어쓰기 제한과 better-auth의 프로세스 공용 IP 제한을 확인하여, 옛 Host는 실제 HTTP 업그레이드 요청으로 검사하고 회원가입 시험은 서로 다른 시험 IP를 사용하도록 고쳤다. 최종 회귀시험은 모두 통과했다.

브라우저 재현 명령:

```sh
PLAYWRIGHT_MODULE=/Users/app/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules/playwright/index.mjs PLAYWRIGHT_EXECUTABLE_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' node test/village-browser.mjs
```

일반 환경에서는 설치된 `playwright`를 자동으로 읽고 기본 Chromium을 사용한다. 별도 설치 경로와 Chrome 실행파일은 위 환경 변수로 지정할 수 있다. 스크립트는 임시 DB·시험 회원·세션을 준비하고 종료 시 브라우저·서버·임시 DB를 정리한다.

## 검증한 동작

실제 서버와 Node 24 내장 WebSocket 클라이언트로 비회원·잘못된 Origin·옛 Host 거부, 두 회원의 이동·채팅·감정, 채널 50명 및 51번째 자동 배정, 가득 찬 채널 입장 거부를 확인했다. 평소 대화가 DB에 저장되지 않으며 신고 때만 대상의 대화 스냅숏이 저장됨을 확인했다. 채널 최근 50개 경계와 10분 만료도 검사했다.

충돌·지도 밖·비인접·임의 속도 입력의 서버 위치 교정, 최대 이동 속도, 어린이 자유 입력 우회 거부와 정해진 문구·감정 통과, 보호자 동의 철회, 도배와 재접속을 통한 우회 거부, 금칙어·80자 제한, 서버 차단 및 차단 해제를 검증했다. 운영자의 실제 신고 조회·시간 지정 금지·만료 복구, 일반 회원의 관리자 API 거부, 중복 접속 종료, 접속 중 세션 만료, 서버 종료 안내·1012 코드, 아바타 동시 revision 409와 팔레트 외 값 거부를 검사했다.

두 브라우저 컨텍스트에서는 옷장 선택·저장·입장, 클릭으로 A* 경로 생성 및 상대에게 서버 이동 반영, 양방향 채팅과 기록, 모바일 하트 전달, 방향키 이동, 비회원 로그인 안내를 확인했다. 390px 화면의 가로 넘침은 없었다. 맵의 다섯 문과 복귀 칸·충돌·도달성, A* 분수 우회, 정적 검사 예외 밖의 추가 소켓·외부 맵·추가 fetch·브라우저 저장소 거부도 회귀시험에 포함했다.

## 결정·남은 일

사용자가 정한 서버·인증·렌더러·아바타·채널·이동·채팅·맵·운영 패키지 결정을 유지했다. 하위 워크트리 생성 금지 지시를 우선하여 현재 작업 브랜치에서 담당 파일을 나눠 구현했다. `main` 직접 커밋·푸시, 다른 워크트리 수정, `fly deploy`를 하지 않았다.

동봉한 원본 Phaser MIT 라이선스는 문안 변경 없이 줄끝만 CRLF에서 LF로 정규화했다. 새 파일을 포함하는 커밋 전 공백 검사를 통과하도록 처리했으며 정적 검사의 라이선스 SHA256도 정규화한 파일에 맞췄다. Phaser 자바스크립트 배포물은 변경하지 않았다.

후속 캐릭터 만들기는 `assets/village/avatar.js`의 `drawAvatar(container, avatarData)`를 교체한다. 건물은 공용 맵의 다섯 문 properties와 기획 문서의 모듈 규격에 맞춰 추가한다. 개인정보처리방침·약관·보호자 동의문 원본은 변경하지 않았으며 [기획 문서](../../docs/기획/그레이스킨-마을.md)의 개정 초안, 실제 보존기간과 계정 삭제·철회 시 삭제 절차를 배포 전에 확정해야 한다.

실제 운영 출처·쿠키·WebSocket 프록시, 50명 부하·메모리, 유휴 정지 후 재접속, 단일 프로세스의 채널 상태와 다중 인스턴스 운영 방식은 배포 전 확인 대상이다. `noindex`와 비연결 상태는 접근 권한을 부여한 회원의 직접 URL 입장을 막는 기능이 아니다. 기존 `npm ci` 감사 알림의 mailparser·nodemailer 관련 보통 심각도 2건은 새 `ws` 추가와 별개이며 이번 변경에서 다른 의존성까지 갱신하지 않았다.
