# 아바타 얼굴·머리·전신 통합 검수

기준 공방 `4e516d0`에서 출발한 얼굴 조형 `d435eac`에는 네 종류 머리 `ef5c09e`와 얼굴 원형·저장 호환 `f745d3b`가 들어 있다. 최종 작업 브랜치에서 전신 비례 `63ec215`를 병합했다. 공방의 두 프리셋을 이전 커밋과 최종 운영 파일 사본에서 각각 실행해 촬영했다.

## 원화와 공방 얼굴

두 공방 모두 모바일 웹킷의 같은 화면 크기에서 촬영했다. 비교판은 동공 사이 간격과 눈높이를 맞춰 등비 확대했다. 가운데 원화의 SHA-256은 제공된 파일과 저장소 원본에서 일치했다. [기존 모델·생성 원화·최종 얼굴](이전-공방과-원화와-최종-얼굴.jpg)

미소년은 곧은 눈썹과 좁은 눈매, 미소녀는 둥근 눈매와 윗입술 모양이 원화와 닮았다. 정면에서 양쪽 홍채가 같은 방향을 보고, 사선에서는 먼 쪽 눈이 자연스럽게 좁아졌다. 동공 간격을 맞춘 첫 비교에서 코밑·입술·턱끝이 원화보다 위에 모여 보여 눈 아래 세로 길이를 보정했다. 최종 정면에서 코와 입의 위치가 원화에 가까워졌다. 공방 염색을 적용한 홍채·머리 색과 앞머리 모양은 원화와 다르다. 확대하면 원화보다 입술 윤곽이 부드럽고 머리카락이 굵은 다발로 보인다.

이전 검수 시안의 소년 가르마 옆에는 피부색 점이 있었다. 완료된 헤어 모듈로 처음 합친 화면에서는 그 점이 재현되지 않았다. 이마의 해당 네 지점에서 피부와 머리 삼각면의 깊이를 비교하는 회귀 검사를 추가했다. 이전 시안 모듈은 이 검사에서 실패했고 최종 모듈은 통과했다. 앞이마에 잔가닥을 더하고 광택을 낮췄다. 턱밑 곡면을 귓불 뒤로 잇고 목 윗부분의 폭과 깊이를 줄여, 측면에서 목이 볼 앞으로 잘라 들어오던 경계를 완화했다. [사선 앞머리와 측면 턱선 확대](앞머리와-턱선-보정.jpg)

얼굴·귀·머리카락은 같은 머리 관절을 따른다. 두 기본 원형을 15°씩 한 바퀴 돌려 첫 장면과 마지막 장면의 화소가 일치하는지 검사했다. 좌우 측면에서 가까운 눈과 코끝이 윤곽에 남고, 뒤에서는 후두부가 얼굴을 가렸다. 검수한 각도에서 별도 얼굴판이 뜨거나 좌우가 뒤집히는 현상, 앞머리 중앙을 뚫고 나오는 피부는 보이지 않았다. 원화는 정면 한 장이어서 측면 코끝·뒤통수의 실제 원형과의 일치도는 판단할 수 없다. [두 원형의 회전](두-원형-한-바퀴.jpg)

## 기능과 패키지 검증

| 항목 | 확인한 결과 |
| --- | --- |
| 대문 → 공방 → 내 계정 → 공방 | 두 브라우저의 데스크톱·모바일에서 이름, 체격, 눈·코·턱 슬라이더, 눈동자색과 옷 색을 편집했다. 직업 10문답, 추천 적용, 수동 직업 변경, 로그인, 회원 저장, 새로고침과 복귀를 거쳤다. 회원 API와 팩 안 스냅샷의 외형·직업 값이 편집값과 일치했다. |
| 원형과 옛 데이터 | 원형 없는 옛 손님 초안을 열어 눈·코·턱·머리를 바꾸고 원형 전환·실행 취소·다시 실행·새로고침을 확인했다. 원형 없는 회원 행의 조회와 다음 저장 시 변환을 임시 데이터베이스에서 검증했다. |
| 게임 모드 | 저장한 외형과 직업으로 별도 그린 초상·보드판·탐험 화면의 픽셀이 실제 계정·게임 화면과 일치했다. 데스크톱 방향키와 모바일 이동 버튼을 확인했다. |
| 내려받기 | 실제 공방에서 ZIP을 내려받았다. 별도 외형 4종 검사에서 초상·게임말·동작 시트의 투명도, 4방향 대기·보행과 두 JSON을 확인했다. 공방에서 편집한 숲길잡이·룬술사는 두 엔진 모두 192×192 칸 24개 전부에서 불투명 화소와 투명 배경을 담았고 최소 여백은 각각 4·5픽셀이었다. |
| 정적 자산 | 새 머리 조형 함수가 두상 생성 시 호출된다. 얼굴과 머리 명암 데이터는 같은 출처의 자바스크립트 모듈로 읽는다. 헤어 모듈 2개를 Docker 허용 목록에 추가했다. Dockerfile의 복사 대상과 허용 목록을 적용한 파일 126개로 운영 모드 서버를 띄워 아바타 자산 23개의 HTTP 응답·형식과 회원 저장을 확인했다. 이 환경에는 Docker 실행 파일이 없어 컨테이너 이미지를 직접 빌드하지 않았다. |
| 렌더러 | 그래픽 가속, 가속 손실·미지원 시 2차원 대체 렌더러, 투명 프레임의 절대 방향과 보행 위상을 검증했다. 두 얼굴 × 네 머리 × 네 직업 × 슬라이더 양 끝의 64개 조합에서 모든 정점이 유한했고, 최대 55,026개 정점이 16비트 인덱스 범위에 들었다. |
| 저장소 | 노드 테스트 224개, 정적 검사 3,390개, 파이썬 보안 테스트 40개, 독립 HTTP 검사 70개가 통과했다. 커밋 대상의 공백 오류와 민감정보 패턴을 검사했다. |
