## 정적 페이지와 운영 파일

- 단순 HTTP 파일 서버에서 대문 링크, 공방의 모듈 로딩, 손님 편집, 보드 이동과 새로고침 초안 복구를 확인했다. 공식 대문 호스트를 로컬 콘텐츠에 연결한 브라우저 시험에서는 공방이 계정 서버의 고정 주소로 이동했고, 설문 링크는 도착 후 첫 질문을 열었다.
- Dockerfile의 복사 경로와 `.dockerignore`의 명시 허용 목록에 따라 파일 122개를 임시 폴더에 복사했다. 그 폴더에서 운영 의존성을 새로 설치하고 서버를 구동했다. 아바타 모듈·CSS 19개, 대문·공방·계정, 상태 확인 경로가 응답했다.
- 별도 임시 DB에서 운영 모드, 정식 Host, Fly 앱명과 프록시 설정을 사용했다. 가입·메일 확인·Secure 세션·회원 저장·재조회가 통과했다. 실제 Fly 인스턴스, 공개 DNS·TLS, Docker 이미지 빌드와 물리 휴대전화 검증은 수행하지 않았다. 이 환경에는 Docker 실행기가 없다.
- 계정 확인 직후 다른 탭에서 같은 저장 버전의 다른 회원으로 변경하면 조건부 저장이 412로 끝났다. 공방은 변경된 계정의 캐릭터를 불러왔고 두 번째 회원의 원래 저장본을 보존했다. 같은 계정의 버전 충돌은 409 처리와 사용자 선택을 유지했다.
- 실제 렌더러에서 미소년·미소녀 기본값과 추가 외형 두 종의 ZIP을 검사했다. 512 × 512 투명 초상과 말, 네 방향별 대기 2장·걷기 4장이 담긴 1152 × 768 시트, 좌표표 및 외형 데이터가 일치했다.
- 기준 커밋부터 바뀐 파일 62개의 파일명과 텍스트에서 자격증명·개인 이메일·휴대전화 번호를 검사했다. 시험 메일 주소는 예시 도메인을 썼다. 보관한 화면과 게임 PNG 18개에는 기기·위치 EXIF 정보가 없었다.

## 재현

Node 24.20.0에서 `npm ci` 후 아래 명령을 사용한다. 브라우저 시험에는 Playwright와 브라우저 실행 파일이 필요하며 Python 이미지 검사는 Pillow를 사용한다. Node용 Playwright를 별도 위치에 설치했다면 `PLAYWRIGHT_MODULE`에 모듈 경로를 준다. `AVATAR_CAPTURE_DIR`은 화면과 게임 PNG를 보관할 폴더다.

```sh
npm test
python3 scripts/verify_site.py
python3 -m unittest discover -s tests/security-review -p 'test_*.py'
node tests/security-review/review_http.mjs .
git diff --check b926da8
node test/avatar-studio-browser.mjs
node test/avatar-integration-browser.mjs
AVATAR_BROWSER=webkit node test/avatar-integration-browser.mjs
python3 test/avatar-gamekit-browser.py
python3 test/avatar-gamekit-browser.py --fixture
python3 test/avatar-render-browser.py /tmp/아바타-렌더-검수 --model assets/avatar/model.js --webkit
```

운영 파일 복사본으로 확인할 때는 `node test/avatar-integration-browser.mjs <복사본 경로>`로 실행한다. 전체 저장소 시험은 Node 217건, 정적 사이트 11쪽 3,377항목, Python 보안 회귀 40건, 독립 HTTP 70항목을 통과했다. [실행 결과](실행-결과.txt)
