# 캐릭터 화면 구현 보고

- 날짜: 2026-11-19
- 담당 브랜치: `formars0309-cloud/character-ui`
- 정본: `docs/기획/캐릭터-구현-계약.md`
- 화면 작업자가 재위임 없이 직접 구현했다. 서버·그림 담당 파일은 수정하지 않았다. 공개 배포와 운영 API·DB 접근은 하지 않았다.

## 구현한 것

- `assets/character/render.js`: manifest 읽기, 계약의 여섯 층 순서 합성, 마스크·HSV 중앙값 비율로 색 변경, 명도 0.22 이하의 선과 채도 0.12 이하의 무채색 보존, 부분 마스크 혼합, 초상 영역 자르기. 원본 그림은 최대 48개, 색을 바꾼 층은 최대 24개를 캐시한다. 오래 걸린 이전 요청이 최근 선택을 덮지 않게 했다. 순수 색 계산과 층 선택을 내보낸다.
- `character/index.html`, `assets/character/character.{js,css}`: 종족 → 꾸미기 → 직업·스탯 → 확인·저장. 정적 호스트에서 커뮤니티의 `/character/`로 쿼리·해시를 보존해 이동한다. 손님 외형 초안은 전용 키로 보관하고 저장소 읽기·쓰기·제거 실패를 처리한다. 캐릭터 이름은 별도로 받지 않는다.
- 저장 후 레벨·경험치·남은 포인트·스탯 10종 분배·초기화 확인·무료 초기화 날짜·칭호·출석·외형 변경·레벨 10 전 종족 및 직업 변경·잠긴 2차 전직 조건을 표시한다. 401은 선택을 화면에 유지하고, 409는 변경을 멈춘 뒤 사용자가 최신 캐릭터를 다시 불러오게 한다. 422·요청 제한·연결 실패도 한국어로 안내한다.
- 계정 화면의 초상과 캐릭터 만들기/내 캐릭터 링크, 커뮤니티 글·댓글·목록의 작성자 캐릭터가 있을 때만 32px 초상을 표시한다. 그림 로딩 실패는 기존 계정·게시판 기능을 막지 않는다.
- 공용 글꼴 변수·기존 색 체계를 사용한다. 한국어 레이블, 기본 라디오 키보드 조작, 분배 후 초점 보존, 상태·오류 알림, 기본 dialog의 초기화 확인을 적용했다.
- `scripts/verify_site.py`에 새 페이지와 글꼴·인증 화면 검사를 등록했다. 손님 외형 초안과 같은 출처의 고정 manifest 요청에만 좁게 예외를 적용했고, 추가 저장소·외부 요청 차단 회귀 시험을 넣었다. 서버 담당의 캐릭터 재귀 허용 목록을 실제 파일로 확장해 운영 패키지도 검사한다.
- `test/fixtures/character/`에 작은 단색 도형·manifest와 시험용 모델 사본을 뒀다. 운영 렌더러에는 시험 자료를 참조하는 경로가 없다. 운영 `manifest.json`과 부품은 만들지 않았다.

브라우저 시험은 손님 초안 복원·키보드 선택·저장·분배·출석·초기화 취소와 실행·실제 409 복원·외형 수정·계정 초상·글과 댓글 초상·레벨 10 잠금·칭호·실제 401 선택 보존·저장소 접근 차단을 확인했다. 그림만 시험용 부품으로 응답했고 API는 모의 응답으로 대체하지 않았다. 경험치와 칭호 상황은 격리 DB에서만 준비했다. 서버 작업자의 구현은 임시 사본으로 읽어 실행했으며 해당 워크트리는 수정하지 않았다.

브라우저 기본 실행은 설치된 Playwright가 찾는 Chromium 버전이 없어 한 번 실패했다. 설치되어 있는 실행 파일을 `PLAYWRIGHT_EXECUTABLE`로 지정해 모두 실행했다. 저장 후 외형 변경에서 다음 버튼이 잠긴 채 남는 문제도 브라우저 시험에서 발견해 수정하고 재검증했다.

## 추가 통합 검사와 조율자에게 필요한 변경

화면과 서버를 임시 폴더에 겹쳐 서버의 캐릭터 시험까지 함께 실행한 `npm test`는 225개 중 223개 통과, 2개 실패였다.

1. 운영 패키지 시험은 임시 사본에 `.git`이 없어서 파일 목록을 읽지 못했다. 임시 사본에만 Git 저장소를 초기화한 후 `node --test <사본>/test/character-package.test.js`를 다시 실행해 1개 통과를 확인했다. 실제 작업 브랜치의 문제는 아니다.
2. **`test/community-phase2.test.js:209`의 작성자 객체 기대값에 `character: null`을 추가해야 한다.** 실제 응답은 계약대로 `{ character: null, name, isOperator }`이고, 기존 시험은 `{ name, isOperator }`와 완전 일치를 검사한다. 이 파일은 화면 담당 범위 밖이므로 수정하지 않았다. 통합 후 조율자가 갱신하고 전체 시험을 다시 실행해야 한다.

화면 브랜치의 정적 검사 실패 5개는 서버 브랜치의 `.dockerignore`·`Dockerfile` 변경을 먼저 통합하면 해소됨을 임시 통합 검사로 확인했다. 서버의 `/character/` 정적 라우트, 공용 `model.js`, API도 먼저 통합해야 한다.

그림 작업자의 운영 manifest·부품이 아직 이 브랜치에 없으므로 실제 납품 그림의 이음새·팔레트·얼굴 자르기 품질은 그림 통합 후 다시 검수해야 한다. 이번 캡처는 모두 작은 시험용 도형이다. 삭제한 원본·사용자 파일은 없다.

## 브라우저 시험 재현

```sh
PLAYWRIGHT_MODULE=/Users/app/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules/playwright/index.mjs \
PLAYWRIGHT_EXECUTABLE=/Users/app/Library/Caches/ms-playwright/chromium_headless_shell-1243/chrome-headless-shell-mac-arm64/chrome-headless-shell \
CHARACTER_SERVER_ROOT=/Users/app/orca/workspaces/gracekin-games/character-server \
CHARACTER_FIXTURE_ART=1 \
node test/character-browser.mjs
```

서버·그림을 모두 통합한 뒤에는 `CHARACTER_SERVER_ROOT`와 `CHARACTER_FIXTURE_ART`를 빼면 현재 저장소의 실제 서버와 운영 manifest를 사용한다. 임시 DB와 서버 사본은 시험 종료 시 제거한다.
