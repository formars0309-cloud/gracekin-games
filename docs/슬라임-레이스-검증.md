서버 구현 원본 `49121c1`을 QA 브랜치의 `5e4179a`로 통합한 뒤 다음을 확인했다. 화면 구현을 합친 브라우저 검수 결과와는 구분한다.

조율자는 별도의 파일 SQLite DB로 재시작·정산 실패를 독립 검수했다. 다섯 선수에게 1,000씩 구매한 뒤 DB를 완전히 닫고 경주 중 재기동해 추첨 영속성과 공개 승자 비노출을 확인했다. 당첨 원장 INSERT 실패 트리거를 주입한 결과, 재기동 정산은 실패하고 잔액 25,000·미정산 상태·기존 승자가 보존됐다. 트리거를 제거한 뒤 재기동하면 정확히 지급하고 손익과 일치했으며, 다시 재기동해도 중복 지급하지 않았다. 해당 실험은 조율자의 보고에 근거하며 QA 브라우저 시험으로 대체해 기록하지 않는다.

브라우저 재현 명령은 `python3 tests/security-review/slime_race_browser.py --output-dir /tmp/gracekin-race-review`다. Python Playwright가 설치된 환경에서 실행하며 서버는 `tests/security-review/slime-race-fixture.mjs`가 띄운다. 검수 전용 성인 어댑터와 시계는 이 fixture 프로세스의 내부 옵션으로만 전달한다. HTTP·쿼리·운영 환경 변수로 구매 잠금이나 서버 시계를 변경하는 경로는 추가하지 않는다.

조율자의 추가 독립 브라우저 검수도 통과했다. 320×800 화면에서 다섯 선수를 모두 선택하고 메타 정보 세 열의 라벨·값이 잘리지 않으며 가로 넘침이 없음을 확인했다. 실제 `/me` 응답을 서버 수신 후 보류하고 계정 clear 사건 뒤 해제해도 과거 30,000 잔액·구매 가능 상태가 다시 노출되지 않았다. focus 재조회는 잔액을 복원하고 blur는 즉시 잔액을 비우고 구매를 잠갔다. 실행 오류는 0개이며 외부 운영 요청을 차단했다. 결과와 화면은 `/Users/app/orca/archives/gracekin-games/slime-race-implementation-20261017/root-browser/`에 보존했다. 이 항목은 조율자의 독립 실험 보고를 기록한 것이다.

시각 검수에서 소리 켜기 직후 다시 끄면 중단된 `Audio.play()`의 취소를 재생 실패로 안내하는 문제가 발견됐다. BGM과 효과음 모두 재생 시도 세대·현재 음원 참조로 취소를 구분하도록 수정했다. 320px 초기 창에 닫힌 안내 카드와 고정 폼이 겹쳐 첫 선수 정보가 가려지는 문제, 초기 API 실패 시 null 정보 접근 문제, 경기 경계의 최대 5초 재조회 지연도 보완했다.

화면 보완 `d8ed358`을 QA `aa71fde`로 합친 실제 서버 재검수에서는 위 기본 흐름을 포함한 9개 묶음을 통과했다. 추가로 다음을 확인했다.

- 최초 state·me를 모두 500 응답 또는 네트워크 중단으로 만들더라도 실행 오류 없이 안내하고, 다시 불러오면 실제 다섯 선수와 30,000 잔액으로 복구한다.
- 320×800에서 새로고침 후 창을 처음 열었을 때 첫 선수의 세 항목 전체가 스크롤 없이 실제 목록 영역 안에 보인다. 저장한 화면에서는 둘째·셋째 선수 카드도 전체가 보인다. 자동 선택 스크롤 시험과 구분한다.
- 판매 종료 1초 전부터 fixture 내부 시계를 실시간으로 전진시켜, 2.5초 안에 서버 countdown 응답을 받는다. 기존 5초 고정 폴링이면 실패하는 조건이다.

효과음 마지막 보완 `fde2ce8`을 QA `f6bc66e`로 합친 뒤에는 음원 항목만 좁혀 재실행했다. `python3 tests/security-review/slime_race_browser.py --sound-only --output-dir /tmp/gracekin-race-qa-review`로 첫 무음, 선택 전 음원 요청 없음, 실제 `BGM.play()` Promise의 성공, 빠른 BGM·효과음 끄기 후 허위 실패 안내 없음, 실행 오류 없음이 통과했다. 실제 청취 취향이나 실물 기기의 음질을 검사한 것은 아니다. 최종 정적 검사도 2,055개·6페이지, 검사기 회귀 13개가 통과했다.

최종 QA 화면과 JSON 결과는 `/Users/app/orca/archives/gracekin-games/slime-race-implementation-20261017/qa-browser/`에 보존했다. `result.json`은 전체 흐름, `sound-result.json`은 마지막 음원 재검수, `mobile-320-initial-ticket.png`는 좁은 화면의 최초 열기, `sound-toggle.png`는 취소 오류 안내가 남지 않는 최종 홈 화면 증빙이다. 최초 발견 화면도 수정 전 증빙으로 별도 보존한다.

## 공개 전 남은 조건

- 사용자의 성인 확인 방식 결정과 그 결정에 따른 구매 자격 검증.
- 운영 DB 백업과 복구 검증을 포함한 배포 절차 준비.
- 상시 실행·비용에 대한 운영 결정. 현재 유휴 정지 설정만으로 24시간 실제 경주 실행을 보장하지 않는다.
- 공개 배포에 대한 사용자의 명시적 요청. 현재 승인은 구현까지다.
