# 슬라임 레이스 점토 테마 검증

## 범위와 격리

승인 시안의 점토 표면·입체 잔디·파스텔 풍경을 실제 경기장 소재로 옮기는 작업을 검수한다. 슬라임 다섯 레인, 부엉이 사회자, 서버 경기 상태와 기존 티켓·원장 기능을 유지해야 한다. 시안 이미지 자체를 경기 화면으로 쓰거나 동적 회차·타이머·선수 이름을 그림에 넣어서는 안 된다.

모든 브라우저 시험은 `tests/security-review/slime-race-fixture.mjs`의 임시 DB와 가짜 회원을 사용한다. 운영 서버·외부 통계/폰트 요청은 차단한다. 점토 자산 전용 시험은 로컬을 포함한 모든 POST도 차단한다. 기존 티켓 회귀는 격리 서버 POST만 허용한다.

## 자동 검증

- `python3 tests/security-review/slime_race_hud_browser.py --output-dir <증빙>/hud`: 320/360/390/500/501/550/700/701/768/900/901/1000/1001/1024/1180/1440/1920px 경계에서 HUD·텍스트 내부 가로/세로 넘침, 테두리 포함, 버튼 겹침·터치 영역, 게스트 구매 잠금, Escape 초점 복귀를 검사한다. 마감·경주·결과·오류 상태도 같은 너비로 확인한다. 선두 교체·동률·결과 대기·과거 데이터·12초 응답 지연 처리와 결과/중계 DOM 반복 쓰기도 확인한다.
- `python3 tests/security-review/slime_race_clay_browser.py --output-dir <증빙>/clay`: 점토 자산 전체 HTTP200/디코드, Jua woff2 디코드, CSS/JS 캐시 버전, 원격 빌드 허용목록, 자산 지연 뒤 장면 재생성, 그림 전체 실패 시 대체 화면/구매창, 왕복 resize 캐시, DPR2·터치·2배 확대 구매창을 확인한다.
- `python3 tests/security-review/slime_race_browser.py --output-dir <증빙>/purchase`: 실제 격리 서버에서 구매·수정·취소·응답 유실 재확인·원장 정산·소리·모바일을 회귀 검수한다.
- `npm test`, `python3 scripts/verify_site.py`, `python3 -m unittest discover -s tests/security-review -p 'test_*.py'`, `node --check assets/slime-race/race.js`, `git diff --check`와 변경 파일 민감정보 검사를 수행한다.

기존 HUD의 최대 높이 590px 상수는 시안의 새 구조에 맞춰 텍스트·조작부의 실제 경계 검사와 경기장 1000px 상한으로 바꿨다. 검사 항목을 제거하지 않고 제목·회차·타이머·말풍선·모든 버튼의 내부 텍스트 박스와 42px 이상 조작 영역을 추가로 확인한다.

## 준비 중 발견

기존 화면에서 320px 타이머의 내부 세로 박스가 실제 글리프보다 2px 작았다(`clientHeight=22`, `scrollHeight=24`). 새 폰트/패널 통합본에서도 해당 검사를 유지하며 UI 작업자에게 전달했다.

## 최종 결과

최종 제품 기준은 `a3f1f7f + 8a5299f`이며 QA 워크트리에서는 마지막 받침 보완이 `235268b`로 적용됐다. 아래 검증이 모두 통과했다.

- 17개 너비 × 판매·마감·경주·결과·오류의 HUD 경계/내부 텍스트/버튼 검사, 선두 교체·동률·서버 결과 대기·과거 응답 거부·12초 지연 제거, 정지 상태 결과/중계 DOM 반복 쓰기 0회.
- 여섯 점토 그림과 Jua woff2의 HTTP200·디코드·원격 빌드 허용목록, 전부 실패할 때 대체 화면/구매창, 지연 완료 후 장면 갱신, 왕복 resize 동일 화면, DPR2·터치·2배 확대에서 320/390px 구매창 열기/닫기.
- 실제 격리 서버 구매·수정·취소·응답 유실 재확인·원장 정산·소리·감소 모션 등 기존 구매 회귀 11개 항목.
- 정적 검사 2779개/9페이지, 정적 검사기 회귀 13개, `node --check`, `git diff --check`, 변경 파일 민감정보 검사.

`npm test` 164개는 동일 제품 JS에서 UI 작업자가 통과했다. 그 후 제품 변경은 부엉이 받침 CSS와 설명뿐이어서 QA에서 전체 단위시험·구매 정산을 중복 실행하지 않았다. 최종 CSS 반영 뒤 HUD/자산 브라우저 검사와 정적 검사는 다시 수행했다. 별도의 빌드 명령은 없는 정적 파일/Node 서버 프로젝트다.

### 실패 원인과 해결

준비 시점 기존 화면의 타이머 세로 글리프 2px 넘침은 UI 작업자가 Jua 행높이를 1.2로 확보하고 시계 박스를 조절하여 해결했다. 통합본의 모든 너비·상태에서 넘침이 없다.

390px에서 회전한 간판의 축정렬 사각형 아래쪽이 부엉이 `<img>` 박스 위쪽과 0.652px 겹쳤다. 간판 사각형 하단은 205.2457px, 이미지 박스 상단은 204.59375px이었다. 부엉이 원본은 360×292px이고 실제 알파 경계는 `(13,13)-(342,282)`이며 `object-fit:contain`을 적용한 불투명 상단은 209.77px이다. 간판 전체 사각형과도 약 4.53px 떨어져 있으므로 실제 그림끼리 겹친 것이 아니었다. 검사는 원본 알파와 object-fit 변환으로 부엉이 실제 그림 경계를 계산하도록 보정했다. 이미지 전체 박스의 경기장 테두리 포함 검사, 제목·시계·말풍선·버튼 텍스트 넘침 검사는 그대로 유지했다.

2배 핀치 확대 뒤 Playwright `locator.tap`은 visualViewport 오프셋을 반영하지 않아 다른 요소를 눌렀다. CDP `touchstart`가 보고한 실제 client 좌표를 실측해 visualViewport의 `offsetLeft`/`offsetTop`을 뺀 화면 좌표로 터치를 전송하도록 검증 도구를 수정했다. 320/390px에서 확대 전후 실제 구매창 열기/닫기가 통과했으며 제품 입력 버그는 아니었다.

### 시각 평가와 한계

승인 시안을 직접 읽고 최종 PC·320/390px·결과·오류 캡처와 대조했다. 점토 나무 간판·크림 패널·금색 버튼, 입체 잔디와 흙길, 파스텔 호수 배경이 같은 재질/조명 분위기를 이룬다. 레인은 양 끝 비율을 보존하고 가운데를 반복하여 그림 확대 번짐이 보이지 않는다. 실제 잔디 위에서 눈에 띄는 밝은 알파 테두리도 없다. 회차·타이머·선수명·결과는 그림에 구워 넣은 글자가 아니라 서버 데이터로 갱신되는 DOM/캔버스 텍스트다.

새 자산은 라이선스 문서를 포함해 총 1,483,459바이트다. 이미지 요청 지연/전체 실패를 주입했지만 실제 이동통신망의 속도·지연 수치는 측정하지 않았다. Chromium의 DPR2·터치·핀치를 검수했으며 실기기 Safari 등 다른 엔진은 확인하지 않았다.

기존 어두운 보라색 결과 오버레이는 유지된다. 320px 결과창은 부엉이 하단·말풍선 장식 테두리 일부를 덮지만 메시지 글자·타이머·세 버튼은 읽고 조작할 수 있다. 결과창까지 점토 소재를 통일하는 것은 후속 시각 개선 후보이며 기능 통과 판정과 구분한다.
