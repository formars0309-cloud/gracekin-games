# 슬라임 레이스 서버 운영·API

구현: `server/slime-race.js`, `server/slime-race-routes.js`, `server/app.js`. 기존 `community.sqlite`와 `grain_wallets`·`grain_ledger`를 공유한다. 이 문서는 배포 지시가 아니며 실제 운영 설정은 변경하지 않았다.

## 공용 그레인 무료 전용 정책

`server/grain.js`의 불변 상수 `GRAIN_ECONOMY`가 공용 정책의 기준이다. 그레인은 무료 게임 화폐이며 현금 충전·구매, 현금 환전, 유료 상품·실물 상품·쿠폰 교환, 타인 양도, 다른 유료 재화로의 전환을 제공하지 않는다. 무료 경주 전용 보조 화폐를 새로 만들지 않고 기존 공용 그레인 지갑·원장을 그대로 사용한다.

`GET /api/slime-race/state`의 최상위 `economy`는 다음 계약을 제공한다.

```json
{"mode":"free-only","purchasable":false,"cashRedeemable":false,"itemExchangeAllowed":false,"transferable":false,"paidCurrencyConvertible":false}
```

정책은 요청·회원 속성으로 변경할 수 없다. 현재 서버에서 지갑을 바꾸는 경로는 신규 가입 이벤트 지급, 본인 경주 티켓 구매·수정·취소와 서버 자동 당첨 정산이다. 계정 그레인 API는 본인 조회만 허용한다. 충전·환전·교환·양도 API나 외부 결제 연결은 존재하지 않으며 새로 만들지 않았다. 티켓 API는 정해진 5개 필드만 받고 금액·수신인·교환 대상·지급액·배당·성인 자격 등을 추가해 조작하면 거부한다. 없는 금전·재화 교환 경로 호출도 거부하며 지갑·원장·티켓을 바꾸지 않는다.

무료 전용 정책은 성인 확인을 대신하지 않는다. 성인 확인 제공자 미설정 시 구매·수정·취소 잠금을 유지하며, HTTP 본문·헤더로 성인 확인을 주장해도 권한을 얻지 못한다. 기존 가입 30,000그레인 지급, 최소 100그레인, 잔액 범위 내 개인 경기 한도 없음, 분산 티켓·멱등성·원자적 정산 정책은 그대로다.

## 시간과 회복

UTC epoch의 600,000ms 단위로 회차를 나눈다. 회차 ID는 `String(startsAt / 600000)`이다. 서버 시각만 판정에 사용한다.

| 구간 | phase | 동작 |
| --- | --- | --- |
| 0 이상 500초 미만 | sales | 구매·수정·취소 |
| 500 이상 510초 미만 | countdown | 판매 마감, 추첨 영속화 |
| 510 이상 570초 미만 | racing | 서버가 저장한 결과의 1분 연출 |
| 570 이상 600초 미만 | results | 승자·전체 순위 공개, 원금 포함 당첨금 지급 |

시작 시와 매초 타이머 및 상태·개인 조회·구매 요청에서 회차를 전진시킨다. 타이머는 서버 종료 시 해제한다. 타이머 저장 장애는 개인정보가 없는 고정 오류 메시지로 기록한다. 새 DB는 현재 회차부터 만든다. 기존 DB 재시작은 미정산 회차부터 회복한 뒤 중단 중 빈 회차도 생성한다. 한 SQLite `BEGIN IMMEDIATE` 트랜잭션이 추첨·순위·연출 시드·당첨 원장·잔액·정산 완료를 묶으므로 성공한 추첨은 재시작해도 바뀌지 않는다. 당첨 원장의 `(userId,eventId)` 고유 제약과 회차 정산 상태가 이중 지급을 차단한다.

메모리 SQLite, Node 24.20.0에서 30일 4,321회 회복은 약 296ms, 365일 52,561회는 약 3,452ms였다. 실제 볼륨 속도에 따라 기동 시간이 늘 수 있다. 오랜 중단 뒤에는 준비 완료와 `/health` 응답을 확인한다.

## 선수·확률·배당

10명 중 최근 20회 출전 횟수가 적은 선수를 `21 - 출전횟수` 가중치로 5명 비복원 추출한다. 별명·기초체력은 시안을 유지한다. 주행 성향은 말랑·클로·구름=꾸준형, 딸기·귤빛·보송=초반 질주형, 물방울·초코=후반 추격형, 반짝=순간 가속형, 밤별=변칙형이다. 성향은 연출만 바꾸며 승률 가중치에 들어가지 않는다. 모든 위치 곡선은 양수 속도의 적분이며 뒤로 가지 않는다.

기초체력 가중치는 S 115, A 105, B 100, C 90이다. 매회 독립 추첨한 컨디션 5단계(매우나쁨·나쁨·보통·좋음·매우좋음)에 80·90·100·110·120을 곱한다. 각 선수에 확률 1%를 우선 배분하고 나머지 95%를 해당 가중치로 정규화한다. 백만 분율 정수의 잔여 단위를 마지막 선수에게 더해 합계가 정확히 1,000,000이다. 1%는 하한이고 고정 약체에 강제 배분하지 않는다.

목표 원금 포함 배당은 `0.95 / p`이다. 표시·지급의 일치를 위해 `oddsCents = floor(95,000,000 / probabilityUnits)`를 저장한다. 100분율 아래를 버리므로 실제 기대 환급률은 95% 이하이며 배당 최대는 9,500(95배)이다. UI는 `oddsCents / 100`을 두 자리로 표시한다. 실제 당첨금은 `floor(BigInt(amount) * BigInt(oddsCents) / 100n)`이다. 원금은 이 금액에 이미 포함된다.

승자 추첨은 판매 마감 이후 `crypto.randomInt(1_000_000)`로 수행한다. 공개 응답에는 결과 구간 이전의 승자·전체 순위·시드가 없다. 경주 응답은 해당 시각의 위치만 담는다. 다른 이용자의 티켓·베팅 합계·참여 수는 공개하지 않는다.

## 회원과 금액

조회 세션은 `disableRefresh: true`로 요청하고 세션을 연장하지 않는다. DB의 현재 회원·이메일 상태를 다시 읽고 `activeAccountUser`로 보호자 동의 철회를 반영한다. 게스트와 성인 확인 미완료 회원도 관람할 수 있다. 구매·수정·취소는 활성 계정, 이메일 확인, 신뢰하는 성인 확인 어댑터의 명시적 `true`가 모두 필요하다. `ageBand=14plus`는 성인 확인으로 보지 않는다. `under14`도 성인으로 처리하지 않는다.

2026-10-17 사용자 결정으로 본인확인 서비스 연동 전 구매 잠금을 유지한다. 기본값에는 제공자가 없어서 전 회원 구매가 잠기며 관람·응원은 허용한다. 실제 공급자 연동과 검증 후 구매를 별도로 개방하고, 만 19세 자기확인이나 가짜 인증 완료는 도입하지 않는다. 시험 전용 내부 옵션 `startServer({slimeRaceAdultVerifier: user => ...})`만 준비했다. HTTP·쿼리·환경 변수로 어댑터를 켤 수 없다. 자격이 중간에 사라지면 취소를 포함한 모든 티켓 변경도 막히며, 이미 접수한 티켓의 자동 정산은 정상 진행한다.

최소 총액은 선수별 100그레인이며 0은 해당 선수 티켓 취소다. 단계 단위 제한은 없고 안전한 정수만 받는다. 동일 회차 여러 선수에 나눌 수 있고 정책상 개인·기금·기간 지급 상한은 없다. 기술적으로 JavaScript·기존 지갑의 안전 정수 범위를 지키기 위해 새 잔액과 어느 선수가 이겨도 발생할 잠재 당첨금 합계를 BigInt로 검사한다. 보유 잔액 부족과 기술 범위 초과는 별도 오류로 거부한다. 기존 신규 가입 30,000 이벤트는 그대로 두며 과거 회원 지갑을 보충하지 않는다.

한 회차·회원의 revision은 성공한 변경마다 1 증가한다. 서로 다른 요청이 같은 revision으로 오면 하나만 성공한다. `requestId`는 회원 전체에서 고유하며 같은 ID·같은 내용 재전송은 저장된 응답을 반환한다. 같은 ID·다른 내용은 거부한다. 재전송 응답의 잔액·revision은 원래 응답이므로 UI는 성공 뒤 `/me`를 재조회한다. 티켓·잔액·원장·revision·멱등 응답은 같은 트랜잭션에 저장한다.

## API 계약

모든 시각은 밀리초 숫자, `slimeId`는 `"0"`부터 `"9"` 문자열이다. 모든 응답은 `Cache-Control: no-store`, `Vary: Origin`이다. 추가 쿼리와 허용되지 않은 필드는 거부한다. 오류는 `{error:{code,message}}` 형태다.

- `GET /api/slime-race/state`: `{serverNow, economy, round, roster}`. `round`는 `{id,startsAt,salesCloseAt,raceStartsAt,resultsAt,endsAt,phase,entrants,animation}`. 각 entrant는 `{slimeId,name,grade,style,condition,probability,oddsCents,recentRanks}`이다. 최근 순위는 실제 완료 출전 최대 5개다. `animation`은 `{elapsedMs,positions:[{slimeId,progress}]}`이며 progress는 0..1이다. results 구간에서만 `winnerId`와 `finishOrder:[slimeId,...]`를 추가한다. roster는 전체 10명의 `{slimeId,name,grade,style}`이다.
- `GET /api/slime-race/me`: `{user,eligibility,roundId,wallet,bets,revision}`. user는 `{id,name}` 또는 null, eligibility는 `{canBet,code,message}`, wallet은 `{balance}`, bets는 `[{slimeId,amount,oddsCents}]`다. 게스트도 200이며 잔액 0·빈 bets·revision 0이다.
- `POST /api/slime-race/tickets`: JSON 본문 `{roundId,slimeId,amount,expectedRevision,requestId}`. amount는 해당 선수의 원하는 최종 총액이고 증분이 아니다. requestId는 `[A-Za-z0-9_-]` 16~80자이며 UUID도 된다. 응답은 `/me` 형태다.
- `GET /api/slime-race/history`: 로그인 본인의 `{rounds,summary}`. rounds는 최근 100개의 실제 티켓을 가진 완료 경기이며 각 항목 `{roundId,startsAt,winnerId,bets,totalBet,payout,profit,hit}`. bets 항목에는 `payout`이 추가된다. summary는 전체 참여 회차의 `{totalBet,payout,profit,hitRate,roundsPlayed}`다. 누적 금액 3개는 장기 정수 손실을 막는 10진 문자열이고 hitRate는 0..1 비율이다. 게스트는 401이다.

주요 오류: `LOGIN_REQUIRED` 401, `EMAIL_NOT_VERIFIED`·`ADULT_VERIFICATION_UNAVAILABLE`·`ADULT_VERIFICATION_REQUIRED`·`ORIGIN_FORBIDDEN` 403, `ROUND_CHANGED`·`SALES_CLOSED`·`REVISION_CONFLICT`·`IDEMPOTENCY_CONFLICT`·`INSUFFICIENT_GRAIN` 409, `INVALID_INPUT`·`NOT_ENTERED`·`AMOUNT_OVERFLOW` 422, `JSON_REQUIRED` 415, `RATE_LIMITED` 429.

이 경로에 한해 정확한 `https://gracekingames.com`·`https://www.gracekingames.com`에 자격증명 CORS와 OPTIONS를 허용한다. 서버 자신과 같은 origin도 지원한다. POST에는 정확한 Origin과 JSON이 필수이고 최대 본문은 4,096바이트다. 사전 요청의 추가 헤더는 content-type만 허용한다. 기존 인증·계정·커뮤니티 origin 정책과 Host 검사는 완화하지 않았다.

## 운영 설정과 상시 실행 조건

`fly.toml`의 유휴 정지·자동 시작과 최소 실행 0대 설정을 유지한다. 관람 공개와 24시간 프로세스 상주는 구분하며, 정지 중에는 다음 시작 시 시각 기준으로 회차와 미정산을 회복한다. 상시 실행이 필요하면 비용에 대한 사용자 결정 후 `auto_stop_machines = "off"`·`min_machines_running = 1` 등을 별도로 검토한다. 공개 배포 요청만으로 이 비용 설정을 바꾸지 않는다. 단일 쓰기 인스턴스·지속 SQLite 볼륨을 유지하며, 다중 독립 볼륨에 각 서버를 띄워 공동 경기·잔액이 갈리는 구성을 허용하지 않는다. 기동 완료, 저장소 여유, 오류 로그, 정산 완료 회차, 정상 종료 후 재시작을 배포 검증에 포함한다. 실제 이미지·보존 검수 결과는 [배포 기록](커뮤니티-배포.md)을 따른다.

## 검증

`node --test test/slime-race*.test.js`는 시간 경계, 무참가 실제 타이머, 재시작 정산, 배당·확률, 뒤로 가지 않는 5성향 곡선, 금액·원장 원자성, 중복·동시 수정, 권한, CORS·Host·세션 연장 방지를 검증한다. `npm test`로 기존 회원·그레인·커뮤니티 회귀를 함께 실행한다. 시험은 임시 DB와 메모리 메일함만 사용한다.
