# 커뮤니티 회원 서버 배포 준비

현재 구성은 대문·게임 홈페이지를 기존 GitHub Pages에 두고, 커뮤니티 화면과 `/api`만 전용 Fly 앱 `gracekin-games-community`의 기본 HTTPS 주소에서 함께 제공하는 안이다. 이 연결 작업에서는 외부 자원·비밀키·DNS를 변경하거나 서버를 배포하지 않았다. 실제 운영 서버의 배포·공유 검증 결과는 조율자가 확인한 뒤 별도로 기록한다. 기존 경국지계 앱과 그 비밀키·볼륨은 사용하지 않는다.

## 검토할 자원과 설정

| 항목 | 준비한 값 | 이유 |
| --- | --- | --- |
| 전용 앱 | `gracekin-games-community` | 기존 게임 서버와 분리. 앱 이름 사용 가능 여부는 생성 직전에 확인 |
| 지역 | `nrt` | 도쿄 단일 지역 |
| Machine | `shared-cpu-1x`, 메모리 512MB, 1개 | 인증의 암호 연산을 고려한 초기안. 256MB보다 여유를 두었으며 실부하 측정값은 아님 |
| 영속 볼륨 | `community_data`, 1GB, `/data` | `/data/community.sqlite`와 SQLite 부속 파일 보존 |
| 유휴 상태 | 자동 정지·자동 시작, 최소 실행 0개 | 요청이 없으면 정지 가능. 다음 방문에 초기 응답 지연이 생길 수 있음 |
| 동시 요청 | 권장 한도 10, 최대 20 | 측정 전의 보수적인 초기값 |
| 상태 확인 | `GET /api/community/session`, 30초 간격·5초 제한·시작 유예 30초 | 익명 요청은 `200`과 `user: null`을 반환. 별도 `/health`는 없음 |
| 배포 | rolling, 한 번에 1개 중단 | SQLite 단일 서버라 배포 중 잠시 중단될 수 있음 |

위 자원에는 실행 시간, 볼륨, 전송량 등에 따른 비용이 발생한다. 신규 자원 비용과 운영 설정은 사용자에게 위임받은 조율자가 승인 범위에서 진행한다. 금액은 아직 확정하지 않았으며, 생성 전에 [공식 요금 계산기](https://fly.io/calculator/)에 지역·512MB·Machine 1개·1GB 볼륨과 예상 사용량을 넣어 확인한다.

자동 시작·정지, 동시 요청 한도와 상태 확인 헤더는 [Fly 설정 문서](https://docs.fly.io/reference/configuration)의 형식을 따른다. `--ha=false`로 최초 배포의 추가 Machine 생성을 막는다. 이 옵션은 Machine 수를 설정 파일만으로 고정해 주는 것은 아니므로 배포 후 실제 1개인지 확인한다. [Fly 배포 명령](https://docs.fly.io/flyctl/cmd/fly_deploy)

볼륨은 Machine 하나에 연결되며 여러 볼륨 사이에 자동 동기화되지 않는다. 이번 안은 SQLite 복제 기능을 추가하지 않아 두 번째 Machine을 띄우지 않는다. 단일 Machine·볼륨은 장애나 배포 때 중단될 수 있으므로 공개 운영 전 별도 백업과 복구 절차가 필요하다. 일일 스냅샷 5일 보관을 켜 두었지만 이것만을 유일한 백업으로 삼지 않는다. [Fly 볼륨 안내](https://docs.fly.io/volumes/overview/)

## 이미지와 비밀정보 경계

`Dockerfile`은 `node:24.20.0-bookworm-slim`으로 고정했다. 2026-10-15에 [공식 Docker Hub 태그 API](https://hub.docker.com/v2/repositories/library/node/tags/24.20.0-bookworm-slim)에서 활성 태그와 amd64·arm64·ppc64le 제공을 확인했다. 의존성은 잠금 파일로 `npm ci --omit=dev --ignore-scripts` 설치한다.

새 볼륨은 이미지의 `/data` 권한을 덮어쓰므로 시작 스크립트가 해당 디렉터리의 소유자를 `node`로 바꾸고 권한을 `0700`으로 설정한다. 이 짧은 준비 단계만 root로 실행한 뒤 `gosu node`로 내려가 Node 서버를 실행한다. 서버 프로세스는 root로 실행하지 않는다. 데이터 경로는 `/data`만 허용하며 기존 서버의 운영 비밀키 필수 검사를 그대로 유지한다.

`.dockerignore`는 전체를 차단한 뒤 파일 이름을 명시한 허용 목록이다. 서버 소스, 잠금 파일과 공개 화면·자산만 빌드 문맥에 들어간다. `.handoff`, `.sage`, `.git`, `.data`, `.env`, `node_modules`, 테스트 코드·계정·QA 비밀번호, 문서와 배포 설정은 이미지에 복사하지 않는다. 새 공개 자산을 추가할 때는 이 허용 목록도 함께 검토해야 한다. [Docker 빌드 문맥과 제외 파일](https://docs.docker.com/build/concepts/context/)

| 실행 환경 변수 | 설정 위치 |
| --- | --- |
| `NODE_ENV=production` | `fly.toml` |
| `HOST=0.0.0.0`, `PORT=8766`, `DATA_DIR=/data` | `fly.toml` |
| `BETTER_AUTH_URL` | 단계별 정식 HTTPS 출처, `fly.toml` |
| `BETTER_AUTH_SECRET` | 승인 범위에서 준비하는 32자 이상 전용 값, Fly의 운영 secret |

비밀키의 실제 값은 이 문서·명령 기록·저장소에 적지 않는다. 기존 게임의 비밀키를 복사하지 않는다. 사용자에게 위임받은 조율자가 전용 운영 비밀키를 발급·설정하며, CLI를 이용한다면 비밀값을 인자에 쓰는 방식 대신 보호된 외부 파일을 표준 입력으로 받는 `fly secrets import`를 사용한다. 적용 앱을 반드시 새 전용 앱으로 지정한다. [Fly secret 안내](https://docs.fly.io/apps/secrets), [표준 입력 명령](https://docs.fly.io/flyctl/cmd/fly_secrets)

운영 비밀키가 없거나 `BETTER_AUTH_URL`이 없거나 HTTPS가 아니면 서버는 시작에 실패한다. 이 조건을 우회하거나 개발용 비밀키를 운영에 재사용하지 않는다. 이메일 인증·비밀번호 복구 메일은 아직 연결하지 않았다.

## 현재안: Pages 대문과 Fly 커뮤니티 연결

- 대문과 게임 홈페이지는 `https://gracekingames.com`의 GitHub Pages에 그대로 둔다. 가비아 DNS와 기존 게임 하위 도메인, 메일 MX·SPF/TXT를 바꾸지 않는다.
- 커뮤니티의 목표 주소는 `https://gracekin-games-community.fly.dev/community/`다. HTML과 `/api`가 같은 출처에 있어 인증 쿠키와 글·댓글 공유를 사용할 수 있다. `/api`만 Pages의 화면에서 따로 호출하는 구성은 사용하지 않는다.
- 기존 Pages `/community/`에 들어오면 `host.js`가 같은 경로·쿼리·해시를 유지한 채 고정된 Fly 출처로 `location.replace`한다. `game`, `board`, `post`, `q`, `page`와 글 위치가 보존되며 사용자 입력으로 목적지 출처를 바꿀 수 없다. 이전은 정확히 `gracekingames.com`과 `www.gracekingames.com`에서만 수행한다.
- `host.js`는 회원 화면 코드보다 먼저 실행된다. 이전 중에는 `community.js`가 초기화를 종료하므로 Pages에 회원 API 요청을 보내지 않는다. 로컬 개발 주소와 Fly 기본 주소에서는 이전하지 않아 반복 이동이 생기지 않는다. 자바스크립트를 끈 경우 안내의 실제 Fly 커뮤니티 링크로 이동할 수 있다.
- Fly 커뮤니티의 로고·게임 홈페이지 복귀 링크는 실제 Pages의 `https://gracekingames.com/`과 `/games/…/`로 연결한다. 로컬 개발에서는 로컬 경로를 유지한다. Fly 서버가 함께 제공하는 대문 복사본을 기본 복귀 대상으로 삼지 않는다.
- `BETTER_AUTH_URL`과 상태 확인 `Host`는 현재 둘 다 Fly 기본 주소로 유지한다. 다른 Host는 서버가 `403`으로 거부한다. 나중에 `community.gracekingames.com`을 연결한다면 인증 출처·상태 확인 Host·이전 스크립트의 고정 목적지를 함께 검토한다.
- 가입창과 바닥글의 공통 방침은 `/community/privacy/`다. 닉네임과 글·댓글의 공개 범위, 이메일 미확인과 복구 메일 미연결을 가입창에 알린다. 회원가입은 만 14세 이상이라는 확인 항목을 필수로 체크하며 `ageConfirmed: true`를 서버로 보낸다. 생년월일을 수집하거나 실제 나이를 확인했다고 설명하지 않는다. 실제 공개 가입을 받기 전 방침 페이지의 공개 응답과 현재 계정·글·댓글 처리에 맞는 내용을 확인한다. 이 연결 작업에서는 방침 본문을 추정해 작성하지 않는다.

기본 도메인에서 두 계정의 가입·로그인, 글·댓글 공유·수정·삭제·권한, 재시작 후 지속성을 확인한 뒤 Pages의 연결 변경을 공개한다. 이 문서는 실서버 검증이 아직 확인되지 않은 상태에서 성공했다고 기록하지 않는다.

## 추후 대안: 전체 사이트 이전

Node 서버는 `/`, `/games/…`, `/community/…`, `/api/…`를 모두 제공하므로 전체 사이트를 옮겨 상대 경로를 유지할 수도 있다. 현재안보다 대문까지 한 서버에 모을 수 있지만 루트 DNS 전환과 원복 준비가 추가된다. 이번 단계에서는 선택하지 않았다.

전체 이전을 선택하면 Fly 기본 주소로 먼저 검증하고, 사용자 도메인 인증서와 DNS를 준비한 뒤 `BETTER_AUTH_URL=https://gracekingames.com` 및 상태 확인 `Host=gracekingames.com`을 함께 바꾼다. 그 뒤에는 Fly 기본 주소가 `403`이 되며 다른 출처의 세션은 이어지지 않아 재로그인이 필요하다. 현재 Pages 전용 이전 스크립트도 함께 바꿔 반복 이동을 막아야 한다.

현재 서버는 Host 하나만 허용하므로 `www`를 같은 앱에 단순 연결하면 `403`이다. `www`→루트 정식 리다이렉트를 준비하고 검증한 뒤에만 해당 DNS를 전환한다. 기존 Pages 리다이렉트를 유지할 경우 실제 유지 조건을 확인한다. 이때도 게임 하위 도메인과 메일 DNS를 보존하고 Pages·CNAME·기존 볼륨을 바로 삭제하지 않아 원복 경로를 남긴다. [Fly 사용자 도메인 안내](https://docs.fly.io/networking/custom-domain/)

## 조율자의 운영 배포 절차

다음은 **이 연결 작업에서 실행하지 않은** 새 자원 생성·배포 절차다. 조율자가 이미 준비한 자원이 있으면 중복 생성하지 않고 상태를 먼저 확인한다. 조율자가 승인 범위와 현재 조직·앱·볼륨·운영 비밀키의 준비 상태를 확인한 뒤 진행한다. 기존 앱 이름으로 치환하지 않는다.

```sh
fly apps create gracekin-games-community --org <선택한-조직>
fly volumes create community_data --app gracekin-games-community --region nrt --size 1 --count 1
```

앱 생성과 볼륨 생성은 [공식 앱 명령](https://docs.fly.io/flyctl/cmd/fly_apps_create), [공식 볼륨 명령](https://docs.fly.io/flyctl/cmd/fly_volumes_create)에 맞춘다. 전용 운영 비밀키를 설정하고 실제 값이 아닌 secret 이름만 확인한 뒤 진행한다.

```sh
fly config validate --strict --config fly.toml
fly deploy --app gracekin-games-community --config fly.toml --ha=false
fly status --app gracekin-games-community
fly volumes list --app gracekin-games-community
fly checks list --app gracekin-games-community
```

상태 확인은 내부 HTTP 요청이므로 설정의 `Host` 헤더가 중요하다. Fly의 외부 HTTPS 강제 설정과 별개로 현재 서버는 HTTP 자체를 리다이렉트하지 않아 이 검사에서 `200`을 반환할 수 있다. 실제 배포에서는 검사 성공과 Machine 1개·볼륨 1개 연결을 확인한다.

## 이번 준비의 검증 기록

- Node.js `v24.20.0`에서 `npm ci --omit=dev --ignore-scripts`와 기존 `npm test`: 14개 통과.
- `/Users/app/.fly/bin/flyctl config validate --strict --config fly.toml`: 통과. 앱 생성이나 배포는 수행하지 않았다.
- 공식 Docker Hub에서 고정 이미지 태그 존재 확인.
- Docker CLI가 PATH와 `/Applications/Docker.app/Contents/Resources/bin/docker`에 없어 이미지 빌드·컨테이너 실행은 수행하지 못했다. 따라서 실제 컨테이너 UID, 새 볼륨 소유권, Linux 이미지 기동과 Fly 상태 확인은 배포 전 확인해야 한다.
- 허용 파일 목록에 공개 연결 스크립트와 공통 개인정보처리방침 페이지를 명시한다. 정책 페이지는 별도 작업자가 작성하며 통합 후 내부 링크와 빌드 문맥 검증을 완료해야 한다. 비밀정보 패턴·문서 공백 검사와 정적 허용 목록 대조는 실제 Docker 문맥 검사와 구분한다.
