# 커뮤니티·공통 계정 서버 배포 기록

2026-10-16 회원 커뮤니티의 정식 출처를 `https://community.gracekingames.com`으로 전환하는 배포를 완료했다. 이전 운영 주소는 `https://gracekin-games-community.fly.dev`였으며, 옛 Host의 GET·HEAD 화면 요청은 새 출처로 301 이동하고 API·쓰기 요청은 403으로 거부한다. 전용 Fly 앱 `gracekin-games-community`는 유지한다. 같은 날 사용자의 공개 배포 요청에 따라 공통 계정 서버와 Pages를 배포했다. 운영 메일은 미연결이므로 신규 가입·이메일 인증·비밀번호 복구·보호자 동의 신청은 준비 중이다. 기존 계정 로그인과 공개 글 읽기는 유지한다.

대문과 게임 홈페이지는 `https://gracekingames.com`의 GitHub Pages에 둔다. Fly 앱 이름, 영속 데이터 경로와 기존 회원·글·댓글 데이터는 유지한다. 도메인 전환에 이어 공통 계정 기능을 배포했으며, 메일 기능 활성화 준비는 [공통 계정 운영 문서](공통계정-운영.md)를 따른다. 기존 경국지계 앱과 그 비밀키·볼륨은 사용하지 않는다.

## Resend 연결 준비 (2026-10-16)

Resend에서 `mail.gracekingames.com`의 인증을 완료했다. 발신은 `account@mail.gracekingames.com`, SMTP는 `smtp.resend.com:465`·사용자 `resend`, 발송 리전은 도쿄로 준비한다. Resend의 미국 저장·처리와 ImprovMX의 프랑스·미국 수신·전달 경로를 공개 방침과 동의문 버전 `2026-10-16-v2`에 반영한다. 도메인 인증 완료는 실제 발송·도착 성공을 뜻하지 않는다.

이 준비 단계에서 운영 SMTP secret은 아직 등록하지 않았으며 기능 개방·운영 메일 시험 완료로 기록하지 않는다. 조율자는 연결 전 시험에서 SMTP TLS 인증과 실제 2통의 Gmail 도착, `support@gracekingames.com`의 ImprovMX 전달, SPF·DKIM 통과를 확인했다. 보호자 검토 담당자 확인과 공개 서버 적용은 아직 완료하지 않았다. Gmail 수신·보관 안내도 공개 방침과 동의문에 포함했다. SMTP 설정 적용 시 일반 가입·인증·복구가 열리며 `GUARDIAN_REPLY_TO` 적용 시 어린이 신청도 열리므로, 확인되지 않은 경로를 먼저 설정하지 않는다. 비밀값은 비공개 파일의 표준 입력을 통해 등록하고 응답에서 이름·적용 여부만 확인한다. 이후 공개 기능별 상태와 검증 범위를 별도로 기록한다.

## 현재 설정

| 항목 | 설정값 | 확인할 점 |
| --- | --- | --- |
| 전용 앱 | `gracekin-games-community` | 운영 중인 앱을 유지하며 새 앱을 생성하지 않는다. |
| 정식 출처 | `BETTER_AUTH_URL=https://community.gracekingames.com` | 인증 API·세션 쿠키·화면의 출처를 하나로 맞춘다. |
| 이전 주소 | `LEGACY_HOSTS=gracekin-games-community.fly.dev` | 정확히 일치하는 Host의 GET·HEAD 화면 요청만 301 이동한다. |
| 상태 확인 | `GET /health`, `Host: community.gracekingames.com` | 30초 간격·5초 제한·시작 유예 30초. DB·인증·API 제한과 분리된 최소 응답이다. |

| 영속 볼륨 | `community_data`, `/data` | 2026-10-16 공통 계정 배포에서 기존 1GB 볼륨을 유지했다. `/data/community.sqlite`와 SQLite 부속 파일을 보존한다. |
| 유휴 상태 | 자동 정지·자동 시작, 최소 실행 0개 | 다음 방문에 초기 응답 지연이 생길 수 있다. |
| 동시 요청·배포 | 권장 한도 10, 최대 20, rolling, 한 번에 1개 중단 | 단일 SQLite 서버이므로 배포 중 잠시 중단될 수 있다. |

`HOST=0.0.0.0`, `PORT=8766`, `DATA_DIR=/data`, `NODE_ENV=production`은 `fly.toml`에 유지한다. `TRUST_FLY_PROXY=true`는 `FLY_APP_NAME`이 정확히 전용 앱과 일치할 때만 Fly Proxy의 접속자 IP를 신뢰한다. `BETTER_AUTH_SECRET`은 32자 이상인 기존 전용 운영 secret을 유지하며 실제 값을 문서·로그·저장소에 적지 않는다. 운영 비밀키가 없거나 정식 출처가 없거나 HTTPS가 아니면 서버는 시작에 실패한다. 개발용 비밀키를 운영에 재사용하지 않는다.

실행 시간, 볼륨, 전송량에는 비용이 발생한다. 이 문서의 자원 설명은 신규 비용을 승인하거나 자원 생성을 지시하는 것이 아니다. 자원 변경이 필요하면 조율자가 승인 범위와 현재 상태를 확인하고 [공식 요금 계산기](https://fly.io/calculator/)로 예상 비용을 검토한다. 최초 준비 당시 금액은 확정하지 않았다.

자동 시작·정지, 동시 요청 한도와 상태 확인 헤더는 [Fly 설정 문서](https://docs.fly.io/reference/configuration)를 따른다. 최초 배포 때 검토했던 `--ha=false`는 추가 Machine 생성을 막기 위한 옵션이며 Machine 수를 설정 파일만으로 고정하지 않는다. 기존 운영 앱의 Machine 수를 먼저 확인하고 도메인 전환을 이유로 새 앱이나 볼륨을 만들지 않는다. [Fly 배포 명령](https://docs.fly.io/flyctl/cmd/fly_deploy)

## 주소와 요청 호환

- Pages의 `/community/`에 들어오면 `assets/community/host.js`가 새 정식 출처로 이동한다. 경로·쿼리·해시를 보존하며, 정확히 `gracekingames.com`과 `www.gracekingames.com`에서만 실행한다. 이동 중 회원 화면 초기화를 종료하므로 Pages에 회원 API 요청을 보내지 않는다. 자바스크립트를 끈 경우 안내 링크도 새 출처를 가리킨다.
- 옛 Fly 기본 Host는 서버의 `legacyHosts` 옵션 또는 `LEGACY_HOSTS` 환경 변수에 명시했을 때만 호환한다. 운영에서는 `fly.toml`로 지정한다. 실제 요청 Host가 정확히 일치한 GET·HEAD 요청만 같은 경로·쿼리의 고정 정식 출처로 301 이동한다. `/health`도 옛 주소에서는 301이며, 상태 확인은 새 Host로 보낸다. `/account/`와 메일 링크의 계정 경로도 같은 규칙을 따른다. URL 해시는 HTTP 요청에 포함되지 않으므로 서버가 읽거나 조합하지 않는다. 301의 Location에 해시가 없으면 브라우저가 원래 해시를 유지하므로 옛 주소로 받은 `#token=...`도 새 화면에 전달된다.
- 옛 Host의 `/api`와 `/api/…`, 그 외 메서드는 403으로 거부한다. 새 출처의 Origin을 붙이거나 쿠키를 보내도 옛 Host에서 세션·쓰기 API를 사용할 수 없다. 임의 Host, 유사한 이름, 포트가 붙은 옛 Host도 403이다. 목적지 출처는 사용자 입력이나 전달 헤더로 바꿀 수 없다.
- 새 Host에서는 화면과 API가 같은 출처로 동작한다. 새 Host의 쓰기 요청도 새 출처의 Origin을 요구한다. 커뮤니티의 로고·게임 홈페이지 복귀 링크는 `https://gracekingames.com/`과 `/games/…/`로 연결하고 로컬 개발에서는 상대 경로를 유지한다.
- 도메인이 바뀌면 브라우저의 기존 로그인 세션은 이어지지 않으므로 한 번 다시 로그인해야 한다. 서버에 저장된 계정·글·댓글은 그대로 사용한다. 배포된 공통 계정은 이메일 인증·비밀번호 복구·보호자 동의 메일을 구현했으며, 링크·콜백은 `BETTER_AUTH_URL`의 새 출처를 기준으로 만든다. 실제 SMTP는 연결하지 않아 신규 가입과 메일 기능은 준비 중이다. 메일 기능 활성화 전 발송·회신 수신 설정과 개인정보 처리 고지 등 운영 준비가 남아 있다.
- 계정 화면과 커뮤니티 바닥글은 `/community/privacy/`로 연결한다. 공개 방침은 적용일 2026-10-16과 운영 메일 준비 상태를 알린다. 메일 기능 활성화 뒤 가입은 `/account/`에서 `ageBand` 연령 구분과 이메일 확인·보호자 동의 회신 검토 절차를 적용한다. 구형 `ageConfirmed: true`만으로 가입할 수 없으며, 생년월일을 수집하거나 자기신고로 실제 나이를 확인했다고 설명하지 않는다. 현재 Umami 도메인 제한은 `gracekingames.com`이며 `community.gracekingames.com`의 방문 통계는 전송하지 않는다.

## 도메인 전환 확인 절차

도메인 전환은 2026-10-16 배포 완료했다. 아래는 전환 때 사용할 확인 절차를 보존한 것이며, DNS·인증서 전환이 아직 남아 있다는 뜻이 아니다. 이후 공통 계정 배포에서도 새 출처·기존 데이터·이전 Host 호환을 다시 확인했다. 실제 검증 결과는 아래 공통 계정 공개 배포 기록에 따로 적었다. 새 주소가 준비되기 전에 목적지를 공개하면 접근 불가가 될 수 있으므로, 이후 주소 변경에도 기존 운영 상태와 원복 방법을 확인하고 전환 시점을 맞춘다.

1. 기존 앱·Machine·볼륨·비밀키 설정과 SQLite 백업·복구 경로를 확인한다. 기존 자원을 중복 생성하지 않는다.
2. `community.gracekingames.com`의 Fly 사용자 도메인 인증서와 DNS를 준비하고 HTTPS 사용 가능 여부를 확인한다. 루트·`www`·게임 하위 도메인·메일 MX·SPF/TXT는 보존한다.
3. 새 출처·이전 허용 Host·상태 확인 Host를 포함한 서버 변경을 배포한다. 새 Host의 `/health`가 200인지 확인한다. 정식 출처에 맞는 Host가 없는 내부 검사는 403이므로 설정 헤더를 함께 적용한다.
4. 새 주소에서 두 계정의 가입·로그인, 글·댓글 공유·수정·삭제·권한과 재시작 후 지속성을 확인한다. 기존 로그인 사용자는 다시 로그인한다.
5. 옛 주소의 GET·HEAD가 경로·쿼리를 보존한 301인지, 옛 API·쓰기와 임의 Host가 403인지 확인한다. Pages의 이동 목적지·경로·쿼리·해시와 새 주소의 복귀 링크·개인정보처리방침도 확인한다.
6. 서버의 새 주소가 정상 응답하는 시점에 Pages 변경을 공개하고 최종 공개 검증 결과를 기록한다. 이전 데이터·볼륨·호환 주소를 바로 삭제하지 않는다.

단일 Machine·볼륨은 장애나 배포 때 중단될 수 있다. SQLite 복제 기능을 추가하지 않았으며 여러 볼륨 사이에 자동 동기화되지 않는다. 두 번째 Machine을 임의로 띄우지 않는다. 일일 스냅샷 5일 보관 설정만을 유일한 백업으로 삼지 않는다. [Fly 볼륨 안내](https://docs.fly.io/volumes/overview/), [사용자 도메인 안내](https://docs.fly.io/networking/custom-domain/)

## 이미지와 검증 범위

`Dockerfile`은 `node:24.20.0-bookworm-slim`으로 고정하고 잠금 파일로 `npm ci --omit=dev --ignore-scripts` 설치한다. 새 볼륨은 이미지의 `/data` 권한을 덮어쓰므로 시작 스크립트는 해당 디렉터리 소유자를 `node`로 맞추고 권한을 `0700`으로 설정한다. 이 짧은 준비 단계만 root로 실행하고 `gosu node`로 내려가 서버를 실행한다. 데이터 경로는 `/data`만 허용한다.

`.dockerignore`는 전체를 차단한 뒤 파일 이름을 명시한 허용 목록이다. 서버 소스, 잠금 파일과 공개 화면·자산만 허용한다. `.handoff`, `.sage`, `.git`, `.data`, `.env`, `node_modules`, 테스트 코드·계정·QA 비밀번호, 문서와 배포 설정은 이미지에 넣지 않는다. 공개 자산을 추가하면 허용 목록도 검토한다. [Docker 빌드 문맥과 제외 파일](https://docs.docker.com/build/concepts/context/)

기존 게임의 비밀키를 복사하지 않는다. 비밀키 발급·교체가 필요하면 사용자에게 맡기며, CLI를 이용할 때도 실제 값을 인자에 쓰지 않고 보호된 외부 파일을 표준 입력으로 받는 `fly secrets import` 방식을 준비한다. 이번 작업은 secret을 발급·교체하거나 이 명령을 실행하지 않았다. [Fly secret 안내](https://docs.fly.io/apps/secrets), [표준 입력 명령](https://docs.fly.io/flyctl/cmd/fly_secrets)

코드 검증은 `npm test`, `python3 scripts/verify_site.py`, `python3 tests/security-review/test_verify_site.py`, `flyctl config validate --strict -c fly.toml`, `git diff --check`로 수행한다. 로컬 검증 통과와 실제 배포 완료는 구분한다. 이번 공통 계정 공개 배포에서는 담당 조율자가 원격 컨테이너 빌드·기동, 운영 데이터 보존과 공개 응답을 별도로 확인했다.

## 이전 배포 준비의 검증 이력

다음은 기존 문서에 기록된 최초 준비 당시 결과다. 2026-10-16 도메인 전환·공통 계정 공개 배포의 검증 수치로 해석하지 않는다.

- Node.js `v24.20.0`에서 `npm ci --omit=dev --ignore-scripts`와 당시 `npm test`: 14개 통과.
- `/Users/app/.fly/bin/flyctl config validate --strict --config fly.toml`: 당시 설정 검사 통과. 최초 준비 작업에서는 앱 생성이나 배포를 수행하지 않았다.
- 2026-10-15에 [공식 Docker Hub 태그 API](https://hub.docker.com/v2/repositories/library/node/tags/24.20.0-bookworm-slim)에서 고정 이미지의 활성 태그와 amd64·arm64·ppc64le 제공을 확인했다.
- 당시 Docker CLI가 PATH와 `/Applications/Docker.app/Contents/Resources/bin/docker`에 없어 이미지 빌드·컨테이너 실행은 하지 못했다. 실제 컨테이너 UID·새 볼륨 소유권·Linux 이미지 기동과 Fly 상태 확인은 해당 최초 로컬 검사만으로 확인되지 않았다. 이후 공통 계정 공개 배포에서는 원격 Docker 빌드와 운영 컨테이너 기동을 별도로 확인했다.
- 공개 연결 스크립트와 공통 개인정보처리방침 페이지를 이미지 허용 목록에 명시했다. 내부 링크·민감정보 패턴·문서 공백·정적 허용 목록 대조는 실제 Docker 문맥 검사와 구분한다.
