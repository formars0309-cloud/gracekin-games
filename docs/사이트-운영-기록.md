## 커뮤니티

회원 커뮤니티의 정식 출처는 `https://community.gracekingames.com`이며, 2026-10-16 도메인 전환과 공통 계정 공개 배포를 완료했다. 전용 Fly 앱 `gracekin-games-community`와 기존 데이터는 유지한다. 배포 이력과 운영 확인 결과는 [커뮤니티 배포 기록](커뮤니티-배포.md)에 적었다. Resend를 통해 신규 가입·이메일 인증·비밀번호 복구를 제공하며, 만 14세 미만은 보호자 동의 회신을 자동 확인한 뒤 가입하도록 한다. 기존 계정 로그인과 공개 글 읽기도 유지한다. 대문과 게임 홈페이지의 주소·DNS는 기존대로 유지한다.

운영 발송 서비스는 Resend로 정했고 `mail.gracekingames.com` 도메인 인증을 완료했다. 발신은 `account@mail.gracekingames.com`이며, 문의·동의 철회 주소는 `support@gracekingames.com`이다. 자동 동의 회신은 안내 메일에 지정한 별도 Resend 수신 주소로 받는다. 실제 SMTP 발송·도착, ImprovMX를 통한 운영자 Gmail 수신, Resend의 직접 수신과 서명된 알림을 확인했다. 일반 가입·인증·복구의 격리 DB 통합시험 24항목과 실제 회신 자료를 사용한 별도 자동 승인·보류·어린이 가입 시험을 통과했다. 업체별 처리 국가·보관 조건은 공개 방침과 보호자 동의문에 반영하고 [연결 순서와 검증 범위](공통계정-운영.md)를 기록했다. 발송 리전이 도쿄여도 Resend의 저장·주요 처리는 미국에서 이뤄진다.

옛 주소의 GET·HEAD 화면 요청은 같은 경로·쿼리의 새 주소로 301 이동한다. 옛 주소의 `/api`와 `/api/…`, 그 외 메서드, 임의 Host는 403으로 거부한다. Pages에서 넘기는 주소도 새 출처로 고정하며 경로·쿼리·해시를 유지한다. 주소가 바뀌면 기존 로그인 세션은 이어지지 않아 한 번 다시 로그인해야 한다. 공통 계정 서버의 배포 완료와 메일 기능의 활성화는 구분한다.

게임마다 게시판과 공식 안내를 분리한다. 슬라임 라인은 자유게시판(`free`)·공략과 팁(`guide`)·갤러리(`gallery`)·공지사항(`notice`), 경국지계는 자유게시판(`free`)·덱 연구(`deck`)·전략과 공략(`strategy`)·공지사항(`notice`)을 제공한다. `board`가 없으면 공지사항을 연다.

게시판 분류 이동, 제목·내용 검색, 페이지 이동, 공식 안내 읽기와 목록 복귀를 이용할 수 있다. 공식 안내는 게임별로 환영 안내(`post=welcome`), 시작 안내(`post=play-guide`), 제보 안내(`post=feedback`) 3개다. 예: `/community/?game=slimeline&board=notice&post=welcome`.

공통 계정의 로그인 화면은 `/account/`다. 기존 커뮤니티 계정과 회원 식별자를 그대로 사용한다. 만 14세 이상은 연령 구분을 선택하고 이메일·닉네임·비밀번호로 가입하며, 새 계정은 이메일 확인 뒤 로그인한다. 만 14세 미만은 보호자의 명시적 동의 회신이 확인 조건을 통과해 승인된 뒤 가입할 수 있다. 어린이 계정은 커뮤니티 읽기만 가능하고 서버와 화면 모두 글·댓글 작성을 차단한다. 비회원도 공개 글을 읽을 수 있으며, 작성 권한이 있는 계정은 본인 글·댓글을 수정·삭제할 수 있다. 두 게임의 실제 계정 연결은 아직 제공하지 않는다. 갤러리는 텍스트 글만 지원하며 사진·파일 첨부는 제공하지 않는다. 공식 공지는 기존 안내로 유지한다.

계정·세션·글·댓글은 서버의 실제 데이터베이스에 저장한다. 브라우저 저장소를 공용 게시판처럼 사용하지 않는다. 서버 연결이 끊기면 실패 안내와 입력 내용을 유지하고, 공식 안내는 계속 읽을 수 있다. 이메일 인증·재발송·비밀번호 재설정 기능을 구현했다. 운영 메일을 설정하지 않은 환경에서는 신규 가입과 메일 기능을 닫고 기존 계정 로그인은 유지한다. 제보와 의견은 기존 구글 설문지로 보내며, 계정·글·댓글의 공통 방침은 `/community/privacy/`로 연결한다. 게임별 개인정보처리방침과 문의 메일 `support@gracekingames.com`도 유지한다. Fly 커뮤니티에서 대문·게임 홈페이지로 돌아가면 실제 `gracekingames.com` 주소가 열린다.

## 공통 계정 1차 배포와 후속 기획 (2026-10-16)

[gracekingames 공통 계정과 게임 연결 기획](기획/공통-계정과-게임-연결.md)에 **게스트로 먼저 체험하고 필요한 기능에서 가입하는 방식**을 반영했다. 슬라임 라인 기본 플레이와 경국지계 튜토리얼·AI전·일반 체험은 게스트로 이용하게 한다. 일반 실시간 PvP의 구체적 범위는 별도 확정한다. 첫 화면에는 ‘바로 시작’과 ‘로그인’ 진입을 마련하고, 플레이를 가입창으로 강제로 끊지 않는다.

공통 계정은 플레이 기록 연결과 커뮤니티 글·댓글 작성에 필요하다. 경국지계 랭크·대회, 다른 기기 이어하기도 해당 기능을 제공할 때 공통 계정을 요구하며, 이 기능들의 구현 완료나 출시 시점을 뜻하지 않는다. 사이트와 각 게임에서 공통 가입·로그인을 시작하고 인증 후 원래 게임으로 복귀한다. 신규 가입자는 방금 게스트로 플레이한 기록을 이어받으며, 두 게임의 진행도·재화·기록은 각각 관리한다. 이미 기록이 있는 계정과 충돌하면 자동으로 합치거나 덮어쓰지 않는다.

사용자는 두 게임 모두 현재 실제 이용자 0명이라고 확인했다. 따라서 기존 게임 이용자의 계정·진행도·구매 내역 이전과 전환 유예는 1차 범위에서 제외한다. 커뮤니티 회원까지 0명으로 추정하거나 기존 데이터를 삭제하지 않으며, 회원과 글·댓글이 있다면 그 관계를 보존한다.

만 14세 미만 가입은 보호자 성명·이메일로 신청 → 동의 내용 이메일 발송 → 보호자 회신 자동 확인·승인 → 신청한 브라우저에서 어린이 계정 생성 순서다. 반복적인 운영자 승인 대신 정해진 회신 양식과 메일 인증 결과를 확인한다. 보호자는 인용문·서명·첨부파일 없이 안내된 7줄만 새 회신 본문에 넣어 보낸다. 확인이 어려운 회신은 보류하고 다시 회신하거나 문의할 방법을 안내한다. 동의 전 어린이 정보는 입력받지 않으며, 승인된 신청은 가입에 한 번만 사용할 수 있다. 이메일을 열거나 링크를 클릭하는 것만으로 동의 처리하지 않는다. 동의 상태는 직접 새로고침할 수 있고 페이지를 새로고침한 뒤에도 HttpOnly 쿠키로 이어진다. 어린이 계정은 커뮤니티 읽기만 허용한다. 동의 철회는 운영자 확인 후 세션을 무효화하고 이후 로그인을 차단한다.

당시 1차 구현 범위는 사이트 공통 이메일 계정, 기존 커뮤니티 계정 유지, 이메일 확인·복구, 보호자 동의와 어린이 가입이었다. 메일 링크의 인증값은 URL 해시로 전달하고 화면 진입 즉시 주소에서 제거한다. 이메일 확인도 사용자가 버튼을 눌러야 처리되며, 계정 화면에는 외부 통계 스크립트를 넣지 않는다. 당시 실제 게임 서버의 공통 로그인 연결·게스트 기록 이전·클라우드 저장·소셜 로그인·결제·대회는 후속 검토 대상으로 구분했다. 이후 공통 로그인·소셜 연결의 실제 반영은 배포 기록에 따르며, 그레인 결제·송금·교환은 2026-10-17 무료 정책에 따라 제공하지 않는다. 일반 메일 활성화 때 업체별 국외 처리 고지와 동의문 v2를 반영했고, 자동 회신에는 수신 처리와 증빙 보관을 설명한 v3를 사용한다. 실제 가입·인증·복구와 회신 자동 승인·보류·어린이 가입 권한은 운영과 분리한 DB에서 검증했다. 운영 서버에서는 실제 수신 연결과 서명을 확인했으며 시험 회원·보호자 신청을 만들지 않았다. 각 검증 범위와 최종 개방 상태는 배포 기록에 구분한다.

## 보호자 회신 자동 확인 (2026-10-16)

사용자는 보호자 회신을 매번 직접 승인하는 대신 자동 처리를 요청했다. `email-reply-auto` 방식은 Resend의 서명된 수신 알림과 API로 가져온 회신을 대조하고, 같은 발신 주소·신청 번호·메일로만 보낸 확인값·동의문 버전·명시적 법정대리인 진술·동의 문구가 맞을 때만 승인한다. 회신 내용이 불명확하면 보류하며 신청 화면에서 이유를 확인할 수 있다. 생성형 AI에 원문을 보내 해석하게 하지 않으며, 이메일로 법정대리인의 실제 신원을 인증했다고 설명하지 않는다.

기존 SMTP 발송 전용 키와 별도로 수신용 Full access API 키·웹훅 서명키를 설정하며 실제 값은 저장소에 넣지 않는다. Resend 기본 수신 주소를 연결해 DNS 추가 없이 실제 수신을 확인했고 기존 루트 ImprovMX 수신 설정은 유지했다. 자동 확인으로도 법정대리인의 실제 신원을 보증하지 않으며 문의·철회·삭제 요청은 지원 메일로 받는다. 연결 설정, 실제 수신과 격리 DB 시험, 최종 개방 확인은 [공통 계정 운영](공통계정-운영.md)에 구분해 적었다.

## 방문 통계 (2026-10-15)

Umami Cloud(무료 Hobby, 사이트 1개, 월 10만 이벤트, 6개월 보관)로 센다. 쿠키를 쓰지 않고 개인정보를 모으지 않는다. `data-domains`로 실제 도메인에서만 보내고, 브라우저의 추적 거부(Do Not Track) 설정은 따른다. 그래서 로컬 미리 보기에서는 기록이 남지 않는다.

- 방문: 주소 꼬리표까지 남는다. 채널별 링크에 `?ref=blog`, `?ref=threads`, `?ref=youtube`, `?ref=kakao`, `?ref=reddit`처럼 붙인다.
- 대문 → 게임 홈페이지: `homepage-slimeline`, `homepage-gyeongguk`(속성 `from` = `stage` 첫 화면 무대, `card-image`, `card-button`). 게임 실행 횟수와 구분한다.
- 게임 홈페이지 START → 실제 게임: `play-slimeline`, `play-gyeongguk`. 클릭 의도를 세며 실제 로딩 완료나 플레이 시간은 뜻하지 않는다.
- 제보 설문지 이동: `feedback-form`. 제출 완료 횟수는 뜻하지 않는다.
- 계정 화면 `/account/`는 외부 방문 통계를 사용하지 않는다.
- 대문·게임별 홈페이지·커뮤니티에 같은 사이트 ID와 실제 도메인 제한, 추적 거부 설정을 적용한다. 현재 도메인 제한은 `gracekingames.com`이므로 `community.gracekingames.com`의 커뮤니티 방문도 이 통계에 포함하지 않는다.
- 바닥글에 "방문 통계는 쿠키 없이, 누구인지 알 수 없는 형태로만 셉니다." 한 줄을 넣었다. 디자인 캔버스 HomeB에는 없는 줄이다.

## 스토어 우선 출시와 사이트 역할 전환 (2026-11-04)

슬라임 라인과 경국지계를 Google Play 모바일로 먼저 출시하기로 했다. 사이트는 닫지 않고 홈페이지·개인정보처리방침·이용약관·문의·계정 삭제 안내를 제공하는 공식 안내처로 유지한다. 스토어에 등록한 방침 URL·계정 삭제 URL·문의처가 끊기면 심사 진행에 문제가 생길 수 있으므로 주소와 접근 가능 상태를 유지한다. 경국지계 서버는 앱 백엔드로도 계속 필요하다.

두 게임 홈페이지의 히어로 1순위 버튼을 `Google Play 출시 준비 중`으로 바꾸고, 기존 게임 실행 링크는 2순위 `웹에서 체험하기`로 내렸다. 스토어 주소가 없으므로 버튼은 `data-store="google-play"`, `is-pending`, `aria-disabled="true"`를 가진 안내 요소이며, 링크 없는 공식 Google Play 배지는 사용하지 않는다. 히어로의 커뮤니티 버튼만 제거하고 내비게이션·소식·이야기 패널·소개 영역의 커뮤니티 경로는 유지했다. 웹 체험을 누르기 전 게임 자원을 불러오지 않는 원칙도 유지한다.

공통 계정의 [계정 삭제 안내](https://community.gracekingames.com/community/account-deletion/)를 신설하고 대문·방침·약관·계정·커뮤니티 화면에서 연결했다. 안내는 사이트 계정·커뮤니티·슬라임 레이스에 적용한다. 웹 경국지계의 공통 로그인 연결과 게임 자체 계정·진행 기록의 처리 범위는 구분하며, 게임 데이터 처리는 각 게임 방침을 함께 확인한다. 가입 이메일을 통한 요청, 접수 후 7일 이내 삭제, 세션 우선 종료, 글·댓글 기본 삭제와 요청 시 작성자 표시 제거 절차를 명시했다. 검증기는 웹 체험 링크·통계 속성, 스토어 요소의 준비/출시 상태, 계정 삭제 페이지의 존재·검색 허용·연결을 검사한다.

Fly 커뮤니티 앱은 이미 `auto_stop_machines = "stop"`, `min_machines_running = 0`으로 설정되어 있어 유휴 상태에서 정지한 동안 CPU·메모리 실행 비용이 발생하지 않는다. 다만 루트 파일시스템·볼륨·백업 보관 비용은 별도이므로 전체 유휴 비용이 0원이라는 뜻은 아니다. [Fly 공식 요금 안내](https://docs.fly.io/about/pricing)를 기준으로 구분한다.

출시 후에는 각 `games/<game>/index.html`의 `data-store="google-play"` 요소를 다음 링크로 교체한다. `<game>`은 `slimeline` 또는 `gyeongguk`, `…`는 확정된 앱 패키지 ID로 바꾸고, 준비 상태의 `is-pending`·`role="status"`·`aria-disabled="true"`는 제거한다.

```html
<a class="button button-store" data-store="google-play" href="https://play.google.com/store/apps/details?id=…" data-umami-event="store-<game>" data-umami-event-from="homepage-hero">Google Play에서 받기</a>
```

교체 후 `python3 scripts/verify_site.py`와 관련 테스트를 실행하고, 실제 스토어 링크가 해당 게임으로 열리는지 확인한다. 웹 체험 링크와 `play-<game>`·`homepage-web` 통계 속성은 그대로 둔다. 공개 배포는 별도 요청을 받은 뒤 진행한다.

## 슬라임 레이스 대문 비공개 (2026-11-04)

사용자는 Google Play 심사와 통신판매업 신고 기간에 사행성으로 오해받지 않도록 슬라임 레이스를 대문에서 비공개로 두기로 결정했다. 무료 그레인이라 법적 도박은 아니라는 사용자 판단을 배경으로, 첫 화면에서 배당·티켓 표현을 치우는 조치다.

대문 첫 화면은 레이스 도입 전의 슬라임 라인·경국지계 두 게임 무대로 복원하고, 대문 공통 스타일과 무대 스타일을 `assets/home/home.css`로 분리했다. 약관·개인정보처리방침·계정·버그 제보에는 현재 제공하지 않는 상태를 표시했다. 서버 API, `assets/slime-race/`, 레이스 테스트·브라우저 스크립트와 DB는 그대로 보존한다. 무료 그레인 정책도 바꾸지 않는다. 이 변경은 작업 브랜치에만 저장하며 공개 배포는 별도 결정한다.

다시 공개하기로 결정하면 커밋 `5cf4f97`의 `index.html`에서 레이스 섹션과 `race.css`·`race.js` 로드를 되가져온다. 두 게임 무대와 `home.css` 로드를 정리하고, 약관·방침의 “제공하지 않음” 문장을 지우며 계정·버그 제보·README의 비공개 표기도 갱신한다. 대문의 레이스 잔존 금지 검사와 해당 회귀 테스트를 재공개 정책에 맞게 바꾸고 `scripts/verify_site.py`를 포함한 전체 검증을 실행한 뒤, 커뮤니티 공지로 재개를 알린다.
