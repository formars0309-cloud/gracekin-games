시행 시각의 기본값은 `server/village/policy.js`의 `VILLAGE_OPENS_AT = '2026-11-27T00:00:00+09:00'` 한 곳에 두며 같은 이름의 환경 변수로 설정할 수 있다. 시간대 없는 값은 시작 시 거부한다. 시행 전에는 기존 관리자 권한을 확인한 운영자만 입장·아바타 저장을 허용한다. 일반 회원은 “2026년 11월 27일에 문을 열어요”를 표시한다. 안내 날짜도 서버 설정에서 계산한다. v5 미만 동의 어린이는 추가 동의 안내로 차단하고 기존 동의 원문을 바꾸지 않는다.

기존 보호자 절차는 새 가입용 신청·승인 흐름이며 이미 가입한 계정의 재동의 API·화면은 없다. 새 흐름은 만들지 않았다. 기존 v4 어린이는 후속 재동의 기능과 실제 동의 확인 전까지 마을 이용이 막힌다. 계정·게시판의 기존 이용 범위와 본인의 차단 조회·해제는 마을 입장 잠금으로 막지 않는다.

## 서버·채널·화면 구조

기존 `server/app.js`의 같은 HTTP 프로세스에 `server/village/`와 WebSocket `/api/village/ws`를 연결한다. `ws@8.23.0`만 의존성으로 추가한 상태를 유지한다. 업그레이드 때 better-auth 쿠키, 정확한 Host·Origin·요청 경로를 검사하며 옛 Host·비회원·다른 출처를 거부한다. Pages에서는 공용 출처 스크립트가 경로·쿼리·해시를 보존하여 정식 커뮤니티 도메인으로 이동하고 API·소켓을 시작하지 않는다. 로컬과 정식 출처는 유지한다.

각 마을은 별도의 채널 Map과 채널별 입장자·변경 위치·퇴장 목록·최근 대화 버퍼를 가진다. 채널은 마을 안에서 1번부터 시작하고 채널당 최대 50명이다. 같은 번호라도 다른 마을의 위치·채팅·감정·입퇴장·채널 목록을 보내지 않는다. 신고도 현재 같은 마을·같은 채널에 있는 대상만 가능하며 그 버퍼만 스냅숏으로 쓴다. 차단과 시간 지정 채팅 제한은 회원 단위다.

운영자는 서버가 기존 `isAdmin` 권한을 확인하는 `tour` 메시지로 두 마을을 둘러볼 수 있다. 화면과 캐릭터에 운영자 표시를 붙인다. 운영자도 어린이 마을에서 자유 채팅을 보낼 수 없으며, 어린이 수신자에 대한 자유 대화 차단은 별도 서버 방어선으로 유지한다. 운영자 신고·제한 목록에는 조치 당시 마을 이름을 표시한다.

`server/village/villages.js`의 정의는 id·이름·강조색·지도 파일·입장 조건 함수로 구성한다. 현재 두 마을 모두 `assets/village/maps/plaza.json`을 사용한다. 서버는 각 정의의 지도에서 충돌·입장 위치를 읽고 클라이언트도 같은 지도를 렌더링한다. 이후 지도·문 zone을 마을별 파일로 바꿀 수 있다. 본인인증을 연동할 때 general을 더 나누는 정의를 추가할 수 있으나 지금 해당 인증·분리 기능은 만들지 않는다.

Phaser 3.90.0 배포물·MIT 라이선스는 자체 호스팅하고 SHA256으로 검증한다. 라이선스는 문안 그대로 줄끝만 LF로 정규화한 상태를 유지한다. 빌드 도구·CDN은 추가하지 않는다. 임시 SD 캐릭터는 `drawAvatar(container, avatarData)`로 분리하며 `{v:1,kind:'placeholder',colors:{skin,hair,outfit}}`만 저장한다. 회원당 한 행·revision으로 동시 저장 409를 처리한다. 모바일 탭/클릭 A*와 방향키/WASD, 서버 충돌·최대 초당 4칸 검사, 약 10Hz 변경분 방송·화면 보간, 지수 백오프 재접속·중복 접속 교체·종료 알림을 유지한다.

## 건물 모듈 규격

건물은 아래 필드를 가진 독립 모듈로 추가한다. 현재 문은 가까이 가면 준비 중 안내만 표시하며 실제 입장·결제·보상을 하지 않는다.

| 필드 | 규격 |
| --- | --- |
| `buildingId` | 변경하지 않는 고유 문자열. 광장 문 zone의 id와 일치 |
| `entry` | 맵 properties의 `requiresLogin`, `minimumAge`, `capacity`를 서버가 검증. 현재 `requiresLogin=true`, `minimumAge=0`, `capacity=0`이며 0은 추가 제한 없음 |
| `roomType` | `shared` 공용 또는 `private` 개인. 방 식별자와 소유자·참가자를 서버에서 관리 |
| `economy` | 사용 화폐, 비용, 보상 규칙. 현재는 비용·보상 없음. 기존 무료 화폐 정책 준수 |
| `returnTo` | `{mapId:'plaza',x,y}`. 출구·취소·연결 복귀 때 충돌 없는 광장 칸으로 복귀 |
| `zone` | Tiled 오브젝트의 위치·크기와 위 필드를 포함하는 properties. 입장 판정은 서버 담당 |

문은 `arcade` 게임장, `shop` 상점, `armory` 무기점, `inn` 여관, `training` 훈련장 5개다. 1단계의 공통 입장 조건은 로그인 필요, 추가 나이·인원 제한 없음, 공용 방 예정, 사용 화폐·보상 없음이다. 실제 좌표는 맵의 zone `returnX`·`returnY`를 정본으로 삼는다. 후속 모듈이 특정 나이·인원·재화를 요구하면 서버 검증과 안내를 함께 추가해야 한다.

## 보관·삭제와 운영 패키지

새 DB의 마을 저장 테이블은 아바타·차단·신고·제한·감사 5개다. 평소 대화는 디스크에 저장하지 않고 채널당 최대 50개·10분만 메모리에 둔다. 아바타·차단은 회원 삭제의 외래키 CASCADE로 즉시 삭제하며 본인 차단 해제는 해당 관계를 즉시 삭제한다. 신고·스냅숏·제한·감사는 생성 후 달력상 1년이 지난 자료를 서버 시작과 이후 24시간마다 정리한다. 서버가 꺼져 있으면 다음 시작 때 처리한다. 연결된 계정 삭제로 먼저 지워질 수도 있다. 운영 DB 삭제와 업체·백업 사본 정리는 구분한다.

아직 배포 전이므로 이전 시험 설계의 호환 이관 기능은 만들지 않는다. 기존 로컬 DB의 사용하지 않는 테이블·추가 열은 읽거나 갱신하지 않아도 서버가 정상 동작한다. 운영 파일은 `.dockerignore`의 명시 허용 목록에 맞추며 기존 Dockerfile의 `COPY server/`, `COPY assets/`, `COPY village/`가 포함한다. Fly 연결 수 설정 150/200은 배포 준비 상태로만 유지한다.

## 남은 일

기존 약관의 고지 기준과 개정 성격·일정을 실제 게시 전에 대조해야 한다. 공지·main 통합·배포는 별도 지시 후에 진행하고, v5 문서·서버 입장 잠금·보존 정리가 같은 버전인지 검증한다. 실제 출처·쿠키·프록시·부하·다중 인스턴스·백업 사본 삭제와 캐릭터 렌더러 교체는 후속 작업이다.

청소년·성인 마을의 연령은 본인 선택이므로 청소년과 성인이 섞인다. 어린이 계정에 보호자 동의 절차를 적용해도 실제 가족관계·나이를 인증하거나 보증하지 않는다. 본인인증 연동 시 추가 분리를 검토할 수 있으며 이번에는 만들지 않는다.

## 결정 기록

3차에서 출생연도를 한 번 받아 초등학생 마을·중학생 마을·고등학생 마을·성인 마을로 나누는 설계를 구현하고 상한 검수도 정정했다. 4차에서 사용자가 이를 14세 기준 두 마을로 바꿨다. 보호자 동의가 필요한 경계 외의 중·고·성인 구분은 자기 입력이라 보호 효과를 확인할 수 없고, 오히려 청소년이 모인 곳을 알려 줄 수 있으며 접속자가 흩어지고 새로운 개인정보·규칙이 늘어나는 점이 변경 이유다. 추가 입력·학년도 계산·운영자 수정 기능과 맞지 않는 화면은 삭제했다. 이전 코드·문서는 원격 브랜치의 d2430b9까지 보존되어 있다. 이 절은 폐기한 설계의 결정 기록이며 현재 동작을 설명하지 않는다.
