# 그레이스킨 마을 — 1단계 분수 광장

2026-11-19의 구현 범위는 로컬 실행·검증이다. 공개 배포하지 않는다. `/village/`는 검색 색인에서 제외하고 대문·게임 목록에 링크하지 않는다.

## 구조와 실행

기존 `server/app.js`의 HTTP 서버에 `server/village/`를 연결하고 `/api/village/ws`를 제공한다. better-auth 세션 쿠키, 기존 연령 판정과 보호자 동의, 기존 관리자 허용 목록을 재사용한다. 옛 호스트·다른 출처·비회원은 WebSocket 연결을 거부한다. `npm ci --ignore-scripts`, `npm start`로 실행한다. 렌더러는 자체 호스팅한 Phaser 3.90.0이며 외부 CDN과 빌드 도구를 사용하지 않는다.

동봉한 Phaser MIT 라이선스는 원문 문안을 유지하고 줄끝만 CRLF에서 LF로 정규화했다. 배포물과 정규화한 라이선스는 정적 검사에서 각각 고정 SHA256으로 검증한다.

맵 정본은 `assets/village/maps/plaza.json`이다. Tiled 호환 바닥·충돌 타일과 문·NPC 오브젝트를 프론트와 서버가 함께 읽는다. 클라이언트 A*는 이동 의도를 만들고 서버가 인접 칸·충돌·초당 최대 4칸을 검사한다. 서버는 약 100ms마다 변경 위치만 보내고 화면은 이를 보간한다. 초등학생·중학생·고등학생·성인 마을을 분리하며, 각 마을의 채널당 최대 50명으로 새 입장자를 배정한다.

`drawAvatar(container, avatarData)`가 캐릭터 만들기 렌더러로 바꿀 지점이다. 임시 저장 값은 `{v:1, kind:'placeholder', colors:{skin,hair,outfit}}`뿐이며 그림·이미지 파일을 저장하지 않는다. 팔레트 밖 값은 거부한다. 회원당 한 행과 revision으로 동시 저장을 검사한다.

## 건물 모듈 규격

건물은 아래 필드를 가진 독립 모듈로 추가한다. 현재 문은 가까이 가면 준비 중 안내만 표시하며 실제 입장·결제·보상을 하지 않는다.

| 필드 | 규격 |
| --- | --- |
| `buildingId` | 변경하지 않는 고유 문자열. 광장 문 zone의 id와 일치 |
| `entry` | 맵 properties의 `requiresLogin`, `minimumAge`, `capacity`를 서버가 검증. 현재 `requiresLogin=true`, `minimumAge=0`, `capacity=0`이며 0은 추가 제한 없음 |
| `roomType` | `shared` 공용 또는 `private` 개인. 방 식별자와 소유자·참가자를 서버에서 관리 |
| `economy` | 사용 화폐, 비용, 보상 규칙. 현재는 비용·보상 없음. 기존 무료 화폐 정책 준수 |
| `returnTo` | `{mapId:'plaza',x,y}`. 출구·취소·연결 복귀 때 충돌 없는 광장 칸으로 복귀 |
| `zone` | Tiled 오브젝트의 위치·크기와 위 필드를 포함하는 properties. 입장 판정은 서버 담당 |

문은 `arcade` 게임장, `shop` 상점, `armory` 무기점, `inn` 여관, `training` 훈련장 5개다. 1단계의 공통 입장 조건은 로그인 필요, 추가 나이·인원 제한 없음, 공용 방 예정, 사용 화폐·보상 없음이다. 실제 좌표는 맵의 zone `returnX`·`returnY`를 정본으로 삼는다. 후속 모듈이 특정 나이·인원·재화를 요구하면 서버 검증과 안내를 함께 추가해야 한다.

## 통신 계약

HTTP는 같은 출처의 JSON 요청이며 쓰기 요청은 기존 Origin·Content-Type 검사를 거친다. 응답은 브라우저 캐시에 저장하지 않는다.

| 경로 | 동작 |
| --- | --- |
| `GET /api/village/session` | 회원, 연령 권한, 아바타와 revision, 허용 팔레트·문구·감정, 채널 정보 |
| `POST /api/village/profile` | `{birthYear,confirmed:true}`로 최초 1회 저장. 같은 회원의 재저장은 409 |
| `GET /api/village/map` | 본인 또는 운영자 둘러보기 중인 마을의 정본 맵. 지도 경로는 서버 마을 규격에서 선택 |
| `GET /api/admin/village/profiles/:userId` | 운영자만 출생연도·현재 마을·최근 수정 감사 확인 |
| `POST /api/admin/village/profiles` | 운영자만 `{targetId,birthYear,expectedRevision,reason}`로 수정. 충돌 409·감사 원자 저장 |
| `GET /api/admin/village/mutes` | 운영자만 마을 이름이 포함된 계정별 제한 이력 확인 |
| `PUT /api/village/avatar` | `{avatar,revision}` 저장. 첫 revision은 0이며 충돌하면 409 |
| `GET/POST/DELETE /api/village/blocks` | 본인의 차단 목록 조회·`{targetId}` 추가·해제 |
| `POST /api/village/reports` | `{targetId,reason}`와 해당 대상의 최근 대화 스냅숏 저장 |
| `GET /api/admin/village/reports` | 운영자만 신고 목록 조회 |
| `POST /api/admin/village/mutes` | 운영자만 `{targetId,durationMinutes,reason}`로 시간 지정 채팅 금지 |

WebSocket의 클라이언트 메시지는 `move`의 `path`, `chat`의 `text`, `phrase`의 `id`, `emote`의 `id`, `channel`의 `channelId`로 구분한다. 위치를 직접 확정하는 입력은 받지 않으며 잘못된 이동에는 서버 위치를 반환한다. 첫 상태·입퇴장·위치 변경·채팅·감정·채널 변경과 오류는 서버 메시지로 전달한다. 같은 회원이 다시 접속하면 이전 연결을 종료한다. 통신이 끊기면 지수 백오프로 재연결하고 중복 접속 종료는 자동 접속 경쟁을 피하도록 안내한다. 서버 정상 종료 때 잠시 뒤 재연결 안내를 전한다.

## 대화 보호와 저장

만 14세 이상과 기존 연령 미분류 회원은 최대 80자의 자유 대화를 사용한다. 어린이 회원은 v5 이상의 보호자 동의가 유효해야 입장할 수 있고 자유 입력은 서버에서도 거부한다. 자유 입력 이벤트는 `kind:free`, 정해진 문구는 `kind:phrase`로 구분한다. 서버는 어린이 수신자에게 자유 입력 이벤트를 보내지 않는다. 화면의 기록 창 위에도 인사말·감정표현만 표시한다는 안내를 둔다. `hello/play/thanks/bye` 정해진 문구와 `wave/heart/laugh/surprise/clap/dance` 감정을 제공한다. 서버는 약 1.5초당 한 개, 순간 최대 세 개의 제한과 확장 가능한 금칙어 필터를 적용한다. 말풍선은 약 5초 표시한다.

차단은 회원별 DB 관계로 남긴다. 서버가 차단한 사람의 대화·감정을 수신자에게 전송하지 않는다. 평소 대화는 디스크에 기록하지 않는다. 채널마다 최근 대화 최대 50개를 메모리에 두며 10분을 넘긴 대화는 신고 스냅숏에서 제외한다. 신고 때만 같은 마을·같은 채널에 현재 있는 대상의 해당 최근 메시지를 DB에 복사한다. 신고 목록과 채팅 금지는 기존 관리자 권한을 통과한 운영자만 처리한다.

## 방침·약관·보호자 동의문 실제 반영 결과

2차 지시로 `community/privacy/index.html` 정본, `privacy/index.html` 안내, `community/terms/index.html`과 `server/guardian.js` 원본을 수정했다. 공고일은 2026-11-20, 마을 관련 시행일은 2026-11-27이다. 파일 수정·브랜치 저장만 수행하며 공개 공고나 배포를 완료했다는 뜻은 아니다. 이전 판 링크·보관 경로를 쓰는 기존 방식은 없어 기존 적용·개정일과 새 변경 이력을 본문에 남겼다.

| 반영 위치 | 실제 추가·수정한 내용 |
| --- | --- |
| 개인정보처리방침 정본 | 출생연도·연령대 배정·운영자 수정, 캐릭터 색상·수정 번호·시각, 이동·접속, 차단, 대화·신고 스냅숏, 채팅 제한·감사의 항목과 목적, 공개·운영자 열람 범위, 보존·삭제, 어린이 수신 제한과 v5 조건 |
| `/privacy/` 안내 | 정본 적용 범위에 마을을 추가하고 공고·시행일과 보존·어린이 보호 변경을 요약 |
| 이용약관 | 출생연도 사실 입력·다른 연령대 사칭 금지·문의에 따른 운영자 수정, 욕설·괴롭힘·도배·개인정보 요구 금지, 차단·신고·시간 지정 제한, 기존 9절의 사유 통지와 이의 제기 적용, 변경 이력·시행일 |
| 보호자 동의문 | `2026-11-20-v5`로 올리고 출생연도 수집·연령대 배정과 마을 처리 항목·목적·보존, 정해진 문구 사용·자유 채팅 미수신, 운영자 열람과 기존 동의 보존을 추가 |

출생연도 프로필·캐릭터 설정·차단 목록은 실제 회원 삭제의 외래키 CASCADE로 즉시 삭제한다. 본인의 차단 해제는 해당 관계를 즉시 삭제한다. 신고·스냅숏, 채팅 제한, 출생연도 수정 전후 연도·사유를 포함한 운영 감사는 각 생성 시각을 기준으로 달력상 1년이 지난 자료를 서버 시작과 이후 24시간마다 정리한다. 서버가 꺼져 있으면 다음 시작 때 처리한다. 회원 외래키 삭제 때문에 연결 자료가 먼저 삭제될 수도 있다. 일반 대화는 기존대로 채널별 50개·10분 이내 메모리만 사용한다.

이 1년은 이번에 정한 운영 보존 기간이다. 법정 의무 기간으로 표현하지 않았다. 운영 DB의 삭제와 업체·백업 사본 정리는 기존 방침의 구분을 유지한다. 실제 보존 기간과 법정대리인 동의 원문 확인에는 [개인정보 보호법 제21조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1006183947) 및 [제22조의2](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1033215047)를 참고했다. 보존 기간을 정했다는 이유로 법령상의 파기·권리 요청 처리가 면제되는 것으로 해석하지 않는다.

## 시행 시각과 추가 동의

실행 중 입장 시각의 기본값은 `server/village/policy.js`의 `VILLAGE_OPENS_AT = '2026-11-27T00:00:00+09:00'` 한 곳에 둔다. `VILLAGE_OPENS_AT` 환경 변수 또는 프로세스 내부 시험 옵션으로 바꿀 수 있으며 시간대가 없는 설정은 시작 시 거부한다. 입장 화면의 날짜는 서버에서 이 값으로 계산하여 보내므로 화면에 별도 날짜 상수를 두지 않는다. 공고 문안과 방침은 확정 일정인 11월 20일·27일로 작성했다. 운영 설정을 바꿀 경우 공고·방침 일정과 먼저 대조해야 한다.

시행 전 일반 회원의 세션 조회·WebSocket 입장·아바타 저장·새 차단 추가는 403 `VILLAGE_NOT_OPEN`으로 거부한다. 운영자만 미리 입장·옷장 저장할 수 있다. 시행 시각부터 일반 회원을 허용한다. 기존 계정·게시판 이용과 본인의 차단 해제는 이 입장 잠금으로 차단하지 않는다.

어린이는 유효한 보호자 동의에 더해 v5 이상이 필요하다. 기존 v4 동의 계정은 `VILLAGE_GUARDIAN_CONSENT_REQUIRED`와 “보호자의 추가 동의가 필요해요” 안내로 입장·옷장 저장을 거부한다. 기존 계정 로그인과 당시 동의 본문·판은 바꾸지 않는다. 접속 중에도 세션·동의·입장 조건을 재확인한다.

기존 보호자 절차는 신청→승인→새 계정 가입에 쓰는 일회용 흐름이며, 이미 가입한 계정에 재동의를 연결하는 API·화면은 없다. 지시대로 새 흐름을 만들지 않았다. 따라서 기존 v4 어린이는 후속 재동의 기능과 실제 동의 확인이 끝날 때까지 마을 이용이 막힌다. 새 계정을 다시 만들거나 DB 판 번호만 고쳐 해결하도록 안내하지 않는다. 자동 회신은 현재 `CONSENT_VERSION`을 참조하는 기존 검증을 그대로 사용하며 v5에서도 전체 회귀시험으로 확인한다.

## 개정 공지 문안 — 미게시

**제목: 그레이스킨 마을 개인정보처리방침·이용약관과 보호자 동의문 개정 안내**

공고일: 2026년 11월 20일
시행일: 2026년 11월 27일

그레이스킨 마을 이용에 필요한 개인정보 처리와 이용 규칙을 안내합니다. 출생연도만 받아 한국 학년도 기준으로 초등학생·중학생·고등학생·성인 마을에 배정합니다. 생일·학교·학년은 받지 않으며 회원은 출생연도를 사실대로 입력해야 합니다. 저장 후 본인은 바꿀 수 없고 잘못 입력했다면 문의 메일로 운영자가 확인·수정합니다. 출생연도 프로필은 회원 탈퇴 시 즉시 삭제하고 수정 전후 연도·사유를 포함한 감사 기록은 1년이 지나면 자동 정리합니다. 임시 캐릭터의 피부·머리·옷 색상과 차단 관계를 저장하고, 신고 접수 때 대상의 최근 대화를 스냅숏으로 보관합니다. 평소 대화는 디스크에 저장하지 않으며 채널별 최근 50개·최대 10분만 메모리에 둡니다. 신고·채팅 제한·마을 운영 감사 기록은 생성 후 1년이 지난 자료를 서버 시작과 하루 한 번 자동 정리합니다. 캐릭터 설정과 차단 관계는 회원 탈퇴 시, 차단 관계는 본인이 해제할 때도 즉시 삭제합니다.

어린이는 정해진 인사말·감정표현만 사용하며 다른 회원의 자유 채팅은 받지 않습니다. 어린이의 신고 증빙에는 화면에 보이지 않은 대상의 자유 채팅이 서버 기록 기준으로 포함될 수 있습니다. v5 미만으로 동의한 기존 어린이는 보호자의 추가 동의 확인 전까지 마을에 입장할 수 없습니다. 기존 계정용 재동의 접수 기능은 아직 제공하지 않으며, 기존 가입·동의를 새 판으로 자동 변경하지 않습니다.

## 3차 — 출생연도와 네 마을의 분리

판정은 `server/village/age-group.js` 한 곳에서 수행한다. 서울 시각의 올해를 Y라고 할 때 3월 이후는 학년도 S=Y, 1·2월은 S=Y−1이며, 계산 학년은 S−출생연도−6이다. 1~6은 `elementary` 초등학생 마을, 7~9는 `middle` 중학생 마을, 10~12는 `high` 고등학생 마을, 13 이상은 `adult` 성인 마을이다. 1 미만은 미취학 안내로 거부한다. 2026학년도에는 각각 2014~2019 / 2011~2013 / 2008~2010 / 2007년생 이하가 해당한다.

첫 마을 세션은 프로필이 없으면 출생연도 입력을 요구한다. 옷장보다 먼저 선택·별도 확인 단계를 거치며, 선택지는 S−7년부터 S−100년까지다. 본인의 저장은 한 번뿐이고 수정·삭제·재등록 API는 제공하지 않는다. 문의를 받은 운영자는 사유와 현재 revision을 보내 수정하며, 프로필 변경과 감사 기록은 같은 트랜잭션으로 처리한다. 감사 저장에 실패하면 수정도 롤백한다. 수정 전후 연도와 사유는 운영자만 조회하고 1년 정리 대상에 포함한다. 프로필은 탈퇴 시 외래키 CASCADE로 삭제한다.

입력·운영자 수정 때 `under14`는 출생연도 ≥ Y−14, `14plus`·`legacy`는 출생연도 ≤ Y−13 조건을 적용한다. 생일을 받지 않으므로 이 조건은 실제 만 나이를 인증하지 않는다. 초등학생 마을에는 별도로 `under14`와 유효한 보호자 동의 v5를 요구하며 2월의 경계나 저장소의 잘못된 배정 값도 출입 단계에서 검사한다. 시행 전 잠금·기존 v4 어린이 차단은 유지한다. 기존 가입 연령 구분을 출생연도에서 자동으로 바꾸지는 않는다. 저장된 연도의 마을 배정은 새 학년도마다 다시 계산하지만, 어린이 계정의 자유 채팅 제한과 동의 조건은 기존 `ageBand`를 기준으로 유지한다.

서버는 마을마다 별도 채널 Map과 각 채널의 입장자·변경 위치·삭제 대상·대화 버퍼를 둔다. 채널 번호는 각 마을의 1번부터이고 정원은 각각 50명이다. 채팅·감정·위치·입퇴장·채널 목록에는 다른 마을 상태를 보내지 않는다. 채널 이동 요청에 다른 마을 id가 있으면 거부한다. 신고는 현재 같은 마을·같은 채널에 있는 회원만 가능하고 스냅숏도 그 버퍼에서 가져온다. 차단과 채팅 제한은 기존처럼 회원 단위로 유지한다.

학년도 또는 프로필 revision이 바뀌면 다음 검사에서 4004 `VILLAGE_CHANGED`로 즉시 퇴장시키고 재접속 때 새 마을로 배정한다. 입력 시의 연령 일관성 조건을 매년 새 입력처럼 다시 강제하여 기존 프로필을 무효화하지는 않는다. 운영자 둘러보기는 서버가 관리자 권한을 다시 확인하는 `tour` 요청으로만 가능하며 화면과 캐릭터에 운영자 표시를 붙인다. 운영자 권한이 바뀌면 연결을 종료해 표시·출입을 새로 확인한다.

`VILLAGES` 레지스트리의 마을 id → 이름·강조색·지도 파일 매핑을 정본으로 삼는다. 현재 네 마을은 동일한 `plaza.json`을 공유하지만 서버는 마을별 지도 참조에서 충돌·입장 위치를 고른다. 클라이언트도 서버가 준 지도 파일을 선택하며 다른 지도는 본인/둘러보기 상태의 맵 API로 받도록 준비했다. 지도에 문 zone이 포함되므로 이후 마을별 건물도 해당 맵에서 분리할 수 있다. 이전 통합 광장의 저장 신고·제한·감사는 `legacy`로 남기고, 기존 회원의 출생연도나 새 마을을 임의로 추정하지 않는다.

### v5 문안과 한계

v5는 아직 공개하지 않았으므로 판 `2026-11-20-v5`, 공고 2026-11-20·시행 2026-11-27을 그대로 두고 본문만 고쳤다. 개인정보 정본·안내에는 출생연도 수집 목적·탈퇴 시 삭제·수정 감사 1년과 같은 마을에서 연령대를 추정할 수 있음을 넣었다. 동의문에는 생년월일은 받지 않고 마을에서 연도만 받는다고 명시했다. 약관 5-1절에는 네 마을, 사실 입력 의무·다른 연령대 사칭 금지, 문의에 의한 운영자 수정과 위반 시 제한을 추가했다. 공지 문안도 함께 갱신했으며 실제 게시하지 않았다.

**출생연도는 자기 입력으로 실제 연령을 검증하지 못한다.** 성인이 출생연도를 속여 중학생·고등학생 마을에 들어오는 위험을 막는 신원 확인 수단은 이번 범위에 없다. 초등학생 마을만 어린이 가입·보호자 동의 v5 조건을 추가로 강제하지만, 이 동의 절차 자체도 실제 가족관계·나이를 보증하지 않는다. 조기입학·유예·실제 학교 재학 여부는 반영하지 않는다. 운영자 수정은 문의 확인과 감사에 의존하며, 기존 어린이 계정의 재동의 기능·운영 부하·다중 인스턴스·캐릭터 렌더러 교체는 여전히 후속 과제다.
