# 캐릭터 만들기 구현 계약

- 기록일: 2026-11-19. 사용자가 "시안 없이 추천대로 전체 캐릭터 생성 게임을 구현하자"고 요청했다.
- 기획 정본: [캐릭터 만들기·성장·전직 기획](캐릭터-성장-전직.md). 이 문서는 세 작업자(그림·서버·화면)가 서로 맞물리도록 형식과 담당을 고정한다. 기획과 이 문서가 다르면 이 문서를 따른다.
- 통합 브랜치: `formars0309-cloud/character-game`. 작업자는 이 브랜치에서 갈라진 하위 브랜치에서 일하고, 조율자가 검수한 뒤 합친다.
- 배포하지 않는다. main 푸시, `fly deploy`, 운영 DB 접근은 금지다.

## 1. 이번 범위

| 포함 | 제외(후속) |
| --- | --- |
| 1단계: 종족 10종 · 꾸미기 · 1차 직업 10종 · 처음 스탯 · 계정 저장 · 내 계정과 커뮤니티 초상 표시 | 게임 경험치(경국지계·슬라임 라인), 2·3차 전직 실행, 5·7등신 몸 |
| 2단계: 레벨 · 경험치 · 스탯 포인트 분배 · 초기화 · 칭호 · 출석과 커뮤니티 활동 경험치 | 표정 선택(1단계는 기본 미소 하나), 마을 렌더러 교체(마을 작업이 따로 한다) |

2차 전직은 화면에 갈래와 조건을 보여 주되 "게임 기록 연결 뒤 열립니다"로 잠근다.

## 2. 정한 것(추천안으로 확정)

- **캐릭터 이름은 따로 받지 않고 계정 닉네임을 쓴다.** 새 이름 입력을 받으면 어린이 계정을 포함한 새 검수 대상이 생긴다.
- 종족과 1차 직업은 레벨 10 전까지 바꿀 수 있다. 바꾸면 처음 스탯이 다시 계산되고, 분배한 포인트는 그대로 둔다.
- 외형은 언제든 바꿀 수 있다.
- 정적 사이트(gracekingames.com)의 `/character/`는 같은 경로의 커뮤니티 도메인(`https://community.gracekingames.com/character/`)으로 쿼리를 유지한 채 이동한다. API는 커뮤니티 도메인에서 같은 출처 쿠키로 부른다.
- 손님도 만들기와 미리보기를 할 수 있다. 초안은 `localStorage`에 두고, 저장할 때 로그인한다.

## 3. 공용 모델 `assets/character/model.js` (서버 작업자 담당)

브라우저와 서버가 함께 가져다 쓰는 ES 모듈이다. 다른 모듈을 가져오지 않는다.

2차 전직 조건은 레벨 15 이상, 위 스탯 조건, 전직 시험(서로 다른 게임 2개에서 각 5판)이다. 이번 범위에서는 조건 충족 여부만 계산해 보여 주고, 전직 시험은 항상 미충족으로 둔다.

### 3-4. 외형 선택지 ID

| 필드 | 허용 ID | 뜻 |
| --- | --- | --- |
| `hair` | `h1`~`h8` | 머리 모양 8종(4절) |
| `hairColor` | `c1`~`c10` | 머리색 10종 |
| `eyeColor` | `e1`~`e6` | 눈 색 6종 |
| `skin` | `s1`~`s6` 또는 `null` | 피부 6종. 고정 종족은 `null`만 |
| `outfitColor` | `a1`~`a8` | 옷 강조색 8종 |

색 값(RGB)은 그림 작업자가 `manifest.json`의 `palettes`에 둔다. 모델은 ID만 검사한다.

### 3-5. 캐릭터 데이터(저장 형식)

```json
{ "v": 1, "race": "cat", "job": "ranger",
  "appearance": { "hair": "h1", "hairColor": "c3", "eyeColor": "e2", "skin": "s2", "outfitColor": "a1" } }
```

### 3-6. 성장 규칙

- `POINTS_PER_LEVEL = 3`, `CHANGE_LOCK_LEVEL = 10`.
- 레벨 n에서 n+1로 가는 데 필요한 경험치: `levelNeed(n) = 100 + 25 × (n − 1)`.
- `progressFromExp(totalExp)` → `{ level, exp, need }`. 레벨 1, 누적 0에서 시작한다.
- 받은 포인트 = `(level − 1) × 3`. 남은 포인트 = 받은 포인트 − 분배 합.
- 스탯 = `BASE_STAT` + 종족 보정 + 직업 보정 + 분배.
- 칭호 구간 `TITLE_TIERS = [30, 50, 80]`. 스탯마다 세 칭호를 둔다(예: 힘 30 "장사", 50 "천하장사", 80 "전설의 장사"). 칭호 문구는 서버 작업자가 정한다.
- 경험치 규칙 `EXP_RULES`: 출석 하루 30, 커뮤니티 글 40(하루 2회), 댓글 10(하루 5회), 하루 합계 300. 기준 날짜는 한국 시간(그레인 보상의 `kstDate`와 같다).

### 3-7. 내보내는 이름

`STATS`, `RACES`, `JOBS`, `BASE_STAT`, `POINTS_PER_LEVEL`, `CHANGE_LOCK_LEVEL`, `TITLE_TIERS`, `EXP_RULES`, `APPEARANCE_OPTIONS`, `FIXED_SKIN_RACES`, `levelNeed`, `progressFromExp`, `statsOf(data, alloc)`, `titlesOf(stats)`, `branchStatus(job, stats, level)`, `validateCharacterData(data)`(잘못되면 `{ code, field, message }`를 담은 오류를 던진다), `createDefaultCharacter()`.

## 4. 그림 `assets/character/` (그림 작업자 담당)

### 4-1. 캔버스와 층

- 원본 편집 캔버스는 1024×1536. 납품은 절반 크기 512×768 WebP(알파 포함)다.
- **머리 위 여백:** 기존 3.5등신 기준 몸(`.handoff/캐릭터시안-2026-11-19/부품시험/부품/base.png`)을 0.86배로 줄이고 아래로 옮겨, 머리 꼭대기가 원본 기준 y≈260 아래에 오게 한 새 기준 몸에서 모든 편집을 시작한다. 긴 토끼 귀·뿔이 들어갈 자리다.
- 층 순서(아래 → 위): `back`(꼬리·날개) → `hairBack` → `body`(종족 몸, 얼굴 포함) → `outfit` → `hairFront` → `ears`(동물 귀·뿔).

### 4-2. `manifest.json`

```json
{
  "v": 1,
  "canvas": { "w": 512, "h": 768 },
  "portrait": { "x": 0, "y": 0, "size": 0 },
  "order": ["back", "hairBack", "body", "outfit", "hairFront", "ears"],
  "races": {
    "cat": { "body": "parts/body/cat.webp", "skinMask": "parts/body/cat-skin.webp", "eyeMask": "parts/body/cat-eye.webp",
             "back": "parts/race/cat-back.webp", "ears": "parts/race/cat-ears.webp" }
  },
  "hair": { "h1": { "label": "헝클어진 짧은 머리", "front": "parts/hair/h1-front.webp", "back": null, "mask": "parts/hair/h1-front-mask.webp", "backMask": null } },
  "outfits": { "ranger": { "image": "parts/outfit/ranger.webp", "accentMask": "parts/outfit/ranger-accent.webp" } },
  "palettes": {
    "hair": [{ "id": "c1", "label": "밤색", "rgb": [124, 74, 44] }],
    "eye": [], "skin": [], "accent": []
  }
}
```

- `portrait`: 얼굴을 담는 정사각 영역(납품 캔버스 좌표). 초상과 아이콘은 이 영역을 잘라 쓴다.
- 없는 층은 `null`. 마스크는 같은 캔버스 크기의 회색조 WebP이며 흰색이 색을 바꾸는 영역이다.
- 종족 몸의 기본 머리색·눈 색·피부는 팔레트 첫 항목과 같지 않아도 된다. 화면은 항상 마스크로 고른 색을 입힌다.
- 머리 모양 8종: `h1` 헝클어진 짧은 머리, `h2` 긴 생머리, `h3` 단정한 단발, `h4` 높은 포니테일, `h5` 양 갈래 땋은 머리, `h6` 뻗친 머리, `h7` 둥근 보브, `h8` 긴 웨이브. 긴 머리는 앞(`front`)과 몸 뒤(`back`)를 따로 그린다.
- 옷 10벌은 1차 직업마다 하나. 3.5등신 꼬마 모험가가 입는 가벼운 차림으로, 무기는 작게 들거나 등에 멘다.

### 4-3. 색 바꾸기(화면과 그림이 같은 식을 쓴다)

마스크 영역 안에서 선(명도 0.22 이하)과 무채색(채도 0.12 이하)을 뺀 화소만 바꾼다. 영역의 명도 중앙값을 m_v, 채도 중앙값을 m_s라 할 때, 목표 색의 HSV(h_t, s_t, v_t)에 대해 새 화소는 `h = h_t`, `s = clamp(s / m_s × max(s_t, 0.04))`, `v = clamp(v / m_v × v_t)`다. 마스크 값이 0과 1 사이면 원래 색과 섞는다. 그림 작업자는 이 식의 파이썬 구현을 `scripts/character-art/`에 두고, 화면 작업자는 같은 식을 자바스크립트로 구현한다.

## 5. 서버 (서버 작업자 담당)

- 모듈은 `server/character/`에 둔다. `server/app.js`에는 생성·라우팅 연결만 더한다.
- 저장(SQLite, 기존 DB):
  - `characters(userId PK → user(id) ON DELETE CASCADE, id UUID, data JSON, alloc JSON, totalExp, resetFreeUsed, lastResetAt, revision, createdAt, updatedAt)`
  - `character_exp_events(eventId PK, userId → user(id) ON DELETE CASCADE, source, amount, expDate, createdAt)`
- 경험치 지급은 서버만 한다. 같은 `eventId`는 한 번만 받는다. 하루 합계와 출처별 횟수 상한을 서버가 계산한다. 그레인 보상 정지 계정(`grain_reward_suspensions`)은 경험치를 받지 못한다.
- 출석: `POST /api/character/me/checkin`으로 하루 한 번 30. 그레인 출석(`/api/grain/attendance`)이 성공하면 같은 날 캐릭터 출석도 함께 처리한다(이미 받았으면 그냥 넘어간다). 캐릭터가 없으면 경험치를 쌓지 않는다.
- 커뮤니티: 그레인 활동 보상이 `confirmed`가 되는 순간 같은 글·댓글에 대해 경험치 이벤트(`grain:<eventId>`)를 만든다. 확정 규칙(24시간 유지, 숨김·삭제 취소)을 그대로 따른다.
- API(모두 JSON, 기존 계정 API와 같은 출처 검사·요청 제한·보안 헤더):

| 요청 | 결과 |
| --- | --- |
| `GET /api/character/me` | 200 `{ character: null }` 또는 `{ character: { id, revision, data, progress: { level, exp, need, totalExp, points }, alloc, stats, titles, branches, reset: { available, nextFreeAt }, checkedInToday } }`. 로그인 없으면 401 |
| `PUT /api/character/me` `{ revision, data }` | 첫 생성은 revision 0. 성공 시 위와 같은 모양. 버전 불일치 409, 잘못된 값 422, 레벨 10 이상에서 종족·직업 변경 422 `CHANGE_LOCKED` |
| `POST /api/character/me/allocate` `{ revision, stat, amount }` | amount는 1 이상 정수. 남은 포인트 초과 422 |
| `POST /api/character/me/reset` `{ revision }` | 분배를 모두 포인트로 되돌린다. 첫 번째는 무료, 이후 마지막 초기화 30일 뒤부터 무료. 그 전이면 422 `RESET_NOT_READY`. 유료 초기화는 없다 |
| `POST /api/character/me/checkin` | `{ granted, amount, character }` |

- 커뮤니티 글·댓글 응답의 작성자 정보에 `character: { race, job, level, appearance }` 또는 `null`을 더한다. 회원 ID는 계속 내보내지 않는다.
- 마을 등 다른 서버 모듈이 쓸 `getPublicCharacter(db, userId)`를 내보낸다(같은 공개 필드).
- 정적 제공: `/character/`를 `server/app.js` 정적 경로에 더하고, `Dockerfile`에 `COPY character/ ./character/`, `.dockerignore`에 `character/`, `assets/character/`, `server/character/`를 허용한다. 이 세 파일은 서버 작업자만 고친다.

## 6. 화면 (화면 작업자 담당)

- 파일: `character/index.html`, `assets/character/character.js`, `assets/character/character.css`, `assets/character/render.js`. 계정 화면(`account/index.html`, `assets/account/*`)과 커뮤니티 화면(`assets/community/*`)의 초상 표시.
- `render.js`: `loadCharacterArt(baseUrl = '/assets/character/')`, `renderCharacter(canvas, data, { mode: 'full' | 'portrait', size })`. 그림과 색 바꾼 층을 캐시한다. 마을도 나중에 이 함수를 쓴다.
- 만들기 흐름: 종족 → 꾸미기 → 직업(스탯 미리보기) → 확인·저장. 저장 뒤 "내 캐릭터": 큰 그림, 닉네임·종족·직업·레벨, 경험치 막대, 남은 포인트와 스탯 10개(+ 단추), 초기화, 칭호, 출석, 외형 바꾸기, 레벨 10 전 종족·직업 바꾸기, 2차 갈래 미리보기(잠김).
- 글꼴은 `assets/shared/fonts.css`의 변수만 쓴다(`scripts/verify_site.py`가 검사). 390px 휴대전화 폭과 키보드만으로 모두 조작할 수 있어야 한다.
