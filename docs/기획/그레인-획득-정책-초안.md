# 그레인 무료 획득 정책 기획

2026-10-17 사용자 요청으로 작성한 기획이다. 같은 날 사용자가 **지급량·한도는 제안값대로, 출석 보상 포함, 기존 글·댓글 소급 지급 없음**을 확정했고, 이어서 나머지 네 항목도 권장안대로 확정했다(9절). 2026-10-18 사용자 요청으로 구현·공개 배포했다(11절). 확정된 내용은 [그레인 기획](그레인-화폐-디자인.md)의 무료 화폐 운영 정책에도 반영했다.

## 1. 배경과 목적

슬라임 레이스는 그레인으로 티켓을 사서 배당을 받는 형식이다. 그레인이 현금 가치를 가지면 도박으로 볼 여지가 커지므로 그레인을 **완전한 무료 재화**로 운영한다. 무료 전용 원칙(현금 구매·충전·환전, 상품·쿠폰·유료 아이템 교환, 회원 간 양도·송금, 유료 재화 전환 금지)은 같은 날 이미 확정해 서버 `GRAIN_ECONOMY`에 고정했다.

이 기획은 그 위에 **획득 경로를 이벤트와 커뮤니티 활동 전반으로 넓히는 방안**을 정리한다. 기존 정책의 “새로운 출석 보상이나 소진 보충은 추가하지 않는다”는 문장은 출석 보상 포함 결정에 따라 바꿨다. 소진 보충은 계속 추가하지 않는다.

## 2. 기본 원칙: 닫힌 순환

| 방향 | 허용 | 금지 |
| --- | --- | --- |
| 들어오는 길 | 이벤트, 커뮤니티 활동, 운영자 확인 보상, 레이스 취소 반환·당첨 정산 | 현금 결제, 유료 재화(그레이스 코인·경국지계 유료 옥) 구매·전환, 유료 상품 구매 보너스 |
| 나가는 길 | 사이트 게임 안 사용(현재 레이스 티켓) | 현금·상품권·쿠폰·실물·유료 아이템 교환, 회원 간 양도·송금, 유료 재화 전환 |

- **유료 결제와 연결하지 않는다.** 그레이스 코인 충전이나 유료 상품 구매에 그레인을 덤으로 주지 않는다. 덤으로 주면 그레인을 사실상 돈으로 사는 구조가 된다.
- **보유량과 레이스 성과를 실물 보상과 연결하지 않는다.** “그레인 많이 모은 사람에게 기프티콘”, “레이스 적중왕 경품”처럼 그레인이나 레이스 결과를 현물로 바꾸는 이벤트를 하지 않는다. 그레인으로 받는 보상만 허용한다.
- **원화와 같은 단위나 환산 표기를 쓰지 않는다.** “1 그레인 = 1원”, “○○원 상당” 같은 표현을 금지한다. 게임산업법 제28조 제1항 제2호의2는 게임머니 단위를 원화와 같게 하는 운영으로 사행성을 조장하는 것을 금지한다.
- **계정 거래를 금지한다.** 양도 기능이 없어도 계정을 사고팔면 그레인이 현금과 바뀐다. 계정·그레인의 판매, 대리 이용, 외부 거래 알선을 금지하고 적발하면 회수·이용 제한한다. 게임산업법 제32조 제1항 제7호는 누구든지 게임머니를 환전·환전 알선·재매입하는 것을 업으로 하지 못하게 한다.
- **획득을 홍보하되 사행심을 자극하지 않는다.** “그레인 벌어서 대박 배당” 같은 문구를 쓰지 않는다.

## 3. 획득 경로

금액은 신규 가입 30,000 그레인과 레이스 최소 티켓 100 그레인을 기준으로 잡았고, 2026-10-17 사용자가 **제안값대로 확정**했다. 활발한 회원이 활동만으로 열흘쯤 지나면 가입 보상만큼 모이는 속도를 목표로 했다.

활동 보상은 기능을 공개한 뒤의 활동부터 적용한다. 그 전에 작성한 글·댓글이나 지난 접속 기록에는 **소급 지급하지 않는다**(2026-10-17 사용자 결정).

### 3-1. 커뮤니티 활동 (자동 지급)

| 활동 | 지급량 | 하루 한도 | 지급 조건 |
| --- | --- | --- | --- |
| 출석(하루 첫 접속) | 300 | 1회 | 로그인 상태에서 계정 화면이나 커뮤니티 진입. 한국 시간 0시 기준 |
| 글 작성 | 500 | 3회(1,500) | 제목 2자·본문 30자 이상, 같은 회원의 직전 글과 내용이 다를 것 |
| 댓글 작성 | 100 | 10회(1,000) | 본문 10자 이상, 본인 글의 댓글 제외, 같은 글에는 첫 댓글만 지급 |

- 자동 지급 활동의 합계 한도는 **하루 3,000 그레인**으로 둔다(출석 300 + 글 1,500 + 댓글 1,000 = 2,800이므로 지금은 각 한도로 충분하다. 활동 종류가 늘어날 때 합계 한도로 묶는다).
- 글·댓글 보상은 **작성 후 24시간 동안 유지되면 확정**한다. 확정 전 삭제되거나 운영자가 숨기면 지급하지 않는다. 확정 후 삭제는 회수하지 않는다(즉시 지급 후 회수 방식을 쓰지 않는 이유는 4절 참고). 확정 전 보상은 계정 화면에 “적립 예정”으로 바로 보여 준다(2026-10-17 사용자 결정).
- 글 수정으로 보상이 다시 생기지 않는다. 지급 단위는 글·댓글 하나당 한 번이다.

### 3-2. 운영자 확인 보상

| 활동 | 지급량 | 기준 |
| --- | --- | --- |
| 버그 리포트 — 단순 | 2,000 | 오탈자·화면 깨짐 등 재현 가능한 표시 문제 |
| 버그 리포트 — 일반 | 5,000 | 기능이 동작하지 않거나 진행이 막히는 문제 |
| 버그 리포트 — 중대 | 20,000 | 보안 취약점, 그레인·원장 오류, 개인정보 노출, 데이터 손실 |
| 우수 글 선정 | 3,000 | 운영자가 고른 가이드·공략·창작 글. 한 글에 한 번 |

- 같은 버그는 **처음 제보한 한 사람만** 받는다. 재현이 안 되거나 이미 알려진 문제는 지급하지 않는다.
- 버그 리포트는 공개 게시판이 아닌 **로그인 계정에 연결한 비공개 양식**으로만 받는다(2026-10-17 사용자 결정). 서버가 접수 시각과 계정을 기록해 최초 제보자를 판단한다. 그레인 중복 지급처럼 악용 방법이 될 수 있는 문제가 수정 전에 퍼지지 않게 하기 위해서다.
- 커뮤니티 게시판에 버그·보안 제보가 올라오면 숨김 처리하고 비공개 양식으로 다시 받는다.
- 중복 제보를 줄이기 위해 운영자가 확인한 문제는 악용 방법을 빼고 **“알려진 문제” 목록**으로 공개한다.
- 운영자 지급은 누가·왜·얼마를 줬는지 원장에 남긴다.

### 3-3. 이벤트

- 운영자가 공지한 이벤트(업데이트 기념, 시즌 시작, 설문 참여, 커뮤니티 대회 등)마다 **이벤트 식별자·대상·지급량·기간**을 미리 정하고 공지한다.
- 같은 이벤트로는 계정당 한 번만 받는다. 기존 신규 가입 이벤트(30,000)는 그대로 유지한다.
- 이벤트 보상도 그레인으로만 준다. 실물 경품이 필요한 이벤트는 그레인 보유량·레이스 결과와 무관한 별도 이벤트로 운영한다.

### 3-4. 후속 후보 (이번 범위 아님)

- 경국지계·슬라임 라인 플레이 성과(업적, 시즌 참여)에 따른 그레인 지급. 공통 계정 연결이 끝난 게임부터 검토한다.
- 좋아요·추천 수 기반 보상. 서로 밀어주기 남용이 커서 도입하지 않는 쪽을 권한다.

## 4. 남용 방지

- **자격**: 이메일 확인을 마친 계정만 활동 보상을 받는다. 현재 커뮤니티는 이메일 미확인 기존(legacy) 계정의 글쓰기를 허용하지만, 보상은 확인 후에만 준다(2026-10-17 사용자 결정). 미확인 계정도 인증 메일을 다시 받아(서버 경로 `/api/auth/send-verification-email`) 확인하면 그 뒤 활동부터 보상을 받는다. 확인 전 활동은 소급하지 않는다. 계정 화면에 인증 요청 버튼이 보이는지는 구현 때 확인한다.
- **한도와 품질**: 하루 한도, 최소 글자 수, 직전 글과 같은 내용 반복 금지, 본인 글 댓글 미지급, 같은 글 반복 댓글 미지급.
- **확정 지연**: 지갑 잔액은 0 아래로 내려갈 수 없다(`balance >= 0`). 즉시 지급 후 회수하면 이미 레이스에 쓴 그레인을 되찾을 수 없으므로 24시간 확정 방식을 기본으로 한다.
- **확정 후 위반**: 다중 계정·도배·계정 거래가 확정 뒤 드러나면 남은 잔액 범위에서 회수하고, 부족하면 해당 계정의 보상과 레이스 이용을 정지한다.
- **1인 1계정**: 한 사람이 여러 계정으로 보상을 받으면 추가 계정의 보상을 회수한다. 양도가 불가능하므로 여러 계정에 모은 그레인을 한 계정으로 합칠 수는 없다.
- **운영 도구 선행**: 지금 커뮤니티에는 신고와 운영자 숨김·삭제 기능이 없고 작성자 본인만 지울 수 있다. 활동 보상을 열기 전에 **신고, 운영자 숨김, 보상 정지** 기능이 먼저 있어야 한다.

## 5. 연령별 적용

| 계정 | 커뮤니티 활동 보상 | 이벤트 보상 | 레이스 티켓 |
| --- | --- | --- | --- |
| 만 14세 미만(보호자 동의) | 해당 없음(게시판 쓰기 불가) | 지급하지 않음 | 불가 |
| 만 14세 이상 | 지급 | 지급 | 성인 본인확인 전 잠금 |
| 성인 본인확인 완료 | 지급 | 지급 | 가능(본인확인 연동 후) |

만 14세 미만 계정에는 출석·이벤트 그레인을 주지 않는다(2026-10-17 사용자 결정). 현재 그레인 사용처는 성인 전용 레이스뿐이고, 베팅에 쓰는 재화를 어린이에게 계속 지급하지 않기 위해서다. 이미 받은 신규 가입 보상 30,000은 그대로 둔다. 어린이도 이용할 수 있는 사용처가 생기면 다시 정한다.

그레인을 받는 것과 레이스를 이용하는 것은 따로 판단한다. 그레인을 많이 가졌다고 레이스 연령 잠금이 풀리지 않는다.

## 6. 원장과 표시

- 모든 지급은 기존 공용 원장 `grain_ledger`에 남기고 `UNIQUE(userId, eventId)`로 중복 지급을 막는다. 식별자는 `community-post:<글 ID>`, `community-comment:<댓글 ID>`, `attendance:<YYYY-MM-DD>`, `bug-report:<접수 ID>`, `event:<이벤트 ID>`처럼 활동마다 하나로 정한다.
- 확정 대기 중인 보상은 잔액에 넣지 않고 계정 화면에 “적립 예정”으로 따로 보여 준다.
- 계정 화면 ‘이용 내역’에 활동 종류(출석·글·댓글·버그 리포트·이벤트)를 사유로 표시한다.
- `GRAIN_ECONOMY`의 거래 관련 항목은 계속 `false`로 둔다. 지급 경로가 늘어도 나가는 길은 늘리지 않는다.

## 7. 이용자 안내와 문서

현재 사이트에는 **이용약관이 없다**. 그레인을 회수하거나 계정 거래를 제재하려면 근거가 필요하므로 활동 보상 공개 전에 이용약관을 만든다.

- **계정 화면·레이스 안내 문구(안)**: “그레인은 이벤트와 커뮤니티 활동으로만 받는 무료 화폐예요. 돈으로 사거나 현금·상품으로 바꿀 수 없고, 다른 회원에게 줄 수 없어요.”
- **이용약관에 넣을 조항**: 그레인의 정의(무료 재화, 재산적 가치 없음), 획득 방법, 사용처, 금지 행위(판매·구매·환전·양도·계정 거래·다중 계정·도배), 회수와 이용 제한, 서비스 변경·종료 때 보상하지 않음(무료 재화라 환불 대상 아님).
- **개인정보처리방침**: 출석·활동 보상 기록과 버그 리포트 접수 정보 처리 항목을 추가한다.
- **버그 리포트 창구**: 현재 제보는 계정과 연결되지 않은 구글 설문(`제보·의견`)으로만 받는다. 보상을 주려면 로그인 계정과 연결된 접수 경로가 필요하다.

## 8. 법·등급 관련 확인 사항

이 절은 확인할 항목을 정리한 것이며 법적 판정이 아니다.

- 무료 지급·환전 불가로 도박의 재산상 이익 요건과는 멀어지지만, 고정 배당 경주라는 **형식 자체가 등급분류에서 사행성 모사로 평가될 수 있다.** 성인 본인확인 잠금을 유지하고, 게임위 문의 목록에 “무료 재화 + 커뮤니티 활동 보상 + 고정 배당 경주”의 등급 판단을 추가한다.
- 게임산업법 제28조 제1항 제3호는 경품 제공으로 사행성을 조장하는 것을 금지한다. 2절의 “보유량·레이스 성과와 실물 보상 분리” 원칙이 이 조항에 맞추기 위한 것이다.
- 그레이스 코인(유료 재화) 기획과 그레인은 어떤 방향으로도 바꿀 수 없다는 원칙을 그레이스 코인 기획서에도 같이 적는다.

- [x] 만 14세 미만 계정의 출석·이벤트 그레인 → 지급하지 않음. 어린이용 사용처가 생기면 다시 정함.
- [x] 이메일 미확인 기존 계정 → 보상 대상에서 제외. 인증하면 그 뒤 활동부터 지급.

## 10. 구현 순서 제안 (구현은 사용자가 명시한 뒤)

4. 로그인 계정에 연결한 비공개 버그 리포트 양식, 운영자 확인 지급, “알려진 문제” 목록

## 11. 구현 상태 (2026-10-18 공개 배포)

사용자가 활동 보상 구현을 요청해 통합 브랜치 `formars0309-cloud/grain-rewards`와 하위 작업 브랜치에서 구현·격리 검증을 진행했다. 이 절 이전의 “구현 전”, “없다”는 표현은 기획 당시의 상태이며, 공개 운영에 반영했다는 뜻은 아니다. 공개 발행·배포, 운영 DB·Fly·비밀값 변경은 이번 작업에 포함하지 않았다.

- 계정·로그인 커뮤니티 진입의 하루 출석 300, 글 500·댓글 100의 24시간 예정/확정, 한국 날짜 한도와 미확인·어린이·정지 자격을 서버에서 처리한다. 기존 글·댓글 소급과 기존 가입 보상 재지급은 하지 않는다.
- 계정 화면에 적립 예정 합계·목록·확정 예정 시각·이용 사유와 보상 자격을 표시하며, 미확인 회원은 기존 이메일 확인 메일 요청으로 안내한다.
- 글·댓글 신고와 운영자 숨김·복원·보상 정지·회수, 비공개 버그 접수와 상태 확인, 버그 등급 채택, 알려진 문제 공개·수정, 우수 글 선정, 이벤트 등록·대상 지급 도구를 구현했다. 제보 원문은 운영자만 확인하고 본인은 접수번호·상태 목록만 확인한다.
- 운영자 ID는 서버 `ADMIN_USER_IDS`의 쉼표 목록으로만 지정한다. 활동·제보·운영 조치는 기존 공용 지갑·원장과 신규 표에 저장하며, 24시간 만기 보상은 시작 시와 실행 중 60초 간격으로 확정한다. 유휴 정지 중에는 다음 서버 시작 때 처리하므로 정확히 만기 시각의 즉시 지급을 보장하지 않는다.
- 새 페이지·자산의 Docker 명시 허용, 비공개 화면의 검색 색인·외부 통계 차단, 정적 검사와 격리 브라우저 검증 절차를 추가했다. 약관·개인정보처리방침의 별도 작업과 통합 검수가 끝나야 공개 준비가 완료된다.

실제 API·저장 표·운영 방법과 검증 명령은 [공통 계정 운영](../공통계정-운영.md)에 기록한다. 2026-10-18 사용자 요청으로 이용약관·개인정보처리방침과 함께 공개 배포했다. 배포·검증 내역은 [커뮤니티 배포 기록](../커뮤니티-배포.md)의 2026-10-18 절을 따른다.
