## 2. 열 곳에서 공통으로 보인 것

1. **공지는 맨 위에 고정하되 적게 보인다.** 공지를 맨 끝 탭에 두는 곳은 없었다(Reddit 하이라이트 카드 3장, 아카라이브 공지 접기, 인벤 소식 모음 상자, HoYoLAB 공식 탭 맨 앞).
2. **글이 적을 때는 운영자 글이 첫 화면을 채운다.** 날짜가 붙은 짧은 패치 노트, 테스트 단계 연재(베타 모집 → 데모 공개 → 「데모를 깨 보세요」), 직접 쓴 시작 가이드, 카드 목록·용어 사전 같은 것들이다. 그림이 붙은 카드로 보여 주면 글 수가 적어도 꽉 차 보인다(STOVE).
3. **피드백은 한 곳으로 모으고, 무엇을 적을지 정해 준다.** 버그 게시판 위에 「제보 전에 해 볼 것」을 고정하고(Steam), 「기대한 결과와 실제 결과」 같은 적을 칸을 정해 준다(Card Monarchy). 처리한 건에는 「해결됨」·「반영됨」을 붙이거나 묶음 답글로 알린다(Gruntz, Card Hog).
4. **운영자 글에는 표시가 붙는다.** Developer, OFFICIAL, GM, 모더레이터 강조 등으로 이용자 글과 한눈에 구분된다.
5. **장식은 적게, 강조색은 하나.** 장식 화살표는 거의 없고 페이지 넘김·뒤로 가기에만 쓴다. 빨강을 주 버튼 색으로 쓰는 곳은 itch 기본 테마와 Reddit 로그인 버튼뿐이었다(2026-10-19 화살표 제거·푸른 버튼 수정과 같은 방향).
6. **인기글·추천·투표·반응은 모두 글이 많을 때 의미가 있다.** 지금 넣으면 0이라는 숫자만 드러난다.

반면교사: 답글 없는 고정 글을 여러 개 미리 깔아 둔 곳(State of Wonder)은 오히려 버려진 곳처럼 보였다. 빈 게시판을 아무 처리 없이 두면(Cards of a Journey) 같은 인상을 준다.

### 2단계 API 계약

서버·DB 구현 범위이며 화면 연결과 공개 배포는 별도 작업이다. 두 게임 모두 기존 게시판에 `notice`를 추가한다. 운영자 판정은 기존 `isAdmin(user)`(설정된 계정이며 현재 계정·이메일 확인 조건 충족)를 그대로 사용한다. 운영자 목록과 이메일은 공개하지 않는다.

| 항목 | 필드·값·권한 |
| --- | --- |
| 새 소식 생성 | `POST /api/community/posts`, 기존 `game`, `board`, `title`, `body`와 선택 `category`, `cover`. `board=notice`는 운영자만 가능. 비로그인 401, 일반 회원 403. |
| 새 소식 수정·삭제 | 기존 `PATCH /api/community/posts/:id`, `DELETE /api/community/posts/:id`. 작성자 외의 운영자도 공동 편집·삭제 가능. 일반 게시판과 댓글은 기존 본인 소유권 규칙 유지. 게시판·게임 이동은 지원하지 않음. |
| 목록·읽기·검색·댓글 | 기존 경로·검색·페이지·댓글 규칙을 `notice`에도 적용. 숨긴 글·댓글은 공개 읽기에서 제외. |
| 말머리 | `category`: `devnote`=개발 노트, `changes`=바뀐 점, `event`=행사, `guide`=안내, 또는 `null`. 앞의 세 값은 3-2의 분류를 따르고, `guide`는 첫 방문·규칙 등 기존 공식 안내를 구분하기 위해 추가. |
| 대표 그림 | `cover`: 아래 게임별 키 또는 `null`. 경로·URL·업로드·다른 게임의 키는 거부(422). 서버는 검증용 키 목록만 보유하고 실제 경로와 타일 자르기는 화면이 매핑. |
| 메타데이터 기본값 | 새 글의 `category`, `cover`, `status` 기본값은 `null`. `category`·`cover`는 새 소식에서만 비어 있지 않은 값을 허용하고 다른 게시판은 `null`. 본문 수정 시 생략한 말머리·그림은 보존하고 명시적 `null`은 해제. |
| 처리 상태 | 모든 게시판의 `status`: `checking`=확인 중, `solved`=해결됨, `applied`=반영됨, 또는 `null`. 운영자만 `PATCH /api/community/posts/:id/status`에 정확히 `{ "status": 값 }`으로 변경·해제. 선택 `?game=` 불일치는 404. 기존 글 생성·본문 수정 경로의 `status` 전달은 422로 거부. 상태 변경·해제는 본문 수정 시각 `updatedAt`을 바꾸지 않음. |
| 공개 작성자 | 글·댓글의 `author`는 `{ name, isOperator: true/false }`. 이전 `author.id`는 제거하며 운영자 ID·이메일·설정 목록을 보내지 않음. `canEdit`는 서버 판정을 사용. 운영자 표시는 작성자의 현재 자격을 반영. 운영 신고·숨김 응답의 작성자도 같은 형태. |
| 현재 세션 | `GET /api/community/session`의 `user`에 `isOperator: true/false` 추가. 기존 본인 `id`, `name`, `canWriteCommunity`는 유지하고 비로그인은 `{ user: null }`. |
| 보상·운영 | 새 소식 글은 활동 보상 기록·예약·확정·일일 한도·중복 판정에서 제외하며 `reward={ pending:false, amount:0 }`. 일반 게시판 글과 새 소식 댓글의 기존 활동 보상 규칙, 수동 운영 지급 규칙은 유지. 기존 신고·숨김·복구 API와 감사 기록을 그대로 사용. 운영 신고 대상·숨김 글에도 세 메타데이터를 포함. |

대표 그림 키와 실제 기존 파일의 계약은 다음과 같다. 경국지계 타일은 기존 커뮤니티 CSS의 `background-size:300% 200%`와 네 게시판 좌표를 따른다. 새로운 그림 파일은 만들지 않는다.

| 게임 | 허용 키 | 화면 매핑 경로·자르기 |
| --- | --- | --- |
| 경국지계 | `tile-free`, `tile-deck`, `tile-strategy`, `tile-notice` | `/assets/gyeongguk/tiles.webp`, 차례대로 위치 `0 0`, `50% 0`, `100% 0`, `0 100%` |
| 경국지계 | `card-lubu`, `card-diaochan`, `card-zhugeliang` | 차례대로 `/assets/gyeongguk/card-lubu.webp`, `/assets/gyeongguk/card-diaochan.webp`, `/assets/gyeongguk/card-zhugeliang.webp` |
| 슬라임 라인 | `tiles`, `hero` | `/assets/slimeline/tiles.webp` 전체, `/assets/slimeline/hero.webp` 전체 |

화면 연결 작업자는 이 표를 화면 쪽 경로 매핑으로 옮기고, `session.user.isOperator`로 운영 버튼을 표시한다. 공개 작성자의 `author.id`에 의존하던 화면 분기도 함께 바꿔야 한다(현재 자기 글 신고 금지는 서버에서 계속 검사). 상태 버튼은 전용 상태 경로를 사용한다. `/account/admin/`의 기존 신고·숨김 화면은 같은 경로를 유지하며 상태 편집 화면은 후속 연결 범위다.

### 2단계 화면 연결 결과 (2026-10-20)

- 두 게임의 서버 새 소식을 최신순으로 먼저 표시하고 고정 공식 안내를 이어 붙였다. 최근 카드 3개는 서버 글부터 채우고 부족한 자리는 날짜가 있는 고정 안내로 채운다. 카드에 쓴 글은 같은 새 소식 목록에서 중복하지 않는다. 검색은 서버 글과 고정 안내를 함께 찾으며, 서버 글의 기존 페이지 이동을 유지한다. 연결 실패 시 고정 안내와 카드로 읽기를 계속 제공한다.
- 대표 그림은 위 계약의 9개 키·타일 좌표를 기존 자산에 매핑하고 시험으로 서버 키 목록과 일치시켰다. 그림 미선택 시 해당 게임의 `hero.webp`, 말머리 미선택 시 ‘새 소식’을 사용한다. 카드 날짜와 글·댓글 시각은 한국 시간 기준이다.
- 운영자에게 새 소식 작성·말머리·그림 미리보기 선택, 글 읽기의 처리 상태 저장·해제를 연결했다. 수정·닫기·재열기 때 선택값을 보존한다. 글·댓글의 운영자 표시, 목록·읽기의 상태 배지, `canEdit`에 따른 본인 신고 숨김을 반영했다. 날짜 없는 고정 안내는 날짜를 생략하며 새 소식 작성·빈 안내에는 보상을 표시하지 않는다.
- 실제 `server/`와 임시 DB·시험 계정으로 검증하는 `test/community-phase2-browser.mjs` 및 격리 서버 준비 파일을 추가했다. 서버 코드는 변경하지 않았다. 두 게임의 테마와 기존 이동용 화살표 3종을 유지했다.

### 3-3. 다른 저장소 작업

- **게임 화면에서 커뮤니티로 바로 오는 버튼**(결과 화면의 「소감 남기기」 등). Card Hog 참고. 게임 쪽 수정이라 각 게임 저장소에서 따로 기획한다.
- **덱 연구·공략 탭에 공식 자료 고정**(카드 목록·용어 사전, 슬라임 공략 기초). Card Monarchy 참고. 게임 데이터 정리가 먼저 필요하다. 다만 고정 글은 1~2개로 제한한다(반면교사 참고).

### 3-4. 글이 늘면 (회원 수십 명, 하루 글 몇 개 이상)

- 인기글 모음과 추천 기준(인벤 10추·30추, 아카라이브 개념글)
- 본문 투표(「이 덱 어때요」, 「다음 슬라임 색 고르기」)
- 게임 그림 이모지 반응(장수 얼굴·슬라임 표정)
- 게시판별 「마지막 글·시각」 표시
- 공동 한 판 연재: 운영자가 경국지계 대전 상황을 올리고 댓글로 다음 수를 정한다(Reddit 「Community Slay Day」). 참여자가 없으면 댓글 0개가 그대로 드러나므로 회원이 늘어난 뒤에 시작한다.
- 「버그를 찾아라」 같은 테스트 참여 행사와 그레인 보상 연동(남용 방지 확인 절차와 함께)

### 3-5. 우리와 안 맞음

- 답글 없는 고정 글을 여러 개 미리 깔아 두기
- 미디어별 탭(스크린샷·영상·가이드·리뷰) 늘리기. 그림 첨부가 없고 글도 없어 빈 탭만 는다.
- 현금·인기글 보상 경쟁. 보상만 노린 글이 생기고 1인 검수 부담이 커진다. 그레인은 지금처럼 조용히 안내한다.
- 이모지 게시판 이름, 붉은 버튼 체계
- 모바일에서 로그인 창으로 글 읽기 막기(HoYoLAB)

### 3-6. 선택 사항

- 게임 용어 회원 호칭(Reddit 「Slayers」). 예: 경국지계 「책사」, 슬라임 라인 「길잡이」. 세계관 톤은 살지만 필수는 아니다. 사용자 취향으로 정한다.
