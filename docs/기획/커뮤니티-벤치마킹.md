## 2. 열 곳에서 공통으로 보인 것

1. **공지는 맨 위에 고정하되 적게 보인다.** 공지를 맨 끝 탭에 두는 곳은 없었다(Reddit 하이라이트 카드 3장, 아카라이브 공지 접기, 인벤 소식 모음 상자, HoYoLAB 공식 탭 맨 앞).
2. **글이 적을 때는 운영자 글이 첫 화면을 채운다.** 날짜가 붙은 짧은 패치 노트, 테스트 단계 연재(베타 모집 → 데모 공개 → 「데모를 깨 보세요」), 직접 쓴 시작 가이드, 카드 목록·용어 사전 같은 것들이다. 그림이 붙은 카드로 보여 주면 글 수가 적어도 꽉 차 보인다(STOVE).
3. **피드백은 한 곳으로 모으고, 무엇을 적을지 정해 준다.** 버그 게시판 위에 「제보 전에 해 볼 것」을 고정하고(Steam), 「기대한 결과와 실제 결과」 같은 적을 칸을 정해 준다(Card Monarchy). 처리한 건에는 「해결됨」·「반영됨」을 붙이거나 묶음 답글로 알린다(Gruntz, Card Hog).
4. **운영자 글에는 표시가 붙는다.** Developer, OFFICIAL, GM, 모더레이터 강조 등으로 이용자 글과 한눈에 구분된다.
5. **장식은 적게, 강조색은 하나.** 장식 화살표는 거의 없고 페이지 넘김·뒤로 가기에만 쓴다. 빨강을 주 버튼 색으로 쓰는 곳은 itch 기본 테마와 Reddit 로그인 버튼뿐이었다(2026-10-19 화살표 제거·푸른 버튼 수정과 같은 방향).
6. **인기글·추천·투표·반응은 모두 글이 많을 때 의미가 있다.** 지금 넣으면 0이라는 숫자만 드러난다.

반면교사: 답글 없는 고정 글을 여러 개 미리 깔아 둔 곳(State of Wonder)은 오히려 버려진 곳처럼 보였다. 빈 게시판을 아무 처리 없이 두면(Cards of a Journey) 같은 인상을 준다.

## 3. 우리에게 적용할 것

### 3-1. 지금 바로 (조율자 추천 순서)

| 순서 | 항목 | 참고한 곳 | 필요한 작업 |
| --- | --- | --- | --- |
| 1 | **새 소식 카드 고정.** 모든 탭에서 글 목록 위에 최근 새 소식 2~3개를 그림·날짜가 있는 카드로 보인다. 빈 게시판 화면도 「아직 고요합니다」만 남지 않는다. | Reddit, STOVE, 인벤, Card Hog | 화면만. 공식 안내 글에 날짜·대표 그림(기존 자산) 추가 |
| 2 | **첫 방문 안내 한 문장.** 첫 화면 그림 띠에 「처음이라면 새 소식부터, 한 판 소감은 자유 게시판에, 문제는 버그 제보로」처럼 세 곳을 잇는 문장을 둔다. | Gruntz | 화면만 |
| 3 | **피드백 안내 글 다듬기.** 「문제 신고와 소감을 보내는 방법」 공식 글에 적을 칸(어느 화면·무엇을 했는지·기대한 결과와 실제 결과·기기와 브라우저)과 「제보 전에 해 볼 것」(새로고침, 다른 브라우저, 알려진 문제 확인)을 넣는다. | Card Monarchy, Steam | 글 내용만 |
| 4 | **커뮤니티 규칙 한 장.** 이용약관을 요약한 규칙 공식 글과 「제재가 억울할 때」 이의 절차(의견 보내기로 받음)를 둔다. | 아카라이브, Reddit | 글 내용만 |
| 5 | **게임 전환 줄.** 상단에 경국지계·슬라임 라인을 작은 그림과 이름으로 나란히 둔다. 두 게임을 오가기 쉽고 한 회사의 두 게임으로 보인다. | HoYoLAB, Gruntz | 화면만 |
| 6 | **오른쪽 안내 칸을 그림 아이콘 바로가기로.** 출석(그레인)·게임 시작·버그 제보·의견 보내기를 아이콘 4개 격자로 바꾸고, 그레인 지급표는 그 아래에 접어 둔다. | HoYoLAB | 화면. 아이콘은 기존 타일 그림이나 단순 선 그림으로 시작 |
| 7 | **첫 화면 그림 미리 불러오기.** 지금은 그림 요청이 페이지 스크립트 실행 뒤에 출발해 약 0.5초 늦고, 느린 연결에서는 빈 상자가 잠깐 보인다(2026-10-19 실측: DOMContentLoaded 1.7초, 그림 응답 2.3초). `host.js`가 게임을 정할 때 해당 그림을 미리 불러오게 한다. | 조사 중 발견 | 화면만 |

1~7은 서버·DB 변경 없이 커뮤니티 화면과 공식 안내 글만 고친다.

### 3-2. 다음 단계 (서버 기능 필요)

| 항목 | 참고한 곳 | 왜 서버가 필요한가 |
| --- | --- | --- |
| **운영자가 새 소식을 직접 올리기.** 「이번 주 바뀐 점」 같은 짧은 날짜 글을 주 1회 정도 쌓는다. 무료 테스트 단계 자체를 연재 소재로 쓴다. | HELLCARD II, Card Monarchy | 지금 새 소식은 `community.js`에 글 3개가 고정돼 있고, 서버(`BOARDS`)와 DB 제약(`CHECK(board IN …)`)이 공지 게시판 글쓰기를 막는다. 운영자만 `notice`에 쓰도록 권한·DB 이전이 필요하다. |
| **말머리.** 새 소식 안에서 [개발 노트]·[바뀐 점]·[행사]를 구분한다. 게시판을 늘리지 않고 분류한다. | STOVE, 아카라이브 | 글에 분류 값을 저장해야 한다. |

| **처리 상태 표시.** 버그·제안 관련 글에 「확인 중」·「해결됨」·「반영됨」을 붙인다. | Gruntz, Card Hog | 상태 값 저장과 운영자 화면 연동이 필요하다. |

### 3-3. 다른 저장소 작업

- **게임 화면에서 커뮤니티로 바로 오는 버튼**(결과 화면의 「소감 남기기」 등). Card Hog 참고. 게임 쪽 수정이라 각 게임 저장소에서 따로 기획한다.
- **덱 연구·공략 탭에 공식 자료 고정**(카드 목록·용어 사전, 슬라임 공략 기초). Card Monarchy 참고. 게임 데이터 정리가 먼저 필요하다. 다만 고정 글은 1~2개로 제한한다(반면교사 참고).

### 3-4. 글이 늘면 (회원 수십 명, 하루 글 몇 개 이상)

- 인기글 모음과 추천 기준(인벤 10추·30추, 아카라이브 개념글)
- 본문 투표(「이 덱 어때요」, 「다음 슬라임 색 고르기」)
- 게임 그림 이모지 반응(장수 얼굴·슬라임 표정)
- 게시판별 「마지막 글·시각」 표시
- 공동 한 판 연재: 운영자가 경국지계 대전 상황을 올리고 댓글로 다음 수를 정한다(Reddit 「Community Slay Day」). 참여자가 없으면 댓글 0개가 그대로 드러나므로 회원이 늘어난 뒤에 시작한다.
- 「버그를 찾아라」 같은 테스트 참여 행사와 그레인 보상 연동(남용 방지 확인 절차와 함께)

### 3-5. 우리와 안 맞음

- 답글 없는 고정 글을 여러 개 미리 깔아 두기
- 미디어별 탭(스크린샷·영상·가이드·리뷰) 늘리기. 그림 첨부가 없고 글도 없어 빈 탭만 는다.
- 현금·인기글 보상 경쟁. 보상만 노린 글이 생기고 1인 검수 부담이 커진다. 그레인은 지금처럼 조용히 안내한다.
- 이모지 게시판 이름, 붉은 버튼 체계
- 모바일에서 로그인 창으로 글 읽기 막기(HoYoLAB)

### 3-6. 선택 사항

- 게임 용어 회원 호칭(Reddit 「Slayers」). 예: 경국지계 「책사」, 슬라임 라인 「길잡이」. 세계관 톤은 살지만 필수는 아니다. 사용자 취향으로 정한다.
