# gracekingames 공통 계정과 게임 연결 기획

- 기록일: 2026-10-16, 한국시간.
- 상태: 기획 반영. 구현·데이터 이전·공개 배포는 시작하지 않는다.
- 대상: gracekingames 사이트·커뮤니티, 슬라임 라인, 경국지계.
- 요청: TCG 프로젝트의 기획 대화에서 논의한 공통 계정 구상을 gracekin-games 프로젝트에 반영한다.

## 1. 목표와 반영 범위

gracekingames에 가입한 회원이 같은 계정으로 슬라임 라인과 경국지계를 플레이한다. 회원가입·로그인·계정 복구는 공통 계정 체계에서 관리하고, 각 게임에는 회원 확인과 게임 프로필 연결 기능을 둔다. 게임별로 독립적인 가입·비밀번호 관리 체계를 추가하지 않는다.

사이트를 먼저 방문하도록 강제하지 않는다. 사이트에서 게임을 선택하거나 게임 주소·앱으로 직접 들어온 경우 모두 공통 가입·로그인을 시작할 수 있게 한다. 인증 후에는 시작했던 게임으로 돌아온다.

이번 반영은 공통 계정 기획과 README 안내에 한정한다. 게임 코드·스타일·실사용 에셋, 현재 로그인 화면과 동작, 서버·DNS·소셜 로그인 등록 설정은 변경하지 않는다. 대회와 경품은 공통 계정의 후속 활용으로 기록하며 운영 규칙을 확정하지 않는다.

## 2. 현재 상태와 목표의 차이

현재 상태는 2026-10-16에 확인한 저장소 코드와 문서 기준이다. 운영 서버의 배포 상태나 실제 회원 데이터까지 확인했다는 뜻은 아니다.

| 영역 | 현재 확인한 상태 | 목표 |
| --- | --- | --- |
| 사이트·커뮤니티 | 사이트는 GitHub Pages, 커뮤니티는 전용 Fly 서버로 연결하는 구성이다. 커뮤니티의 이메일·닉네임·비밀번호 계정은 게임 계정과 별도다. | 기존 커뮤니티 회원을 보존하면서 사이트와 두 게임에서 사용할 공통 회원 체계를 정한다. |
| 커뮤니티 인증 | Better Auth를 사용한다. 이메일 인증과 비밀번호 재설정 메일은 연결하지 않았다. 서버는 설정한 출처를 기준으로 세션을 처리한다. | 공통 계정의 인증·복구 수단을 마련하고, 게임이 회원을 확인할 연결 방식을 추가한다. |
| 경국지계 | 게스트 계정에 로그인 수단을 연결하는 기획과 관련 코드가 있다. Google·Apple·카카오·네이버·이메일 처리가 게임 안에 존재한다. | 기존 게임 계정과 자산을 유지한 채 공통 회원과 연결한다. 공급자별 운영 설정·승인 상태는 전환 전에 확인한다. |
| 슬라임 라인 | 이 기획 반영에서 로그인·저장 구조를 확인하지 않았다. | 기존 진행도와 구매 기록의 위치·소유권 확인 수단을 조사한 뒤 연결 방식을 정한다. |

경국지계의 기존 기획은 게스트 시작을 허용하지만, 이번 목표는 공통 회원 계정으로 게임을 플레이하는 것이다. 전환 시점과 기존 게스트의 승계 절차는 구현 기획에서 정한다. 이 문서 반영만으로 기존 게스트의 접속을 차단하지 않는다.

## 3. 계정과 게임 데이터의 관계

| 담당 영역 | 보관·관리할 내용 |
| --- | --- |
| gracekingames 공통 계정 | 변경되지 않는 회원 식별자, 로그인 수단, 계정 복구, 로그인 기기·세션 관리 |
| 커뮤니티 | 회원과 연결된 게시글·댓글·커뮤니티 이용 상태 |
| 슬라임 라인 게임 프로필 | 해당 게임의 진행도·재화·플레이 기록 등 게임 고유 데이터 |
| 경국지계 게임 프로필 | 보유 카드·덱·재화·랭크·대전 기록·구매 내역 등 게임 고유 데이터 |

공통 회원 식별자와 각 게임의 기존 플레이어 식별자를 연결한다. 닉네임이나 이메일 주소를 회원 연결의 기준 키로 삼지 않는다. 계정이 같아도 두 게임의 재화·랭크·구매 내역은 합치지 않는다.

초기 연결안은 회원 한 명에게 게임별 프로필 하나를 연결하는 구조다. 이미 같은 게임의 계정이 여러 개 있는 경우에는 어느 계정을 연결할지와 충돌 처리 방법을 먼저 정한다. 계정이나 자산을 자동으로 합치거나 덮어쓰지 않는다.

## 4. 가입과 게임 진입 흐름

1. 사용자가 사이트의 게임 시작 버튼, 게임 주소 또는 앱으로 진입한다.
2. 게임이 유효한 게임용 로그인 상태를 확인한다. 유효하면 연결된 게임 프로필로 시작한다.
3. 로그인 상태가 없으면 공통 인증 화면으로 연결한다. 버튼 문구의 기획 예시는 ‘gracekingames 계정으로 시작’이다.
4. 기존 회원은 로그인하고, 신규 이용자는 같은 흐름에서 공통 계정을 만든다. 공통 로그인 상태가 유효하면 정책에 따라 재입력을 줄인다.
5. 인증 결과를 해당 게임 서버에서 확인하고, 원래 실행한 게임으로 복귀한다.
6. 이미 연결된 게임 프로필이 있으면 그 진행도를 불러온다. 기존 계정을 연결해야 하는 이용자는 승계 절차로 안내하고, 신규 플레이어에게만 새 프로필을 만든다.

다른 게임에서도 같은 회원 계정을 사용한다. 기기·브라우저·앱이 바뀌거나 세션이 만료되면 다시 인증할 수 있으며, 모든 환경에서 무조건 자동 로그인된다고 약속하지 않는다.

사이트의 게임 소개 열람과 게임 실행은 계속 구분한다. 기존 ‘START를 누르기 전에 게임이나 게임 자원을 불러오지 않는다’는 원칙을 유지한다. 로그인 화면의 구체적인 외형·위치·버튼 배치는 별도 화면 기획에서 정한다.

## 5. 공통 인증의 경계

공통 계정을 사용해도 각 게임 서버는 로그인 결과와 해당 게임에 대한 접근 권한을 확인해야 한다. 사이트 버튼을 숨기거나 브라우저에 로그인 표시를 저장하는 것만으로 회원 전용 플레이를 구현하지 않는다.

공통 인증 서비스가 회원을 확인하고, 게임이 자신에게 발급된 인증 결과를 검증한 뒤 게임용 세션을 만드는 구성을 기본안으로 둔다. 웹과 앱을 지원하는 표준 인증 방식인 OpenID Connect 등을 후보로 검토한다. 현재 Better Auth 구성에서 필요한 기능을 어떻게 제공할지는 별도 조사하며 제품·플러그인·요금제는 이 문서에서 확정하지 않는다.

인증 복귀 주소와 대상 게임을 제한하고, 만료·재사용·다른 게임에 대한 인증 결과를 구분한다. 공통 로그인 비밀값이나 비밀번호를 각 게임에 복사하지 않는다. 현재 Fly 커뮤니티 주소와 게임 주소는 출처가 다르므로 기존 쿠키를 그대로 공유하면 된다고 가정하지 않는다.

계정 복구, 전체 기기 로그아웃, 게임별 제재와 공통 계정 제재, 게임 데이터 삭제와 전체 회원 탈퇴의 범위는 따로 정한다. 한 게임의 탈퇴·제재가 다른 게임과 커뮤니티에 어떤 영향을 주는지 사용자에게 명확히 안내할 수 있어야 한다.

## 6. 기존 회원과 게임 진행도 연결

- 기존 커뮤니티 회원의 식별자와 글·댓글 작성자 관계를 보존한다. 공통 회원 식별자가 새로 필요하면 기존 회원과의 대응 관계를 남긴다.
- 이메일 주소가 같다는 이유만으로 커뮤니티 계정과 게임 계정을 자동 연결하지 않는다. 현재 커뮤니티 이메일은 확인되지 않은 상태다.
- 연결 시 공통 회원과 기존 게임 계정 양쪽의 소유권을 확인한다. 게임별로 허용할 기존 로그인·복구·기기 기반 확인 수단은 구현 전에 정한다.
- 이미 다른 회원에게 연결된 게임 계정은 연결을 거절하고 충돌 안내를 제공한다. 기존 연결을 조용히 교체하지 않는다.
- 카드·재화·진행도·랭크·구매 내역은 기존 게임 계정에 유지한다. 연결 성공을 이유로 초기화하거나 중복 지급하지 않는다.
- 연결 전후의 대응 관계를 검증하고 실패 시 기존 게임 계정으로 복귀할 수 있는 전환 절차를 마련한다. 기존 계정 기록을 먼저 삭제하지 않는다.

이메일 인증·비밀번호 재설정 메일의 도입, 기존 소셜 로그인 수단의 승계, 공급자별 서비스 등록 변경 여부는 공통 계정 전환 준비 항목이다. 기존 커뮤니티 계정만으로 복구와 소셜 로그인이 이미 완성됐다고 보지 않는다.

## 7. 대회와 경품의 후속 연계

앞선 대화에서는 한국시간 매일 밤 10시 토너먼트, 참가 인원에 맞춘 대진표, 순위 보상, 우승자 커피 쿠폰을 아이디어로 논의했다. 공통 계정에서는 게임별 대회 신청·우승 기록·경품 수령 내역을 한 회원에게 연결해 사이트에서 모아 볼 수 있다.

대회 개최 여부, 참가 최소·최대 인원, 진행 방식, 보상 종류·금액·지급 조건·예산은 아직 확정하지 않았다. 공통 계정 반영으로 대회를 개설하거나 쿠폰을 구매·발송하지 않는다. 공통 계정 한 개가 실제 사람 한 명을 보장하지 않으므로 중복 출전·수령 방지 정책도 대회 기획에서 별도로 정한다.

## 8. 구현 전에 정할 항목

1. 기존 커뮤니티 회원을 공통 회원으로 확장하는 방법과 게임별 기존 계정 연결 규칙.
2. 공통 인증 서비스의 주소·운영 위치, 웹·앱 복귀 방식, 게임별 세션과 공통 로그아웃 처리.
3. 이메일 인증·복구 메일과 소셜 로그인 제공 범위, 기존 로그인 수단의 승계 절차.
4. 회원 필수 플레이의 적용 시점과 기존 게스트·기존 가입자의 전환 안내.
5. 공통 닉네임과 게임별 닉네임의 관계, 게임별 제재·탈퇴와 전체 계정 제재·탈퇴의 범위.
6. 인증 서버 장애·만료 때의 신규 진입과 진행 중 경기 처리.

구현 검수에서는 사이트·게임 직접 진입·모바일 앱에서 가입과 복귀가 되는지, 같은 회원이 두 게임의 올바른 프로필을 불러오는지, 기존 진행도와 구매 내역이 보존되는지 확인한다. 다른 계정의 프로필 접근, 잘못된 게임용 인증 결과, 연결 충돌, 로그아웃·만료 뒤의 재접속도 확인한다. 이 목록은 향후 검수 기준이며 현재 통과 기록이 아니다.
