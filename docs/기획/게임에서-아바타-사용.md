# 게임에서 아바타 사용하기

공방에서 옷과 직업을 고른 뒤 **게임 파일 만들기**를 누른다. **게임 파일 받기 (ZIP)**가 나타나면 파일을 내려받아 압축을 푼다. 보드게임과 RPG에 필요한 그림을 모두 담고 있어, 이후에는 공방 접속 없이 쓸 수 있다. 외형을 수정했다면 파일을 다시 만든다.

| 파일 | 게임에서 쓰는 곳 |
| --- | --- |
| `portrait.png` | 카드와 인물 소개에 넣는 정면 얼굴. 배경이 투명한 512 × 512 PNG |
| `pawn.png` | 보드의 칸 위에 올리는 정면 전신 말. 배경이 투명한 512 × 512 PNG |
| `sprites.png` | 192 × 192픽셀 칸 24개를 이어 붙인 1152 × 768 투명 PNG |
| `atlas.json` | 스프라이트의 방향, 동작, 재생 간격과 각 칸의 픽셀 좌표 |
| `avatar.json` | 아바타 공개 ID, 저장 리비전, 얼굴 원형을 포함한 외형과 직업을 담은 버전 2 스냅샷 |

## 보드게임

카드 편집기에서 초상을 이미지로 불러와 카드 안의 인물 영역에 맞춘다. 말은 PNG 한 장을 게임의 말 이미지로 등록하고 보드의 한 칸에 맞게 정사각형 비율로 줄인다. 종이에 인쇄할 때는 원하는 실물 크기를 정해 투명한 영역에 카드나 말 받침의 바탕색이 보이도록 배치한다.

## RPG

게임의 자산 폴더에 `sprites.png`와 `atlas.json`을 함께 넣는다. 자동 격자 자르기를 지원하는 엔진에서는 칸 크기를 192 × 192픽셀, 가장자리 여백과 칸 사이 간격을 0으로 지정한다. 위에서부터 정면(아래), 왼쪽, 오른쪽, 뒷모습(위) 순서다. 각 행의 왼쪽 두 칸은 대기, 이어지는 네 칸은 걷기다.

| 동작 | 칸 번호 (왼쪽부터 1번) | 한 프레임 | 한 바퀴 |
| --- | --- | --- | --- |
| 대기 `idle` | 1, 2 | 500ms | 1초 |
| 걷기 `walk` | 3, 4, 5, 6 | 125ms | 0.5초 |

위치가 멈추면 마지막 진행 방향의 대기를, 이동 중이면 해당 방향의 걷기를 반복한다. 예를 들어 오른쪽으로 이동할 때는 셋째 행의 3~6번 칸을 초당 8장으로 돌린다.

엔진에서 JSON을 읽을 수 있으면 `animations`에서 `direction`과 `motion`이 일치하는 항목을 찾는다. `down`은 정면, `up`은 뒷모습이다. 좌표 원점은 이미지의 왼쪽 위이며 오른쪽으로 x, 아래로 y가 증가한다. 아래 예제에서 `sheet`는 이미 읽은 PNG, `elapsedMs`는 동작 시작 후 경과한 밀리초다.

```js
const clip = atlas.animations.find(item => item.direction === 'right' && item.motion === 'walk');
const index = Math.floor(elapsedMs / clip.frameMs) % clip.frames.length;
const { x, y, w, h } = clip.frames[index];
context.drawImage(sheet, x, y, w, h, playerX - 48, playerY - 96, 96, 96);
```

## 웹게임에서 같은 렌더러 사용하기

웹게임에 `assets/avatar/renderer.js`와 해당 렌더러가 사용하는 모듈·자산을 함께 제공하면 스냅샷의 인물을 직접 그릴 수 있다. 컨테이너의 너비와 높이를 먼저 정한다. 보드에서는 `mode: 'board'`, RPG에서는 `mode: 'rpg'`를 쓴다.

```js
import { createAvatarView } from '/assets/avatar/renderer.js';
import { gameSnapshot } from '/assets/avatar/gamekit.js';

// snapshot은 avatar.json을 읽은 객체다. 1판의 얼굴 원형도 편집 전에 확정한다.
const { character } = gameSnapshot(snapshot);
const view = createAvatarView(container, character, { mode: 'rpg' });
view.setMotion('walk');
// 게임 화면에서 나갈 때 해제한다.
view.dispose();
```

`avatar.json` 버전 2는 `character.appearance.faceBase`에 미소년은 `"youth"`, 미소녀는 `"maiden"`을 기록한다. 게임에서 머리나 얼굴 비율을 편집할 때 이 필드를 보존한다. 기존 버전 1 팩을 여는 게임은 위 예제처럼 `gameSnapshot`을 한 번 호출해 원형을 채운 뒤 그 결과를 편집·렌더링에 사용한다. 두 버전 모두 `atlas.json` 버전은 1이며, 기존 팩의 PNG와 좌표표는 그대로 재생할 수 있다.

`id`는 서버에서 받은 아바타의 공개 식별 문자열이다. 저장 전에는 `id`가 `null`, `revision`은 0이다. 파일은 만들기 버튼을 누른 시점의 외형을 담으며, `revision`은 당시 공방이 알고 있던 서버 저장 리비전이다. `character.appearance`는 원형, 얼굴·체형 수치 여섯 개, 머리 모양, 피부·머리·눈·옷 색을 담고 `character.job`은 직업을 담는다. 캐릭터 이름과 회원·인증 정보, 추천 응답은 파일에서 제외한다.

## 공방 연결과 검증

공방은 컨테이너에 `mountAvatarExport(container, getAvatar)`를 한 번 호출한다. `getAvatar()`는 현재 편집 중인 `{ id, revision, character }`를 반환한다. 공방을 닫거나 화면을 다시 구성할 때 반환 객체의 `dispose()`를 호출하면 다운로드 주소와 이벤트가 해제된다.

`node --test test/avatar-gamekit.test.js`로 필드 선별을 검사한다. Python의 Playwright와 Pillow, Chrome을 사용할 수 있는 환경에서 `python3 test/avatar-gamekit-browser.py`를 실행하면 실제 렌더러로 두 외형의 ZIP을 내려받아 PNG를 열고 프레임별 투명도와 방향·포즈 차이, 모바일 너비와 다운로드 수명을 확인한다. `--fixture` 옵션은 렌더러를 계약 대역으로 교체해 빈 프레임 실패와 생성 중 화면 해제도 재현한다.
