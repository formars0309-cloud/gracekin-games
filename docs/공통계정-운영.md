# 공통 계정 운영

이 구현은 사이트와 커뮤니티의 기존 Better Auth 계정을 공통 회원 기반으로 확장한다. 게임 두 개의 서버 저장·로그인 연동은 아직 연결하지 않는다. 게스트 게임 체험은 회원가입을 전제로 하지 않는다. 2026-10-16 사용자 요청에 따라 공통 계정 서버를 `https://community.gracekingames.com`에 공개 배포했다. 운영 메일은 미연결 상태이며 신규 가입·이메일 인증·비밀번호 복구·보호자 동의 신청은 준비 중이다. 기존 계정 로그인과 공개 글 읽기는 유지한다. 실제 메일 연결과 발송 시험은 후속 운영 작업이다.

## 회원과 기존 데이터

- 기존 `user.id`, 글·댓글·세션을 유지한다. 추가한 `user.ageBand`가 없는 기존 회원은 응답에서 `legacy`로 표시하고 기존 로그인을 허용한다. 미확인 이메일을 확인 완료로 바꾸지 않는다.
- 만 14세 이상 신규 회원은 `14plus`, 만 14세 미만 어린이는 `under14`로 기록한다. 생년월일·주민등록번호는 수집하지 않는다. 연령 구분은 자기신고이며 본인인증이 아니다.
- 신규 회원은 이메일 확인을 마쳐야 로그인할 수 있다. 확인은 세션 생성 직전에 검사하므로 비밀번호를 모르는 요청으로 회원 상태를 알아낼 수 없다.
- 어린이는 보호자 동의 승인 후 가입할 수 있다. 현재 커뮤니티 읽기만 가능하며 글·댓글 생성·수정·삭제는 서버가 거부한다. 어린이 결제·대회 참여를 허용하는 구현은 없다.
- 동의 철회 후 어린이의 기존 세션과 신규 로그인을 차단한다. 이메일 확인 또는 비밀번호 복구만으로 이 제한을 풀 수 없다.

## 메일 설정과 기능 활성화 전 준비

`.env.example`의 `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`을 운영 발신 서비스 값으로 지정한다. 포트 465는 TLS, 587은 필수 STARTTLS이며 인증서 검증을 끌 수 없다. 접속·인사 응답은 10초, 소켓은 15초 타임아웃을 사용한다. `GUARDIAN_REPLY_TO`는 보호자가 실제 회신할 수 있고 운영자가 확인하는 수신함이다.

설정이 없으면 신규 가입·인증메일·비밀번호 복구는 준비 중 오류를 반환하고 기존 로그인은 계속 제공한다. 설정 유무는 실제 전달 성공을 보증하지 않는다. 전송 실패는 `EMAIL_DELIVERY_FAILED`로 알린다. 가입 정보가 생성된 뒤 발송이 실패했다면 계정을 다시 만들기보다 이메일 확인 메일을 재요청한다. 비밀번호·메일 링크·SMTP 오류 원문을 로그에 남기지 않는다.

신규 가입·메일·보호자 동의 기능 활성화 전 발신 도메인 인증, 수신함 확인, 실제 SMTP 업체·처리국가·수탁 업무가 반영된 개인정보 처리방침, 보호자 회신을 검토할 담당자를 준비해야 한다. 현재 동의문에는 Fly.io 일본 도쿄 보관을 안내하지만 SMTP 업체는 운영 설정이 정해져야 구체화할 수 있다. 업체를 정하면 `server/guardian.js`의 동의문과 개인정보 처리방침을 함께 갱신하고 동의 버전도 바꾼다. 이번 공개 배포에서도 실제 SMTP 접속·외부 메일 전송은 실행하지 않았다.

## 보호자 회신 검토

아래 절차는 운영 메일과 회신 수신함을 연결하고 담당자를 준비한 뒤 적용한다. 현재 공개 서버에서는 보호자 동의 신청을 받지 않는다.

1. 어린이 정보를 받기 전에 보호자 이름·이메일만 신청받는다. 서버는 7일 유효한 비밀값을 HttpOnly·SameSite=Strict 쿠키에 넣고 해시만 보관한다. 운영 환경은 Secure 쿠키를 쓴다.
2. 신청 번호와 동의문을 보호자에게 보낸다. 목적·항목·보유 기간·국외 보관·거부 영향·법정대리인이라는 명시적 진술과 동의 회신 문구를 안내한다. 이메일의 도착이나 링크 클릭만으로 승인하지 않는다.
3. 운영자는 실제 수신한 회신의 발신자, 신청 번호, 동의 내용과 법정대리인 진술을 확인한다. 이름·이메일 불일치, 진술 불명확, 전달받은 메일 등 확인이 어려운 경우 승인하지 않고 회신으로 보완한다. CLI의 발신자 헤더 일치는 보조 검사이며 신원이나 법정대리인 지위를 자동 인증하지 않는다.
4. 검토한 회신 원문을 `.eml`로 내보내 로컬 운영 CLI에 전달한다. 최대 2MB의 원문을 MailParser로 해석해 MIME로 인코딩된 단일 발신자·제목·텍스트의 신청 번호를 검사한다. 첨부파일은 열지 않고 HTML을 화면에 표시하거나 실행하지 않는다. 원문과 SHA-256 해시를 비공개 데이터 폴더에 보관한다. 검토 완료 플래그 세 개는 운영자가 직접 검토했다는 기록이다.
5. 승인 후 신청한 브라우저에서 어린이 닉네임·이메일·비밀번호를 입력한다. 계정 생성과 동의 1회 소모는 SQLite 트리거의 같은 INSERT에서 처리한다. 경쟁 요청, 승인 뒤 철회·만료, 프로세스 재시작으로 같은 동의를 두 계정에 사용할 수 없다. 비밀번호 검증 등 회원 생성 전 실패는 승인을 소비하지 않는다.

공개 관리·승인 API는 제공하지 않는다. 다음 명령은 해당 데이터 폴더에 접근할 권한이 있는 운영자가 실행한다. 비밀키·비밀번호·회신 본문을 명령 인자로 넣지 않는다.

```sh
DATA_DIR=/data node scripts/guardian-review.mjs list
DATA_DIR=/data node scripts/guardian-review.mjs approve 신청번호 --evidence /비공개경로/회신.eml --confirm-reply --confirm-guardian --confirm-scope
DATA_DIR=/data node scripts/guardian-review.mjs reject 신청번호
DATA_DIR=/data node scripts/guardian-review.mjs withdraw 신청번호
DATA_DIR=/data node scripts/guardian-review.mjs delete-child 신청번호 --confirm-parent-request --confirm-deletion
DATA_DIR=/data node scripts/guardian-review.mjs cleanup
```

목록은 보호자 이메일을 마스킹한다. 승인 원문은 `DATA_DIR/guardian-evidence/` 아래 폴더 0700·파일 0600으로 복사한다. 검토용으로 내보낸 원본 `.eml`은 작업 후 같은 개인정보 보존 원칙에 따라 운영자가 정리한다. 실제 개인정보 삭제 명령은 보호자의 요청과 대상을 확인한 경우에만 실행한다. `delete-child`는 연결된 어린이 계정·세션·인증정보와 동의 증거를 삭제하므로 사전 보존 의무 여부를 확인한다. 성인 계정은 이 명령의 대상이 아니다.

미가입 신청은 7일 만료 후 이름·이메일과 승인 원문을 정리한다. 미가입 철회 신청도 정리하며, 회원 삭제로 연결이 끊긴 동의 자료도 정리한다. 서버 시작과 1시간 주기, 수동 `cleanup` 명령에서 실행한다. 원문 복사 직후 프로세스가 중단되어 DB에 기록되지 않은 UUID 이름의 `.eml`은 24시간 유예 후 정리하며 정상 참조 파일·다른 파일·심볼릭 링크는 보존한다. 서버가 꺼져 있으면 다음 시작 때 실행한다. 가입한 어린이의 철회는 우선 이용을 차단하고, 확인된 삭제 요청을 `delete-child`로 처리하면 개인정보 보관을 끝낸다. 이 작업은 DB 및 증거 폴더의 현재 사본에 적용되며 운영 백업은 정해진 보관 기한에 따라 별도로 만료시켜야 한다.

서버는 같은 DB에 한 인스턴스로 실행한다. 시작 시 회원 생성 전에 중단된 예약을 복구한다. 동의가 소모된 회원은 다시 승인 상태로 열리지 않는다. 기존 회원을 삭제하거나 테스트 데이터로 초기화하는 마이그레이션은 없다.

## HTTP 계약

운영 계정 출처는 `BETTER_AUTH_URL=https://community.gracekingames.com`으로 설정한다. 메일 링크와 콜백은 이 설정에서 얻은 출처를 사용한다. Pages의 `/account/` 진입도 새 출처로 이동하며, 계정 화면의 대문·게임 복귀 링크는 `https://gracekingames.com`을 사용한다.

모든 변경 요청은 같은 Origin·JSON이 필요하다. Host 검증과 IP 속도 제한을 적용한다. 인증·계정 JSON은 `no-store`, 응답은 `no-referrer`다. 본문 `callbackURL`·`redirectTo`는 서버의 `/account/` 주소로 고정한다. 임의 외부 URL로 토큰을 전달하지 않는다.

| 요청 | 입력 | 성공 응답 |
| --- | --- | --- |
| `GET /api/account/config` | 없음 | `emailAvailable`, `registrationAvailable`, `guardianConsentAvailable`, `guardianConsentMethod` |
| `GET /api/account/session` | 로그인 쿠키 | `user:null` 또는 `id,name,email,emailVerified,ageBand,canWriteCommunity` |
| `POST /api/auth/sign-up/email` | `name,email,password,ageBand` | `{status:true}`, 세션 없음 |
| `POST /api/auth/sign-in/email` | `email,password` | Better Auth 로그인 응답과 HttpOnly 세션 쿠키 |
| `POST /api/auth/sign-out` | `{}` | Better Auth 로그아웃 응답 |
| `POST /api/auth/send-verification-email` | `email` | `{status:true}`, 계정 존재 여부를 밝히지 않음 |
| `POST /api/account/verify-email` | `token` | `{status:true}` |
| `POST /api/auth/request-password-reset` | `email` | `{status:true}`, 계정 존재 여부를 밝히지 않음 |
| `POST /api/auth/reset-password` | `token,newPassword` | `{status:true}`, 모든 기존 세션 철회 |
| `POST /api/account/guardian-requests` | `guardianName,guardianEmail` | `{status:true}`, 신청 쿠키 발급 |
| `GET /api/account/guardian-request` | 신청 쿠키 | `request:null` 또는 `status,expiresAt,requestNumber` |
| `POST /api/account/guardian-request/cancel` | `{}`와 신청 쿠키 | `{status:true}`, 가입 전 대기·승인 신청 취소, 진행·사용된 신청은 거부 |

보호자 상태는 `pending`, `approved`, `rejected`, `expired`, `used`, `withdrawn`이다. 내부 `creating` 예약은 화면에서 `approved`로 표시하지만 중복 회원 생성은 서버에서 막는다. 개인정보·비밀 capability는 상태 응답에 포함하지 않는다. 어린이 가입은 `ageBand:'under14'`와 승인된 신청 쿠키가 함께 필요하다. 구형 `ageConfirmed:true`, `emailVerified`, 임의 동의 ID 등으로 가입 조건을 우회할 수 없다. 보호자 신청이 진행 중인 브라우저는 성인 구분으로 우회할 수 없다. 쿠키를 지우고 연령을 허위 신고하는 행위까지 본인인증으로 막는 구조는 아니다.

이메일 확인 링크는 `https://community.gracekingames.com/account/?view=verify#token=...`, 복구 링크는 `https://community.gracekingames.com/account/?view=reset#token=...`이다. 옛 Host의 `/account/` GET·HEAD 요청도 경로·쿼리를 보존해 새 출처로 301 이동하며 계정 API는 403으로 거부한다. URL 해시는 HTTP 요청에 포함되지 않아 서버가 다루지 않으며, 해시가 없는 Location으로 301 이동하면 브라우저가 기존 `#token=...`을 유지한다. 화면에서 해시를 즉시 지우고 사용자 확인 버튼으로 POST한다. GET만 하는 메일 스캐너는 토큰을 소비하지 않는다. 확인 토큰은 256비트 무작위값의 SHA-256 해시만 DB에 저장하며 1시간·1회 유효하고 재발송하면 앞선 링크를 폐기한다. 복구 토큰도 Better Auth의 해시 저장과 트랜잭션 내 1회 소비를 사용하며 1시간 유효하다.

## 로컬 검증용 메일 주입

자동 테스트는 `startServer({port:0,dataDir:임시폴더,mailer:async message=>mailbox.push(message),guardianReplyTo:'support@example.test'})`로 외부 전송을 대체한다. `message`는 `{to,subject,text}`이고 보호자 동의 메일에는 `replyTo`가 추가된다. 확인·복구 링크는 `text`의 URL 해시에만 있다. 캡처 객체와 토큰을 로그·공개 파일·저장소에 출력하지 않는다. 테스트 주소는 `example.test`만 사용한다. 파일 메일함이나 공개 테스트 메일 조회 API는 없다.

`npm test`는 기존 커뮤니티·프록시 검증과 신규 계정·동의 HTTP 통합 검증을 함께 수행한다. SMTP 운용과 수신 회신의 실제 진위 검토는 자동 테스트가 대신하지 않는다.

참고: [Better Auth 이메일·비밀번호 문서](https://better-auth.com/docs/authentication/email-password), [Nodemailer SMTP 문서](https://nodemailer.com/smtp), [MailParser 문서](https://nodemailer.com/extras/mailparser), [개인정보 보호법 제22조의2](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1020398523).

- 격리한 임시 DB와 외부 전송 없는 메일 주입, `example.test` 주소로 로컬 서버를 실행했다. 실제 브라우저에서 일반 가입 → 미인증 로그인 거부 → 이메일 확인 → 로그인 → 게시글 작성, 비밀번호 복구 → 기존 세션 철회 → 새 비밀번호 로그인을 확인했다.
- 보호자 신청 → MIME 회신 원문 CLI 승인 → 어린이 가입·이메일 확인·로그인 → 읽기 전용 화면 및 직접 쓰기 요청 403 → 동의 철회 후 기존 세션·신규 로그인 차단을 확인했다. 동일 탭의 인증·복구 해시 링크 처리 결함은 수정 후 두 흐름을 재검수했고 브라우저 자바스크립트 오류는 없었다.
- 1440×1000·360×800 화면을 확인했으며 360px 화면에서 가로 넘침이 없었다. axe의 WCAG 2 A·AA 자동 검사에서 위반 0건이었고, 자동 판정이 끝나지 않은 그라데이션 대비는 화면으로 추가 확인했다. 이 결과는 전체 접근성 준수 인증을 뜻하지 않는다.
- 당시 실제 SMTP·외부 회신함 전송, 운영 DB 접근·변경, 운영 배포는 수행하지 않았다. 로컬 Docker 런타임이 없어 이미지 빌드는 검증하지 못했다. 이후 공개 배포에서 원격 컨테이너 빌드와 운영 데이터 보존을 별도로 확인했다. 두 게임의 실제 공통 로그인 연결은 후속 범위다.

## 2026-10-16 공개 배포 검증

- 배포 전 자동 검사: 서버 테스트 45개, 보안 검사 8개, 정적 검사 6페이지·1,620항목 통과.
- Fly 원격 Docker 빌드·기동·상태 확인과 Pages 공개 빌드를 완료했다. 기존 Machine·1GB 볼륨을 유지했으며, SQLite 온라인 백업과 로컬 복구 사본의 마이그레이션 시험 후 운영에 반영했다. 기존 6개 테이블의 기존 열 데이터 해시가 전후 동일하고 추가 계정 테이블 3개와 DB 무결성 정상 응답을 확인했다.
- 공개 계정 화면·자산, 양 게임 공개 게시판, 새 출처·이전 주소 호환을 확인했다. 현재 설정의 메일·가입·보호자 동의 가능 값은 모두 `false`이며 신규 가입·비밀번호 복구·보호자 신청은 503 준비 중 응답이다.
- 실제 브라우저에서 대표 사이트 로그인과 게임별 커뮤니티 로그인이 공통 계정 화면으로 이동하고, 경국지계 구분·게임 홈페이지 복귀 링크가 유지되는지 확인했다. 가입 버튼 비활성·보호자 신청 폼 숨김·준비 중 안내, 360px 가로 넘침 없음, 자바스크립트 오류 0건을 확인했다.
- 실제 SMTP·회신함 전송과 운영 신규 가입·보호자 승인은 시험하지 않았다. 기존 운영 계정이 없어 운영 로그인도 실행하지 않았으며 해당 흐름은 로컬 자동·브라우저 검수 결과에 따른다. 운영 테스트 회원을 생성하지 않았다. 이미지와 공개 자산 대조 결과는 [배포 기록](커뮤니티-배포.md)에 적었다.
