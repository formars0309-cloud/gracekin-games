# 공통 계정 운영

이 구현은 사이트와 커뮤니티의 기존 Better Auth 계정을 공통 회원 기반으로 확장한다. 게임 두 개의 서버 저장·로그인 연동은 아직 연결하지 않는다. 게스트 게임 체험은 회원가입을 전제로 하지 않는다. 2026-10-16 공통 계정 서버와 일반 메일에 이어 보호자 회신 자동 동의를 공개했다. 실제 수신·서명 검증과 실메일 자료를 사용한 격리 DB 자동 승인·보류·어린이 가입 시험을 완료했고, 운영 설정과 모바일 신청 화면도 확인했다. 기존 계정 로그인과 공개 글 읽기는 유지한다. 운영 DB에 시험 회원·보호자 신청을 만들지 않았다. 격리 시험 계정·신청·이벤트·증빙은 삭제해 잔여 0건을 확인했으며 공급자·Gmail에 남은 시험 메일은 별도 정리 대상이다.

## 회원과 기존 데이터

- 기존 `user.id`, 글·댓글·세션을 유지한다. 추가한 `user.ageBand`가 없는 기존 회원은 응답에서 `legacy`로 표시하고 기존 로그인을 허용한다. 미확인 이메일을 확인 완료로 바꾸지 않는다.
- 만 14세 이상 신규 회원은 `14plus`, 만 14세 미만 어린이는 `under14`로 기록한다. 생년월일·주민등록번호는 수집하지 않는다. 연령 구분은 자기신고이며 본인인증이 아니다.
- 신규 회원은 이메일 확인을 마쳐야 로그인할 수 있다. 확인은 세션 생성 직전에 검사하므로 비밀번호를 모르는 요청으로 회원 상태를 알아낼 수 없다.
- 어린이는 보호자 동의 승인 후 가입할 수 있다. 현재 커뮤니티 읽기만 가능하며 글·댓글 생성·수정·삭제는 서버가 거부한다. 어린이 결제·대회 참여를 허용하는 구현은 없다.
- 동의 철회 후 어린이의 기존 세션과 신규 로그인을 차단한다. 이메일 확인 또는 비밀번호 복구만으로 이 제한을 풀 수 없다.

## 그레인 신규 가입 보상 (2026-10-16 공개)

신규 공통 계정의 이메일 확인 완료 시 `signup-email-verified-v1` 이벤트로 30,000 그레인을 계정당 한 번 지급한다. 2026-10-16 사용자의 요청으로 공개 배포했다. 기존 회원과 기존 미확인 회원을 소급 지급하지 않으며, 조회·로그인·서버 재시작 시 자격을 추가하지 않는다. 이벤트 종료일은 아직 없고, 종료 시에는 자격 부여 중단과 인증 대기 계정의 처리 방침을 먼저 정한다.

- 신규 가입 요청의 서버 생성 회원 ID를 `grain_signup_reservations`에 임시 예약한다. 사용자 INSERT 트리거가 같은 문장 안에서 `grain_event_eligibility`에 자격을 남기므로 기존 DB의 회원에는 자격이 생기지 않는다. 실패·완료된 요청의 예약은 정리하고, 회원 생성 이전에 종료된 예약은 서버 시작 때 정리한다.
- `grain_wallets`는 회원별 잔액, `grain_ledger`는 증감 원장이다. 이벤트 자격과 원장 모두 `(userId,eventId)` 고유 제약을 둔다. 이메일 토큰 소비·확인 상태·원장 INSERT·잔액 갱신을 하나의 `BEGIN IMMEDIATE` 트랜잭션으로 수행한다. 지급 실패 시 토큰도 롤백되어 같은 링크로 재시도한다.
- `GET /api/account/grain`은 세션의 활성 계정에서만 회원 ID를 얻어 `{ balance, entries }`를 반환한다. 추가 쿼리와 쓰기 메서드는 거부하고 읽기는 DB를 변경하지 않는다. 각 내역에는 금액·사유·시각을 반환하며 메일·토큰·다른 회원 정보를 포함하지 않는다. 가입 보상의 양수 지급뿐 아니라 레이스 티켓 차감·감액과 취소 반환·당첨 정산도 같은 공용 원장에 기록하므로, 계정 화면의 ‘이용 내역’ 목록에는 실제 증감 내역이 함께 표시된다. 응답은 `no-store`다.
- 어린이는 현재 보호자 동의가 유효할 때만 인증·지급·조회할 수 있다. 동의 철회 후 기존 잔액을 자동 회수하거나 새로 지급하지 않는다. 회원 삭제 시 자격·지갑·원장은 회원 외래키의 `ON DELETE CASCADE`로 함께 삭제한다.
- 계정 화면은 서버 잔액이 로딩 중이거나 조회에 실패하면 0으로 표시하지 않는다. 실패 안내와 다시 불러오기 버튼을 제공하며 로그아웃·페이지 이탈 시 기존 그레인 표시를 비운다. 외부 추적 스크립트를 추가하지 않는다.

보호자 동의문 v4에는 그레인 처리 목적·항목과 계정 삭제 시 함께 삭제하는 내용을 추가했다. 이미 신청에 저장된 동의문·버전은 바꾸지 않는다. 자동 회신 확인은 최신 동의문만 승인하므로, 아직 승인되지 않은 v3 신청의 회신은 구버전으로 보류한다. 해당 보호자는 기존 신청을 취소한 뒤 새 동의 안내를 받아 다시 신청할 수 있다. 이미 승인되거나 가입에 사용된 신청의 상태를 변경하지 않는다.

`node --test test/grain.test.js`로 인증 전 미지급, 최초·동시·중복 확인, 토큰 만료·재발송, 지급 실패 롤백, 기존 회원 제외, 본인 조회·변조 거부·로그아웃, 재시작 영속, 어린이 동의 철회·삭제, 메일 발송 실패 후 재시도를 격리 DB에서 검증한다. 전체 검증은 `npm test`, `python3 scripts/verify_site.py`, `git diff --check`로 실행한다. 2026-10-17 슬라임 레이스는 기존 공용 지갑·원장의 무료 그레인 사용·반환·정산을 구현한다. 일반 운영자 지급은 추가하지 않았다. 현금 구매·충전·환전, 상품·쿠폰·유료 아이템 교환, 회원 간 양도·송금과 유료 재화 전환은 무료 전용 정책에 따라 제공하지 않는다. 레이스의 성인 확인 잠금은 유지하며 공개 반영 여부는 [레이스 검증 기록](슬라임-레이스-검증.md)에서 구분한다.

## 사이트 상단 계정 표시 (2026-10-16 공개)

대문·게임 소개 두 곳·커뮤니티의 공통 헤더는 `GET /api/account/summary`로 `{ user: null }` 또는 `{ user: { name, grainBalance } }`만 받는다. 세션과 활성 보호자 동의를 서버에서 확인하며 이메일·회원 식별자·인증값·이벤트 내역은 표시 API에 넣지 않는다. 자격·지갑·원장을 만들거나 갱신하지 않으며 표시 조회만으로 유효 세션을 연장하지 않는다(`disableRefresh: true`). 만료 세션은 라이브러리의 기존 정리를 거쳐 익명으로 표시한다. 새로 수집하거나 저장하는 개인정보는 없으며 기존 닉네임·잔액을 본인 화면에 표시한다. 2026-10-16 사용자의 요청으로 Fly·GitHub Pages에 공개했다.

- Pages의 정확한 `https://gracekingames.com`, `https://www.gracekingames.com`에서만 고정된 `https://community.gracekingames.com/api/account/summary`로 `credentials: include` 요청을 보낸다. 같은 인증 출처와 로컬 서버는 상대 경로·`same-origin`을 사용한다. 표시 GET에 불필요한 `Content-Type` 등의 헤더를 붙이지 않는다.
- 서버는 해당 GET에만 정확한 요청 Origin과 `Access-Control-Allow-Credentials: true`, `Vary: Origin`, `Cache-Control: no-store`를 제공한다. 허용 출처의 처리 실패·속도 제한 응답도 같은 경계를 적용한다. `null`·HTTP·다른 포트·임의 하위 도메인·유사 접미사·다른 외부 출처, 쓰기 메서드와 OPTIONS는 거부한다. 대문에서 별도 preflight가 필요한 표시 요청은 제공하지 않는다.
- 다른 계정·인증·커뮤니티 API에는 CORS를 추가하지 않는다. 쓰기 Origin 보호와 기존 Host 검사를 유지한다. host-only HttpOnly 쿠키와 기존 SameSite·Secure 정책을 유지하며 쿠키 Domain 확장·토큰 복사·브라우저 저장소·iframe 중계는 사용하지 않는다.
- 상태 확인 중이거나 실패하면 숫자를 비우고 계정 링크와 다시 확인 버튼을 제공한다. 페이지 이탈·숨김·포커스 해제·같은 탭 커뮤니티 로그아웃 시작 시 개인 표시를 즉시 비우고 요청을 취소한다. 페이지 복원·표시·포커스 복귀와 로그아웃 완료 시 재조회하며 이전 요청이 늦게 돌아와도 다시 표시하지 않는다. 짧은 간격의 반복 조회는 하지 않는다.
- `assets/shared/account-header.js`만 고정 summary URL 요청을 정적 검사에서 예외 허용한다. 다른 파일·다른 URL·다른 요약 경로의 예외를 넓히지 않는다. 서버와 공통 자산은 `.dockerignore`의 명시 허용 목록에 포함한다.

`test/account-summary.test.js`는 익명·로그인·동의 철회·로그아웃·읽기 무변경·민감필드 미포함·정확한 CORS 허용과 거부·오류 응답을 검증한다. `test/account-header.test.js`는 비동기 이전 응답 무시, 페이지·세션 전환, 오류 시 0 미표시, 고정 출처와 계정 링크 문맥을 검증한다. 전체 시험과 정적 검사 외에 `python3 tests/security-review/test_verify_site.py`로 정적 요청 예외의 경계를 검증한다.

## 네이버·구글 로그인과 게임용 OIDC 제공자 (2026-10-16 구현, 미배포)

TCG `docs/기획/34-공통계정-통일-기획.md` 결정 2·5·6·7·8·13과 작업 지시서 `공통-34-공통계정.md` 1·2절을 구현했다. 브랜치 `formars0309-cloud/acct-social`에만 있고 운영에는 배포하지 않았다. 공급자 콘솔 등록·키 발급·`fly secrets` 설정은 사용자 몫이며 하지 않았다. 새 기능은 `server/social.js`·`server/oidc.js`에 두고 `server/app.js`에는 설정 연결과 경로 분기만 더했다.

### 공급자 설정

| 환경 변수 | 설명 |
| --- | --- |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | 둘 다 있을 때만 구글 로그인을 켠다. 콜백 `https://community.gracekingames.com/api/auth/callback/google` |
| `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET` | 둘 다 있을 때만 네이버 로그인을 켠다. 콜백 `https://community.gracekingames.com/api/auth/callback/naver`. 검수 전에는 키를 넣지 않아 버튼을 숨긴다 |

- Better Auth 1.7.10 내장 `google`·`naver`를 쓴다. 구글은 `openid email profile`, 네이버는 기본 `profile email` 범위를 요청한다. 구글은 계정 선택 화면(`prompt=select_account`)을 띄운다.
- `/api/account/config`에 `socialProviders`(켜진 공급자 목록)와 `socialSignupAvailable`(공급자와 메일 발송이 모두 있을 때 `true`)을 더했다. 메일 설정이 없으면 소셜 로그인은 되지만 소셜 가입은 닫는다. 공급자가 확인하지 않은 이메일은 확인 메일이 필요하기 때문이다.
- 공급자 접근·갱신 토큰은 Better Auth `encryptOAuthTokens`로 암호화해 `account`에 저장한다. 공급자의 실명·별명·프로필 사진은 회원정보로 저장하지 않는다(`image`는 비움). 닉네임은 가입 화면에서 입력한 값이다.

### 가입·로그인 흐름(결정 6·7)

1. '회원가입' → 나이 선택 → '만 14세 이상' → 가입 화면에 닉네임을 넣고 '네이버로 가입하기'·'구글로 가입하기'. '만 14세 미만'은 기존 보호자 동의 이메일 가입만 있다.
2. `POST /api/auth/sign-in/social`에 `requestSignUp:true, ageBand:'14plus', name`이 오면 서버가 HMAC 서명한 가입 쿠키(`__Host-gracekin-social-signup`, 개발 환경은 접두사 없음, HttpOnly·SameSite=Lax·10분)를 발급한다. 콜백은 이 쿠키를 검증한 경우에만 `signupContext`에 `ageBand:'14plus'`와 닉네임을 넣는다. 쿠키가 없거나 변조·만료되면 기존 회원 생성 훅이 `AGE_CONFIRMATION_REQUIRED`로 회원을 만들지 않는다. `under14`는 403 `SOCIAL_SIGNUP_ADULT_ONLY`, 보호자 동의 진행 중인 브라우저는 이메일 가입과 같이 403이다.
3. 공급자 설정은 `disableImplicitSignUp:true`라 '로그인' 버튼(가입 요청 없음)으로 처음 보는 소셜 계정이 오면 회원을 만들지 않고 `error=signup_disabled`로 돌려보낸다. 화면은 회원가입에서 나이를 먼저 고르라고 안내한다.
4. 같은 이메일의 기존 회원이 있으면 `accountLinking.disableImplicitLinking:true`로 자동 연결하지 않고 `error=account_not_linked`로 돌려보낸다. 로그인 수단은 로그인한 회원이 `/account/` '로그인 수단'에서만 연결한다(다른 이메일의 공급자 계정도 본인이 직접 연결하면 허용, `allowDifferentEmails`). 이미 다른 회원에게 붙은 공급자 계정은 `account_already_linked_to_different_user`로 거부한다.
5. 네이버가 이메일을 주지 않으면(제공 미동의) `email_not_found`로 가입하지 않는다. 네이버가 준 이메일은 네이버가 확인한 주소로 보고 `emailVerified`를 켠다. 구글은 `email_verified`를 그대로 쓴다.
6. 공급자가 확인하지 않은 이메일로 가입하면 회원은 만들어지지만 기존 세션 훅이 로그인을 막고(`EMAIL_NOT_VERIFIED`) 기존 확인 메일을 보낸다. 확인을 마치면 소셜 로그인이 된다.
7. 소셜 결과는 `/account/?view=signin&social=<공급자>&error=<코드>`, 가입 성공은 `/account/?joined=<공급자>`, 연결 성공은 `/account/?linked=<공급자>`로 돌아온다. 진입 스크립트는 알려진 오류 코드만 넘기고 나머지는 `unknown_error`로 바꾼다.

### 로그인 수단 관리

| 요청 | 입력 | 결과 |
| --- | --- | --- |
| `GET /api/account/login-methods` | 로그인 쿠키 | `methods:[{provider:'email'|'naver'|'google', linkedAt}]`, `available`, `canUnlink`. 공급자 식별값은 내보내지 않는다 |
| `POST /api/account/login-methods/link` | `provider` | 공급자로 이동할 `url`. 어린이 계정 403 `SOCIAL_LINK_UNAVAILABLE`, 이미 연결 409 |
| `POST /api/account/login-methods/unlink` | `provider`(`email`은 비밀번호 로그인) | 마지막 하나는 400 `LAST_LOGIN_METHOD`. Better Auth의 최근 로그인 조건(1일)을 넘긴 세션은 다시 로그인 안내 |

소셜로만 가입한 회원은 '비밀번호 재설정' 메일로 비밀번호를 정하면 이메일 로그인이 추가된다(Better Auth가 `credential` 계정을 만든다). 공급자 소셜 기능이 꺼져 있으면 '로그인 수단' 칸을 숨겨 기존 내 계정 화면을 그대로 둔다.

### 그레인(결정 8)

소셜 가입도 기존 `signup-email-verified-v1` 자격 예약·트리거를 그대로 쓴다. 콜백이 세션을 만든 회원의 이메일이 확인 상태이면 `BEGIN IMMEDIATE` 안에서 활성 회원을 다시 확인하고 기존 `awardSignup`을 호출한다. 원장 `(userId,eventId)` 고유 제약으로 계정당 한 번이며, 지급 중 오류가 나면 로그인은 막지 않고 다음 소셜 로그인 때 다시 시도한다. 이메일이 확인되지 않은 소셜 가입은 기존 이메일 확인 트랜잭션에서 지급한다. 기존 회원·연결만 한 회원에게는 자격이 생기지 않는다.

### OIDC 제공자(계약 1절)

`@better-auth/oauth-provider` 1.7.10과 Better Auth `jwt` 플러그인을 쓴다.

| 항목 | 값 |
| --- | --- |
| 발견 문서 | `GET <BETTER_AUTH_URL>/.well-known/openid-configuration` (예: `https://community.gracekingames.com/.well-known/openid-configuration`). `issuer`는 `BETTER_AUTH_URL` 출처 그대로 |
| 인가 | `GET /api/auth/oauth2/authorize`, `response_type=code`, `scope=openid`만, PKCE `S256` 필수(`plain` 거부), `state`·`nonce` 그대로 돌려줌, 응답에 `iss` |
| 토큰 | `POST /api/auth/oauth2/token`, `application/x-www-form-urlencoded`, `client_secret_basic`만(`client_secret_post`는 `invalid_client`). 브라우저 출처 검사 대신 클라이언트 인증을 쓰며 IP당 분당 120회 |
| JWKS | `GET /api/auth/jwks`. EdDSA(Ed25519) 공개 키. 개인 키는 `jwks` 테이블에 `BETTER_AUTH_SECRET`로 암호화해 저장한다 |
| ID 토큰 | `iss`, `aud`(=client_id), `sub`(=`user.id`), `exp`, `iat`, `nonce`, `age_band`(`14plus`/`under14`), `auth_time`, `acr`, `at_hash`. 이메일·이름 없음 |
| 수명 | 인가 코드 600초·한 번, ID 토큰·접근 토큰 600초, 갱신 토큰 없음(`grantTypes:['authorization_code']`) |
| 동의 화면 | 없음(등록 클라이언트 `skipConsent`) |
| 복귀 주소 | 등록 주소와 글자 그대로 같아야 한다(루프백 포트 완화 없음). 등록되지 않은 주소·클라이언트의 오류는 게임으로 보내지 않고 `/account/?view=signin&error=...`로 보낸다 |
| 취소 | 계정 화면의 '취소하고 게임으로 돌아가기' → `redirect_uri?error=access_denied&state=...&iss=...` |
| 닫은 경로 | 동적 등록, 관리 API, userinfo·introspect·revoke·end-session, jwt 플러그인의 세션 JWT(`/api/auth/token`)는 게이트에서 열지 않는다(404) |

`OIDC_CLIENTS`는 서버 시작 때 읽는 JSON 배열이다. 항목은 `client_id`(소문자·숫자·하이픈), `client_secret`(공백 없는 32자 이상), `redirect_uris`(1~10개), `name`(계정 화면에 보이는 게임 이름)만 쓴다. 운영(`NODE_ENV=production`)은 HTTPS 복귀 주소만, 그 밖에는 루프백 HTTP도 받는다. 시작 때 `oauthClient` 표에 맞추고(비밀값은 SHA-256 해시만 저장), 목록에서 빠진 클라이언트는 지우지 않고 사용 중지한다. 형식이 틀리면 서버가 시작하지 않고 비밀값 없는 `OIDC_CLIENTS ...` 안내만 출력한다. 아래 값은 형식 예시이며 실제 비밀값이 아니다.

```json
[
  {"client_id":"gyeongguk","client_secret":"<32자 이상 무작위 값>","redirect_uris":["https://gyeongguk.gracekingames.com/auth/gracekin/callback"],"name":"경국지계"},
  {"client_id":"gyeongguk-test","client_secret":"<32자 이상 무작위 값>","redirect_uris":["https://gyeongguk-test.fly.dev/auth/gracekin/callback"],"name":"경국지계(스테이징)"},
  {"client_id":"gyeongguk-dev","client_secret":"<32자 이상 무작위 값>","redirect_uris":["http://127.0.0.1:8787/auth/gracekin/callback"],"name":"경국지계(로컬)"}
]
```

운영 공통 계정에는 `gyeongguk`만, 시험판(결정 15)에는 `gyeongguk-test`만, 로컬에는 `gyeongguk-dev`만 등록한다. 운영 서버는 루프백 주소를 거부하므로 `gyeongguk-dev`를 넣으면 시작하지 않는다. 같은 비밀값을 경국지계 `GRACEKIN_CLIENT_SECRET`에 넣는다.

### 연령 기록 없는 기존 회원(결정 13)

`postLogin` 단계에서 연령 구분이 없으면 코드를 발급하지 않고 서명된 인가 요청을 붙여 `/account/`로 보낸다. 계정 화면은 '게임 연결 · 나이 확인'을 보여 준다.

- '만 14세 이상' → `POST /api/account/oidc/age {ageBand:'14plus'}`가 `account_age_declarations`에 기록하고 `POST /api/auth/oauth2/continue {postLogin:true, oauth_query}`로 같은 인가 요청을 이어 코드를 발급한다. `user.ageBand`는 바꾸지 않으므로 기존 회원의 `legacy` 표시·커뮤니티 쓰기·이메일 확인 상태는 그대로다. 이 선택은 OIDC `age_band`에만 쓴다. 이미 연령이 있는 회원은 409.
- '만 14세 미만' → 기록하지 않고 코드도 발급하지 않는다. 보호자 동의 가입 안내로 보낸다. 게임으로는 '취소하고 게임으로 돌아가기'(`access_denied`)로 돌아간다.
- 어린이(`under14`) 계정은 보호자 동의가 유효할 때만 코드·토큰을 발급한다. 동의 철회 뒤의 토큰 교환은 거부한다.

계정 화면 보조 API: `POST /api/account/oidc/context {oauth_query}`(서명 검사 뒤 게임 이름·로그인 여부·나이 확인 필요 여부), `POST /api/account/oidc/age`, `POST /api/account/oidc/cancel {oauth_query}`. 모두 같은 출처·JSON이 필요하다. 서명이 틀리거나 만료된 요청은 400 `OIDC_REQUEST_EXPIRED`다. 로그인하지 않은 사용자가 인가 요청으로 들어오면 계정 화면 위에 '<게임 이름>에서 그레이스킨게임즈 계정 로그인을 요청했어요' 안내가 나오고, 이메일·네이버·구글 로그인을 마치면 같은 인가 요청으로 돌아가 코드가 발급된다. 이메일 가입은 확인 메일을 거치므로, 같은 탭에서 10분 안에 로그인하면 이어지고 그보다 늦으면 게임에서 다시 시작한다.

### 검증 절차

- 자동 시험: `node --test test/oidc.test.js test/social.test.js`. 실제 키 없이 실행마다 만든 시험값과 가짜 공급자 응답(fetch 대체)을 쓴다. OIDC는 발견 문서 → 인가 → 코드 → `client_secret_basic` 토큰 → JWKS 서명·`iss`·`aud`·`exp`·`nonce` 검증까지 돌고, 코드 재사용·PKCE 위반·다른 클라이언트·미등록 주소·사용 중지·비밀값 교체·기존 회원 연령 선택·어린이 동의 철회를 확인한다.
- 로컬 통합: 공통 계정 서버는 SMTP 없이도 시작한다(새 가입·소셜 가입만 닫히고 기존 로그인은 된다). 경국지계와 함께 확인할 때는 아래처럼 띄운다. `scripts/dev-server.mjs`는 운영 환경·루프백 아닌 주소에서 실행을 거부하고, 실제 메일을 보내지 않으며 가입 확인 메일만 같은 서버에 바로 확인 요청한다(링크·토큰은 출력하지 않음).

  ```sh
  # 비밀값은 셸 변수로만 만들고 저장소·명령 기록에 남기지 않는다.
  SECRET=$(node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))")
  OIDC_CLIENTS="[{\"client_id\":\"gyeongguk-dev\",\"client_secret\":\"$SECRET\",\"redirect_uris\":[\"http://127.0.0.1:8787/auth/gracekin/callback\"],\"name\":\"경국지계(로컬)\"}]" \
    DATA_DIR=.data/local-oidc PORT=8766 node scripts/dev-server.mjs
  # 경국지계: GRACEKIN_DISCOVERY=http://127.0.0.1:8766/.well-known/openid-configuration
  #          GRACEKIN_CLIENT_ID=gyeongguk-dev GRACEKIN_CLIENT_SECRET=$SECRET
  ```

  `http://127.0.0.1:8766/account/`에서 가입하면 바로 로그인할 수 있다. 끝나면 직접 띄운 서버의 PID로 종료한다.
- 배포 전(사용자 승인 뒤): 공급자 콘솔에 콜백을 등록하고 키를 비공개 설정한 다음, 시험판에서 구글·네이버 실제 가입·로그인·연결·해제, 같은 이메일 거부, 경국지계 스테이징 연결을 확인한다. 이 문서의 자동 시험 통과를 실제 공급자 로그인 성공으로 기록하지 않는다.

## 메일 설정과 기능 활성화 전 준비

`.env.example`의 `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`을 운영 발신 서비스 값으로 지정한다. 포트 465는 TLS, 587은 필수 STARTTLS이며 인증서 검증을 끌 수 없다. 접속·인사 응답은 10초, 소켓은 15초 타임아웃을 사용한다. `GUARDIAN_REPLY_TO`는 보호자가 실제 회신하는 주소이며 자동 모드는 Resend 직접 수신 주소, 수동 모드는 운영자가 확인하는 수신함을 사용한다.

설정이 없으면 신규 가입·인증메일·비밀번호 복구는 준비 중 오류를 반환하고 기존 로그인은 계속 제공한다. 설정 유무는 실제 전달 성공을 보증하지 않는다. 전송 실패는 `EMAIL_DELIVERY_FAILED`로 알린다. 가입 정보가 생성된 뒤 발송이 실패했다면 계정을 다시 만들기보다 이메일 확인 메일을 재요청한다. 비밀번호·메일 링크·SMTP 오류 원문을 로그에 남기지 않는다.

발신 서비스는 Resend, 발신 주소는 `account@mail.gracekingames.com`이다. 자동 동의 회신 주소는 실제 연결한 Resend 전용 수신 주소로 지정한다. `support@gracekingames.com`은 문의·동의 철회 창구로 유지한다. 일반 메일만 개방했던 단계에서는 `GUARDIAN_REPLY_TO`를 설정하지 않았다. 자동 모드의 연결 검증에서는 주소·수신 키·서명키를 설정하고 `GUARDIAN_AUTO_APPROVAL_READY=false`로 신청·승인을 막은 채 실제 수신을 확인했다. Resend 도메인 `mail.gracekingames.com`은 인증 완료이며 발송 리전은 일본 도쿄(`ap-northeast-1`)다. `.env.example`에 `smtp.resend.com:465`, 사용자 `resend`를 주석 예시로 넣었다. 비밀번호에는 사용자가 발급한 해당 도메인의 발송 전용 API 키를 비공개 secret으로 설정한다. 실제 키·인증 링크·메일 원문을 명령 인자, 저장소, 로그에 넣지 않는다. [Resend SMTP 안내](https://resend.com/docs/send-with-smtp)

SMTP 설정이 유효하면 서버 시작 시 이메일 인증·가입·복구가 열린다. 기존 `email-reply-review` 모드는 회신 주소 설정으로 보호자 신청을 열며, 새 `email-reply-auto` 모드는 아래의 수신 주소·키·검증 완료 설정을 모두 요구한다. 다음은 일반 메일 설정의 확인 절차이며 자동 확인의 세부 절차는 아래 별도 절을 따른다.

1. 공개 방침과 `server/guardian.js` 동의문에 실제 업체·처리국가·보관 조건을 반영한다. 일반 메일 배포 동의 버전은 `2026-10-16-v2`였으며, 자동 회신에는 `2026-10-16-v3` 동의문을 사용한다. 기존 신청에 저장된 동의문을 소급 변경하지 않는다.
2. 운영과 분리한 시험 환경에서 사용자에게 허용받은 수신 주소로 실제 발송·도착을 확인한다. SMTP 접속 성공이나 서버 접수만으로 수신 성공으로 기록하지 않는다. Resend의 링크·열람 추적은 계정 인증 메일에서 사용하지 않으며 도메인 설정을 확인한다.
3. 문의 주소 `support@gracekingames.com`의 ImprovMX → Gmail 수신과 자동 동의 회신용 Resend 수신 주소를 구분한다. 실제 도착·처리·증빙 보관·삭제를 검증하며 DNS 레코드만으로 확인을 대신하지 않는다. 업체별 처리 위치·보관 고지도 실제 경로에 맞춰 공개 방침과 동의문에 반영한다.
4. 확인 결과를 반영한 서버·공개 방침을 배포하고 비공개 설정을 적용한다. `/api/account/config`와 가입·메일 확인·비밀번호 복구를 검증한다. 새 자동 모드의 수신 설정을 갖추더라도 `GUARDIAN_AUTO_APPROVAL_READY=false`로 어린이 신청·승인을 닫고 아래 절차로 연결을 검증한다.
5. 실제 확인한 범위만 아래 검증 이력과 배포 문서에 기록하고 README·공개 방침의 준비 중 안내를 기능별 상태에 맞게 갱신한다. 운영 테스트 자료와 수신함 사본을 같은 보존 원칙에 따라 정리한다.

회원 이메일·절차별 메일 본문과 전달 결과가 발송업체에서 처리되고, 보호자 회신의 성명·이메일·신청 번호·동의 내용은 수신 경로에서 처리된다. 비밀번호나 로그인 세션을 메일에 넣지 않는다. 이용자가 선택한 수신 메일 업체의 보관도 별개다. 업체 자료의 GDPR 설명만으로 한국 법률 준수를 확정했다고 안내하지 않는다. 공급업체·요금제·수신 경로·보관 조건을 바꾸면 공개 방침, 동의문·버전, 운영 절차를 함께 검토한다.

## 보호자 회신 자동 확인 운영

이 절은 공개 운영 중인 `email-reply-auto`의 운영과 연결 검증 절차다. 실제 수신과 실메일 자료를 사용한 격리 DB 시험 후 `GUARDIAN_AUTO_APPROVAL_READY=true`로 개방하고 공개 설정·화면을 확인했다. 기존 발송 전용 Resend 키로 수신 API를 호출하면 권한 오류가 나므로 대체 키로 간주하지 않는다. 수신 조회에는 별도 Full access 키가 필요하며 키 발급·교체는 사용자 권한과 명시적 승인 범위에 따라 진행한다. 실제 값은 비공개 설정으로 전달한다. [Resend API 키 권한 안내](https://resend.com/docs/api-reference/api-keys/create-api-key)

| 설정 | 역할과 준비 조건 |
| --- | --- |
| `GUARDIAN_CONSENT_MODE=email-reply-auto` | 자동 확인 모드를 선택한다. 기존 수동 모드는 `email-reply-review`다. |
| `GUARDIAN_REPLY_TO` | 실제 Resend 수신 주소. 설명용 예시는 `guardian@YOUR-TEAM.resend.app`이며 실제 주소를 확인하여 설정한다. |
| `RESEND_RECEIVING_API_KEY` | 수신 메일 조회에 필요한 사용자가 발급한 Full access 키. 기존 SMTP 발송 전용 키는 유지한다. |
| `RESEND_WEBHOOK_SECRET` | 해당 수신 웹훅의 서명을 검증하는 비밀값. 저장소·명령 인자·로그에 넣지 않는다. |
| `GUARDIAN_AUTO_APPROVAL_READY` | `false`에서는 수신 연결만 검증하고 신청·승인은 막는다. 실제 연결과 승인·보류·증빙 시험을 검수하고 공개 개방을 결정한 뒤 `true`로 설정한다. |

Resend가 제공하는 `<별칭>@<팀 식별자>.resend.app` 주소는 추가 DNS 없이 사용할 수 있다. 자체 주소를 사용하려면 수신 전용 하위 도메인 하나를 선택해 Resend가 안내하는 MX를 추가한다. `mail.gracekingames.com`을 선택할 수도 있지만 기존 루트 `gracekingames.com`의 ImprovMX MX를 교체하지 않는다. 문의 메일은 계속 기존 경로로 받는다. [Resend 수신 기능 안내](https://resend.com/features/inbound), [공식 수신 설정 설명](https://github.com/resend/resend-skills/blob/main/skills/resend/references/receiving.md)

웹훅은 `https://community.gracekingames.com/api/webhooks/resend/guardian`의 `email.received` 이벤트로 연결한다. 서버는 서명을 검사한 뒤 지정된 Resend API에서 내용을 조회한다. 웹훅 본문이나 발신자가 넣은 임의 헤더를 권위 있는 메일 인증 결과로 간주하지 않는다. 회신·첨부파일에 적힌 URL로 추가 요청하지 않으며 첨부파일을 내려받거나 실행하지 않는다.

### 신청을 닫은 상태의 수신 연결 검증

1. 자동 모드·수신 주소·수신 API 키·서명키를 비공개 설정하고 `GUARDIAN_AUTO_APPROVAL_READY=false`를 유지한다. 이 상태에서도 웹훅 서명, 고정 Resend API 조회, 메일 인증 결과, 단일 발신 주소, 수신 주소와 메타데이터를 검증한다. 어린이 신청 접수는 503으로 거부하며 기존 신청의 승인·보류 상태도 변경하지 않는다.
2. 허용받은 시험 주소에서 해당 수신 주소로 실제 메일을 보내고 아래 명령의 `verifiedReceipts`와 `latestVerifiedAt`을 시험 시각과 대조한다. 연결 검증 통과는 개인정보 없는 해시 이벤트에 `readiness_verified`로 기록한다. 이 결과는 동의 회신의 승인 증빙이 아니며 메일 본문을 출력하지 않는다.

   ```sh
   DATA_DIR=/data node scripts/guardian-review.mjs readiness
   ```

   확인 이력이 없으면 `{ "verifiedReceipts": 0, "latestVerifiedAt": null }`을 반환한다. 이력이 있으면 건수와 ISO 형식의 최근 시각을 반환한다. 이전 시험 기록만으로 새 설정의 연결 성공을 판단하지 않는다.
3. 실제 연결 결과와 별도 시험 환경의 승인·보류·증빙·삭제 검증을 함께 검수한 뒤 공개 개방을 결정하고 `GUARDIAN_AUTO_APPROVAL_READY=true`를 설정한다. 이후 공개 설정·화면과 가입 권한을 다시 확인한다. 준비 상태에서 연결만 확인한 동일 메일 이벤트가 다시 도착하면 활성화 이후의 승인 조건으로 새로 검사하므로 연결 확인 자체가 신청의 승인·소모를 뜻하지 않는다.

### 동의 회신 판정과 보류

자동 확인은 발신 주소·수신 주소·신청 번호·메일에만 넣은 256비트 회신 확인값·v3 동의문·법정대리인 진술·동의 범위가 맞는 새 회신에만 적용한다. 메일에서 안내한 7줄만 새 회신 본문에 넣어야 하며 인용문·서명·첨부파일을 제외한다. 인용된 안내문, 전달된 메일, 모호한 문장만으로 승인하지 않는다. 메일 인증 결과를 포함한 조건이 충족되지 않으면 보류한다. 생성형 AI에 회신 원문을 전송하거나 자유문장 의미를 추측하게 하지 않는다. 이는 회신의 일치 여부를 확인하는 절차로 실제 법정대리인 신원을 인증·보증하지 않는다.

메일에 HTML 본문이 함께 있으면 `div`, `p`, `br`, `span`과 `dir=ltr`·`lang` 속성으로 된 단순 서식만 허용하며 표시되는 7줄이 일반 텍스트 본문과 일치해야 한다. 서로 다른 동의 내용, 인용문, 스타일·숨김 요소, 주석, 서명·첨부나 복잡한 HTML은 보류한다. 일반적인 Gmail의 단순 줄바꿈 서식을 지원하되 HTML을 화면에 렌더링하거나 실행해 판단하지 않는다.

신청 API의 `reviewStatus`는 `awaiting-reply`, `held`, `approved` 또는 `null`이다. `held`여도 신청 상태는 `pending`이며 계정 생성 권한을 주지 않는다. 화면은 안전한 `reviewMessage`를 텍스트로 표시해 재회신·문의 방법을 안내한다. `reviewReason`은 `reply_format`, `email_authentication`, `sender_or_recipient`, `request_mismatch`, `message_metadata` 또는 `null`이며 원문이나 비밀값을 담지 않는다. 회신 확인값과 원문은 웹 화면·공개 API에 보내지 않는다. 새 회신이 도착한 뒤 상태를 다시 확인할 수 있으며 반복 폴링으로 승인하지 않는다. 기존 수동 모드 안내는 구분해서 표시한다.

승인 증빙은 동의문(회신 확인 코드는 해시로 대체), 인증·판정 결과, 발신·수신 주소와 메일 ID를 비공개 JSON으로 보관한다. 보류된 자유본문은 서버 증빙으로 저장하지 않는다. 미가입 신청 7일 만료·가입 전 취소·회원 삭제와 함께 정리하고 참조되지 않는 JSON은 24시간 유예 뒤 정리하는 기존 원칙을 적용하며, 메일 업체의 별도 보관 기간과 구분한다. 동의 철회·정보 삭제 문의는 자동 회신용 주소가 아닌 `support@gracekingames.com`으로 받는다. 운영자 확인이 필요한 예외는 문의로 처리하되 모든 정상 회신에 수동 승인을 다시 요구하지 않는다.

실제 활성화 전에는 서명 위조·재전송, 인증 실패·불명확, 다른 주소·번호·확인값·버전, 인용문만 있는 회신, 승인 후 중복·취소·만료, 같은 브라우저에서 한 번 가입, 증빙 보관·삭제를 검증한다. 키·주소·연결이 준비되지 않으면 신청은 닫힌 상태를 유지한다. 구현 초안·모의시험 통과를 실제 수신 연결 성공이나 공개 배포 완료로 기록하지 않는다.

### 자동 확인 화면의 초안 검증

외부 메일 없이 로컬 임시 API 응답을 사용하는 실제 브라우저에서 자동 최초 안내·대기·보류·승인, 수동 안내, 만료·신청 불가, 보류 안내의 HTML 주입 방지 등 27항목을 확인했다. `status=pending`인 요청은 `reviewStatus=approved`만으로 가입 버튼을 열지 않았다. 360px 보류 화면과 방침에 가로 넘침이 없었고 자바스크립트 오류도 없었다. 이 검증은 화면 상태 확인이며 서버의 자동 승인 통합시험·실제 Resend 수신 성공·공개 배포 완료를 뜻하지 않는다.

## 기존 수동 회신 검토 모드

아래는 `email-reply-review` 모드에서 사용하는 기존 절차다. 사용자가 요청한 자동 확인 모드와 구분하며, 수동 검토 절차를 자동 모드의 매회 필수 단계로 요구하지 않는다.

1. 어린이 정보를 받기 전에 보호자 이름·이메일만 신청받는다. 서버는 7일 유효한 비밀값을 HttpOnly·SameSite=Strict 쿠키에 넣고 해시만 보관한다. 운영 환경은 Secure 쿠키를 쓴다.
2. 신청 번호와 동의문을 보호자에게 보낸다. 목적·항목·보유 기간·국외 보관·거부 영향·법정대리인이라는 명시적 진술과 동의 회신 문구를 안내한다. 이메일의 도착이나 링크 클릭만으로 승인하지 않는다.
3. 운영자는 실제 수신한 회신의 발신자, 신청 번호, 동의 내용과 법정대리인 진술을 확인한다. 이름·이메일 불일치, 진술 불명확, 전달받은 메일 등 확인이 어려운 경우 승인하지 않고 회신으로 보완한다. CLI의 발신자 헤더 일치는 보조 검사이며 신원이나 법정대리인 지위를 자동 인증하지 않는다.
4. 검토한 회신 원문을 `.eml`로 내보내 로컬 운영 CLI에 전달한다. 최대 2MB의 원문을 MailParser로 해석해 MIME로 인코딩된 단일 발신자·제목·텍스트의 신청 번호를 검사한다. 첨부파일은 열지 않고 HTML을 화면에 표시하거나 실행하지 않는다. 원문과 SHA-256 해시를 비공개 데이터 폴더에 보관한다. 검토 완료 플래그 세 개는 운영자가 직접 검토했다는 기록이다.
5. 승인 후 신청한 브라우저에서 어린이 닉네임·이메일·비밀번호를 입력한다. 계정 생성과 동의 1회 소모는 SQLite 트리거의 같은 INSERT에서 처리한다. 경쟁 요청, 승인 뒤 철회·만료, 프로세스 재시작으로 같은 동의를 두 계정에 사용할 수 없다. 비밀번호 검증 등 회원 생성 전 실패는 승인을 소비하지 않는다.

공개 관리·승인 API는 제공하지 않는다. 다음 명령은 해당 데이터 폴더에 접근할 권한이 있는 운영자가 실행한다. 비밀키·비밀번호·회신 본문을 명령 인자로 넣지 않는다.

```sh
DATA_DIR=/data node scripts/guardian-review.mjs list
DATA_DIR=/data node scripts/guardian-review.mjs approve 신청번호 --evidence /비공개경로/회신.eml --confirm-reply --confirm-guardian --confirm-scope
DATA_DIR=/data node scripts/guardian-review.mjs reject 신청번호
DATA_DIR=/data node scripts/guardian-review.mjs withdraw 신청번호
DATA_DIR=/data node scripts/guardian-review.mjs delete-child 신청번호 --confirm-parent-request --confirm-deletion
DATA_DIR=/data node scripts/guardian-review.mjs cleanup
```

목록은 보호자 이메일을 마스킹한다. 승인 원문은 `DATA_DIR/guardian-evidence/` 아래 폴더 0700·파일 0600으로 복사한다. 검토용으로 내보낸 원본 `.eml`은 작업 후 같은 개인정보 보존 원칙에 따라 운영자가 정리한다. 실제 개인정보 삭제 명령은 보호자의 요청과 대상을 확인한 경우에만 실행한다. `delete-child`는 연결된 어린이 계정·세션·인증정보와 동의 증거를 삭제하므로 사전 보존 의무 여부를 확인한다. 성인 계정은 이 명령의 대상이 아니다.

운영자는 서버에 필요한 증빙을 보관한 뒤 수신함·내려받은 파일의 중복 사본을 정리한다. 미가입 신청의 만료·가입 전 철회와 문의 처리 종료를 확인하여 관련 사본도 정리하며, 수신함이 자동 삭제된다고 설명하지 않는다. 서버의 `cleanup`은 ImprovMX·최종 수신함·Resend의 사본이나 로그를 삭제하지 않으므로 별도 요청이 필요한 경우 각 업체 절차를 따른다.

미가입 신청은 7일 만료 후 이름·이메일과 승인 원문을 정리한다. 미가입 철회 신청도 정리하며, 회원 삭제로 연결이 끊긴 동의 자료도 정리한다. 서버 시작과 1시간 주기, 수동 `cleanup` 명령에서 실행한다. 원문 복사 직후 프로세스가 중단되어 DB에 기록되지 않은 UUID 이름의 `.eml`은 24시간 유예 후 정리하며 정상 참조 파일·다른 파일·심볼릭 링크는 보존한다. 서버가 꺼져 있으면 다음 시작 때 실행한다. 가입한 어린이의 철회는 우선 이용을 차단하고, 확인된 삭제 요청을 `delete-child`로 처리하면 개인정보 보관을 끝낸다. 이 작업은 DB 및 증거 폴더의 현재 사본에 적용되며 운영 백업은 정해진 보관 기한에 따라 별도로 만료시켜야 한다.

서버는 같은 DB에 한 인스턴스로 실행한다. 시작 시 회원 생성 전에 중단된 예약을 복구한다. 동의가 소모된 회원은 다시 승인 상태로 열리지 않는다. 기존 회원을 삭제하거나 테스트 데이터로 초기화하는 마이그레이션은 없다.

## HTTP 계약

운영 계정 출처는 `BETTER_AUTH_URL=https://community.gracekingames.com`으로 설정한다. 메일 링크와 콜백은 이 설정에서 얻은 출처를 사용한다. Pages의 `/account/` 진입도 새 출처로 이동하며, 계정 화면의 대문·게임 복귀 링크는 `https://gracekingames.com`을 사용한다.

계정·게시판의 브라우저 변경 요청은 같은 Origin·JSON이 필요하다. 외부 메일 수신은 쿼리가 없는 `POST /api/webhooks/resend/guardian`에 한해 Origin 검사 대신 Resend 서명 검증을 적용한다. 수신 웹훅에도 JSON 형식, Host 검증과 IP 속도 제한을 적용한다. 인증·계정 JSON은 `no-store`, 응답은 `no-referrer`다. 본문 `callbackURL`·`redirectTo`는 서버의 `/account/` 주소로 고정한다. 임의 외부 URL로 토큰을 전달하지 않는다.

| 요청 | 입력 | 성공 응답 |
| --- | --- | --- |
| `GET /api/account/config` | 없음 | `emailAvailable`, `registrationAvailable`, `guardianConsentAvailable`, `guardianConsentMethod` |
| `GET /api/account/session` | 로그인 쿠키 | `user:null` 또는 `id,name,email,emailVerified,ageBand,canWriteCommunity` |
| `POST /api/auth/sign-up/email` | `name,email,password,ageBand` | `{status:true}`, 세션 없음 |
| `POST /api/auth/sign-in/email` | `email,password` | Better Auth 로그인 응답과 HttpOnly 세션 쿠키 |
| `POST /api/auth/sign-out` | `{}` | Better Auth 로그아웃 응답 |

| `POST /api/account/verify-email` | `token` | `{status:true}` |

보호자 상태는 `pending`, `approved`, `rejected`, `expired`, `used`, `withdrawn`이다. 내부 `creating` 예약은 화면에서 `approved`로 표시하지만 중복 회원 생성은 서버에서 막는다. 개인정보·비밀 capability는 상태 응답에 포함하지 않는다. 어린이 가입은 `ageBand:'under14'`와 승인된 신청 쿠키가 함께 필요하다. 구형 `ageConfirmed:true`, `emailVerified`, 임의 동의 ID 등으로 가입 조건을 우회할 수 없다. 보호자 신청이 진행 중인 브라우저는 성인 구분으로 우회할 수 없다. 쿠키를 지우고 연령을 허위 신고하는 행위까지 본인인증으로 막는 구조는 아니다.

이메일 확인 링크는 `https://community.gracekingames.com/account/?view=verify#token=...`, 복구 링크는 `https://community.gracekingames.com/account/?view=reset#token=...`이다. 옛 Host의 `/account/` GET·HEAD 요청도 경로·쿼리를 보존해 새 출처로 301 이동하며 계정 API는 403으로 거부한다. URL 해시는 HTTP 요청에 포함되지 않아 서버가 다루지 않으며, 해시가 없는 Location으로 301 이동하면 브라우저가 기존 `#token=...`을 유지한다. 화면에서 해시를 즉시 지우고 사용자 확인 버튼으로 POST한다. GET만 하는 메일 스캐너는 토큰을 소비하지 않는다. 확인 토큰은 256비트 무작위값의 SHA-256 해시만 DB에 저장하며 1시간·1회 유효하고 재발송하면 앞선 링크를 폐기한다. 복구 토큰도 Better Auth의 해시 저장과 트랜잭션 내 1회 소비를 사용하며 1시간 유효하다.

## 로컬 검증용 메일 주입

자동 테스트는 `startServer({port:0,dataDir:임시폴더,mailer:async message=>mailbox.push(message),guardianReplyTo:'support@example.test'})`로 외부 전송을 대체한다. `message`는 `{to,subject,text}`이고 보호자 동의 메일에는 `replyTo`가 추가된다. 확인·복구 링크는 `text`의 URL 해시에만 있다. 캡처 객체와 토큰을 로그·공개 파일·저장소에 출력하지 않는다. 테스트 주소는 `example.test`만 사용한다. 파일 메일함이나 공개 테스트 메일 조회 API는 없다.

이메일 확인을 마친 만 14세 이상 활성 계정이 보상 대상이다. 미확인 계정은 인증 뒤 활동부터 받으며 확인 전 활동·기존 글·댓글은 소급하지 않는다. 만 14세 미만 계정은 출석·활동·운영자 이벤트 보상에서 제외하고 기존 잔액은 유지한다. 보상 정지는 활동·운영자 지급과 레이스 이용을 제한한다. 정지를 해제해도 취소된 예정 보상은 되살리지 않는다.

| 경로 | 지급·조건 |
| --- | --- |
| 출석 | 로그인한 회원의 계정·커뮤니티 진입 시 한국 시간 하루 한 번 300 그레인. `POST /api/grain/attendance`에 빈 객체 `{}`를 보내며 `{awarded,amount,date}` 반환 |
| 글 | 제목 2자·본문 30자 이상, 직전 본인 글과 중복 아님. 하루 3건까지 각 500 그레인 예정 |
| 댓글 | 본문 10자 이상, 본인 글 제외, 같은 글의 첫 댓글만. 하루 10건까지 각 100 그레인 예정 |
| 자동 활동 합계 | 한국 시간 하루 3,000 그레인 한도. 예정·확정 보상을 함께 계산 |
| 버그 채택 | 단순 `simple` 2,000 · 일반 `normal` 5,000 · 중대 `critical` 20,000. 같은 문제 최초 제보 여부는 운영자가 확인 |
| 우수 글 | 글당 한 번 3,000 그레인 |
| 이벤트 | 미리 등록한 식별자·기간·지급량을 사용하고 이벤트별 계정당 한 번 |

글·댓글은 생성과 보상 예약을 같은 트랜잭션에 기록한다. 생성 응답의 `reward:{pending,amount}`가 예정 여부를 알려 주며 수정으로 다시 예약하지 않는다. **작성 후 24시간 유지**가 확정 조건이다. 삭제·숨김·보상 정지 시 대기분은 취소되고 복원해도 다시 예약하지 않는다. 확정된 보상은 글 삭제만으로 회수하지 않는다.

서버 시작 때 한 번, 실행 중에는 **60초마다** 예정 목록을 확인해 만기가 지난 보상을 원장과 지갑에 확정한다. 프로세스가 실행 중이면 만기 이후 다음 확인 때 반영되며 정확히 24시간째 지급되는 타이머는 아니다. Fly 유휴 정지·최소 실행 0대 정책을 그대로 두므로 정지 중에는 처리하지 못하고 다음 시작 때 미처리분을 확인한다. 예정 금액은 확정 전 잔액에 포함하지 않는다. 중복 원장 방지와 잔액 0 이상 제약은 유지한다.

`GET /api/account/grain`은 기존 `{balance,entries}`에 `pending:[{eventId,targetType,targetId,amount,createdAt,confirmsAt}]`, `pendingTotal`, `rewardEligibility`를 더한다. 시각은 ISO 형식이다. 자격은 `eligible|unverified|under14|suspended`이며 사유·예정 합계·예정 목록을 본인 계정 화면에 표시한다. 미확인 안내는 기존 `/api/auth/send-verification-email` 화면을 재사용하며 로그인 세션의 이메일을 채운다. 출석 지급에 성공한 경우에만 짧은 지급 안내를 표시한다.

`server/grain-policy.js`의 깊게 동결한 `GRAIN_REWARD_POLICY`가 지급량·하루 한도·최소 본문 길이·확정 지연의 정본이다. 활동 보상과 버그 등급·우수 글 지급 코드가 이 상수를 직접 사용한다. 기존 `server/grain-rewards.js`의 `REWARD_DAY_MS` 내보내기는 유지한다. 로그인 없이 읽는 `GET /api/account/config`는 기존 필드에 `grainRewardPolicy`를 추가하며 회원 정보·잔액·운영자 식별자를 포함하지 않고 DB를 변경하지 않는다. `/account/`의 ‘그레인 받는 방법’ 표는 회원 전용 잔액·이용 내역 밖에 한 번만 배치하고, 공개 설정 수치를 검증한 뒤 안전한 DOM으로 표시한다. 로그인·로그아웃 모두 같은 정책을 볼 수 있고, 설정을 읽지 못하거나 잘못된 수치가 오면 수치 표 대신 재확인 안내를 표시한다.

| `grain_admin_audit` | 조치 운영자·행위·대상·사유·시각과 관련 회원/글/댓글/신고/제보/이벤트/공개문제 외래키 |

새 표의 회원 외래키는 `ON DELETE CASCADE`를 사용한다. `grain_admin_audit`도 관련 회원·글·댓글·신고·제보·이벤트·공개문제에 외래키로 연결해 삭제에 따라 정리한다. 활동 표의 대상 ID는 삭제 뒤 중복 예약·소급을 막기 위한 식별값으로 남을 수 있으나, 회원을 삭제하면 해당 회원의 활동 기록은 함께 삭제한다. 글·댓글 삭제·숨김과 회원 정지 트리거가 확정 전 보상을 취소한다. 운영 자료를 브라우저 저장소에 보관하지 않는다.

### 비공개 제보와 신고 API

| 요청 | 입력·응답 |
| --- | --- |
| `POST /api/community/reports` | 글쓰기 가능한 로그인 계정, 본인 대상 제외. `{targetType:post|comment,targetId,reason,description?}`. 사유는 도배·광고/욕설·괴롭힘/개인정보 노출/계정·그레인 거래/버그·보안 제보 공개/기타, 설명 최대 500자 |

| `POST /api/community/bug-reports` | 로그인 계정만. `{game:slimeline|gyeongguk|site|slime-race,title,body,steps?,url?}`. 제목 2~100자, 본문 10~5,000자, 재현 절차 최대 3,000자, 주소 최대 2,000자이며 http/https만 |
| `GET /api/community/bug-reports` | 본인의 `{reports:[{id,status,grade,createdAt,updatedAt}]}`만. 원문·다른 회원 지정 경로 없음 |

제보 상태는 **접수/확인 중/중복/재현 불가/채택/수정 완료**다. 알려진 문제 상태는 **확인 중/수정 중/수정 완료**다. `/community/bug-report/` 상단에서 알려진 문제를 먼저 확인한다. 보안·개인정보 문제도 비공개 양식으로 받으며 글·댓글 공개 제보는 신고·숨김 후 비공개 접수를 안내한다. 비공개 페이지는 `noindex, nofollow`, `no-referrer`를 지정하고 외부 통계·외부 스크립트를 넣지 않는다.

### 운영 권한과 도구

`ADMIN_USER_IDS`는 **기존 공통 계정의 회원 ID를 쉼표로 구분한 문자열**이다. 양쪽 공백과 빈 항목은 제거한다. 이메일·닉네임을 넣는 설정이 아니며 기본값은 운영자 없음이다. 설정값은 서버만 읽는다. 이 문서·저장소·로그에 실제 운영 ID나 비밀값을 넣지 않는다. 사용자 요청이나 브라우저 입력으로 운영 권한을 정하지 않으며 모든 운영 API가 현재 세션·활성 계정·설정 ID를 서버에서 재확인한다. 화면 경로를 아는 것만으로 권한을 얻을 수 없다.

운영 화면은 `/account/admin/`이며 검색 색인을 막는다. 비운영 계정·비회원은 권한 안내만 보며 운영 목록·입력 영역은 숨긴다. 권한 만료·403 응답·페이지 이탈 때 기존 개인 자료를 비운다. 조치 입력에는 2~1,000자 사유가 필요하고 서버 감사 표에도 기록한다.

| 요청 | 운영 입력·결과 |
| --- | --- |
| `GET /api/admin/session` | `{admin:true}`. 비운영자는 403 |
| `GET /api/admin/reports` | 신고 목록과 대상 원문. 대상 삭제 시 `target:null` |
| `POST /api/admin/reports/:id` | `{action:dismiss|hide|unhide,reason}`. 기각·숨김·복원 |
| `POST /api/admin/content` | `{targetType,targetId,hidden:boolean,reason}` |
| `GET /api/admin/hidden` | `{posts,comments}`. 숨긴 원문 목록 |
| `GET /api/admin/users?q=…` | 정확한 이메일 또는 닉네임. `{users:[{id,name,rewardEligibility,balance}]}`. 이메일 등 불필요한 개인정보는 반환·표시하지 않음 |
| `POST /api/admin/users/:id/suspension` | `{suspended:boolean,reason}`. 정지 시 예정분 취소, 보상·레이스 제한 |
| `POST /api/admin/users/:id/reclaim` | `{amount,reason}`. 남은 잔액 범위의 양수 정수만. `{ok,reclaimed,balance}`. 잔액 초과분은 거부하며 필요하면 별도 정지를 적용 |
| `GET /api/admin/bug-reports` | 운영자만 제보 원문·접수 계정 최소정보·보상 판정 확인 |
| `POST /api/admin/bug-reports/:id` | `{status,grade?:simple|normal|critical,reason}`. `{report,awarded,duplicate,rewardEligibility}` |
| `POST /api/admin/known-issues` | `{title,summary,status,reason}`. 공개 제목 2~100자·요약 10~2,000자 |
| `POST /api/admin/known-issues/:id` | 같은 입력으로 별도 공개 안내를 수정. 제보 원문 자동 공개 없음 |
| `POST /api/admin/best-post` | `{postId,reason}`. `{awarded,duplicate,rewardEligibility}` |
| `GET /api/admin/events` | `{events:[{slug,title,amount,startsAt,endsAt,createdAt}]}` |
| `POST /api/admin/events` | `{slug,title,amount,startsAt,endsAt,reason}`. 식별자는 소문자·숫자·붙임표, 이름 2~100자, 1~100,000 그레인, 종료는 시작보다 뒤. 시각 입력은 ISO8601 또는 안전정수 밀리초 지원, 응답 ISO |
| `POST /api/admin/events/:slug/awards` | **본문은 `{recipients,reason}`만**. 최대 500개 회원 ID 또는 정확한 이메일. `{awarded,skipped,duplicates,notFound}`는 각각 건수 |

버그 채택 시 등급별 지급은 제보당 한 번이다. 미확인·어린이·정지 계정으로 채택 판정을 마친 경우에도 당시 자격을 기록하므로 나중에 인증·정지 해제 후 재채택해 소급 지급할 수 없다. 지급 판정을 마친 등급은 변경할 수 없다. 같은 버그인지, 이미 알려진 문제인지의 판단은 운영자가 먼저 확인하고 중복/재현 불가 상태로 처리한다. 회수는 남은 잔액 범위에서만 수행하며 지갑을 음수로 만들지 않는다. 이벤트 지급 결과는 건수만 표시한다.

### 검증과 배포 준비

- `python3 scripts/verify_site.py`: 새 제보·운영 페이지 필수 존재, HTML/자산·Docker 허용 목록, 같은 출처 API, 민감정보 패턴, 비공개 페이지의 색인 제외·외부 스크립트 없음 검사.
- `node --check assets/account/account.js` 및 `admin.js`, `tools.js`, `assets/community/community.js`, `bug-report.js`: 구문 검사.
- `npm test`, `python3 tests/security-review/test_verify_site.py`, `git diff --check`: 기존 회귀·정적 검사 경계·공백 검사.
- `scripts/verify_grain_screens.mjs`: **운영과 분리된 새 임시 DB**에서 실제 가입·메일 확인·로그인·출석·신고·댓글 보상·제보·운영 도구를 검증한다. Playwright 설치 환경에서 `node scripts/verify_grain_screens.mjs`로 실행한다. 필요하면 `PLAYWRIGHT_MODULE`에 모듈 절대 경로, `CHROME_PATH`에 브라우저 실행 파일을 지정한다. 통합 전 별도 서버 스냅샷을 검증할 때만 `GRAIN_SERVER_ROOT`를 지정하며 화면 자산은 현재 저장소를 쓴다. 1440/390/320px 가로 넘침·실행 예외·로그인/비로그인 공개 표의 수치·조건·표 의미·회원 정보 구분·실제 로그아웃 후 표 유지·비회원 차단·본인 신고 제외·이벤트 본문 허용필드를 확인하고 스크린샷과 결과를 임시 경로에 남긴다. 임시 DB는 종료 시 삭제한다.

`.dockerignore` 마지막의 「그레인 활동 보상·버그 제보·운영자 도구」 절에 새 서버·화면·자산만 명시 허용한다. `_config.yml`의 서버·시험·문서·운영자료 제외는 유지한다. 약관·방침·화면·API를 통합 검수한 뒤 사용자의 명시적인 공개 요청이 있을 때만 배포한다. 공개 여부와 운영 반영은 기존 배포 기록에서 따로 확인한다.
