| 계약 항목 | 구현 | 결과 |
| --- | --- | --- |
| 발견 문서 위치 | `GET <공통 계정 주소>/.well-known/openid-configuration` (예: `https://community.gracekingames.com/.well-known/openid-configuration`, 로컬 `http://127.0.0.1:8766/.well-known/openid-configuration`) | 준수 |
| `issuer` | `BETTER_AUTH_URL` 출처 그대로(예: `https://community.gracekingames.com`). ID 토큰 `iss`와 인가 응답 `iss`도 같은 값 | 준수 |

| 흐름 | `response_type=code`, `scope=openid`(다른 범위 거부), PKCE `S256` 필수(`plain`·누락 거부), `state`·`nonce` 그대로 반환 | 준수 |

| 등록 | `OIDC_CLIENTS` JSON 배열(`client_id`, `client_secret`, `redirect_uris`, `name`)을 서버 시작 때 등록·갱신, 빠진 클라이언트는 사용 중지. 동의 화면 없음 | 준수 |
| 복귀 주소 | 등록 주소와 글자 그대로 일치해야 함(플러그인의 루프백 포트 완화도 끔) | 준수 |
| ID 토큰 클레임 | `iss`, `aud`(=client_id 문자열), `sub`(=Better Auth `user.id`), `exp`, `iat`, `nonce`, `age_band`(`'14plus'`/`'under14'`). 이메일·이름 없음 | 준수. 추가로 `auth_time`·`acr`(`"0"`)·`at_hash`가 들어간다(플러그인 기본, 무시해도 됨) |
| 서명 | JWKS 공개 키, `kty=OKP`, `crv=Ed25519`, `alg=EdDSA` | 준수 |
| 로그인 안 된 사용자 | 인가 요청 → `/account/`(서명된 요청 보존) → 이메일·네이버·구글 로그인 → 같은 인가 요청으로 코드 발급 | 준수(시험·실제 브라우저 확인) |
| legacy 회원 | 코드 발급 전 `/account/` 나이 확인. 14세 이상 선택 뒤 코드 발급, `age_band='14plus'`. 14세 미만 선택은 기록·코드 없이 보호자 동의 가입 안내 | 준수(아래 3절 1) |
| 14세 미만 계정 | 코드 발급, `age_band='under14'`. 보호자 동의 철회 뒤에는 토큰 교환 거부 | 준수 |
| 취소·실패 | 계정 화면 '취소하고 게임으로 돌아가기' → `redirect_uri?error=access_denied&state=...&iss=...`. 범위·PKCE 오류도 등록된 복귀 주소로 표준 `error`. 미등록 클라이언트·미등록 주소는 게임으로 보내지 않고 계정 화면 오류(RFC 6749 4.1.2.1) | 준수 |

`OIDC_CLIENTS` 형식 예시(값은 가짜):

```json
[{"client_id":"gyeongguk-dev","client_secret":"<32자 이상 무작위 값>","redirect_uris":["http://127.0.0.1:8787/auth/gracekin/callback"],"name":"경국지계(로컬)"}]
```

운영은 `gyeongguk`(`https://gyeongguk.gracekingames.com/auth/gracekin/callback`), 시험판은 `gyeongguk-test`(`https://gyeongguk-test.fly.dev/auth/gracekin/callback`)를 같은 형식으로 넣는다.

### T34가 알아 둘 플러그인 동작

- 인가 끝점은 브라우저 이동(`sec-fetch-mode: navigate` 또는 `accept: text/html`)이면 302, fetch 요청이면 JSON `{redirect:true,url}`을 준다. 경국지계는 지금처럼 브라우저를 302로 보내면 된다. Node fetch로 시험할 때는 JSON이 오는 점을 감안한다.
- 토큰 끝점 오류는 RFC 형식 `{error, error_description}`(400·401). 코드는 한 번만 쓰이고 600초 뒤 만료. ID 토큰·접근 토큰 수명 600초, 갱신 토큰 없음.
- 서버는 `nonce`를 필수로 요구하지 않는다(보내면 그대로 돌려준다). 계약대로 경국지계가 항상 보내고 검증한다.
- userinfo·introspect·revoke·end-session은 발견 문서에 광고되지만 게이트에서 열지 않았다(404). 계약은 이 경로들을 쓰지 않는다.

## 3. 계약·지시와 다르게 하거나 해석한 점(조율자 확인 필요)

1. **legacy 회원의 연령 선택 저장**: `user.ageBand`에 쓰지 않고 새 표 `account_age_declarations`에 둔다. `user.ageBand`를 채우면 기존 세션 훅이 미확인 이메일의 기존 회원 로그인을 막고, 커뮤니티 쓰기 권한(`legacy`는 이메일 확인과 무관하게 허용)이 바뀌기 때문이다. 이 값은 OIDC `age_band`에만 쓴다. 14세 미만 선택은 저장하지 않으며 계정을 잠그지 않는다(다시 연결하면 다시 묻는다). 게임으로의 복귀는 사용자가 '취소하고 게임으로 돌아가기'를 눌러 `access_denied`로 돌아간다(자동 복귀 아님).
2. **소셜 가입 닉네임**: 공급자의 실명·별명·사진을 공개 닉네임으로 쓰지 않도록, 가입 화면에서 입력한 닉네임을 서명 쿠키로 콜백까지 넘긴다. 공급자 프로필 사진은 저장하지 않는다.
3. **네이버 이메일 = 확인된 이메일**: 기획 결정 8 문구대로 네이버가 이메일을 주면 확인된 것으로 보고 가입 때 그레인을 준다. 네이버가 이메일을 주지 않으면(제공 미동의) 가입하지 않는다(`email_not_found`). 이메일 없는 소셜 가입 후 확인하는 경로는 Better Auth가 이메일 없는 회원을 만들지 않아 만들지 않았다.
4. **소셜 가입은 메일 발송이 있을 때만**: 공급자가 확인하지 않은 이메일은 확인 메일이 필요하므로 `socialSignupAvailable = 공급자 있음 && 메일 설정 있음`. 소셜 로그인은 메일과 무관하게 된다.
5. **공급자가 확인하지 않은 이메일의 소셜 가입**(구글 `email_verified=false`): 회원은 만들어지지만 기존 세션 훅대로 이메일 확인 전 로그인이 막히고 확인 메일이 간다. 확인 뒤 그레인 지급·로그인.
6. **버튼 모양**: 기존 화면 양식(테두리 단추)으로 '네이버로 로그인'·'구글로 로그인' 글자 단추를 넣었다. 네이버 검수·구글 브랜딩 가이드가 공식 로고 단추를 요구하면 별도 시안이 필요하다(지금은 로고 없음).
7. **공급자 토큰 저장**: Better Auth가 공급자 접근·갱신 토큰을 `account`에 저장하는 것을 끌 수 없어 `encryptOAuthTokens`로 암호화해 저장한다.

## 5. 로컬 통합 확인 방법

공통 계정 서버는 SMTP 없이 시작한다(`npm start`도 됨). 다만 메일 없이는 새 가입·소셜 가입이 닫히므로, 경국지계와 함께 확인할 때는 `scripts/dev-server.mjs`로 띄운다. 이 스크립트는 메일을 보내지 않고 가입 확인 메일만 같은 서버에 바로 확인 요청해 가입 즉시 로그인할 수 있게 한다.

```sh
cd /Users/app/orca/workspaces/gracekin-games/acct-social
SECRET=$(node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))")
OIDC_CLIENTS="[{\"client_id\":\"gyeongguk-dev\",\"client_secret\":\"$SECRET\",\"redirect_uris\":[\"http://127.0.0.1:8787/auth/gracekin/callback\"],\"name\":\"경국지계(로컬)\"}]" \
  DATA_DIR=.data/local-oidc PORT=8766 node scripts/dev-server.mjs &
echo $!   # 끝나면 이 PID로 kill <pid>
# 경국지계 서버(기본 8787): GRACEKIN_DISCOVERY=http://127.0.0.1:8766/.well-known/openid-configuration
#   GRACEKIN_CLIENT_ID=gyeongguk-dev  GRACEKIN_CLIENT_SECRET=$SECRET
```

2026-10-16 이 방법으로 포트 8796에 띄워 발견 문서 → 가입(자동 확인) → 로그인 → 인가 → `client_secret_basic` 토큰 → ID 토큰(`age_band=14plus`, `aud=gyeongguk-dev`)을 확인했고, 직접 띄운 PID로 종료했다. 실제 네이버·구글 로그인은 로컬에서 키가 없어 확인하지 않았다(버튼만 보려면 가짜 키 값을 넣으면 되고, 누르면 공급자 오류가 난다).

## 6. 남은 것

- 사용자 몫: 구글 Cloud OAuth 클라이언트·네이버 애플리케이션 등록(콜백 `https://community.gracekingames.com/api/auth/callback/google|naver`), 키 발급, `fly secrets`(`GOOGLE_*`, `NAVER_*`, `OIDC_CLIENTS`), 네이버 검수. 검수 전에는 네이버 키를 넣지 않으면 버튼이 숨겨진다.
- 배포 때: 개인정보처리방침 적용일 갱신, 시험판(결정 15)에서 실제 공급자 가입·로그인·연결·해제와 경국지계 스테이징 연결 확인. 운영 DB에는 `jwks`·`oauth*`·`account_age_declarations` 표가 새로 생긴다(기존 표 변경 없음).
- `BETTER_AUTH_SECRET`를 바꾸면 JWKS 개인 키(그 값으로 암호화)를 쓸 수 없게 되므로 `jwks` 행을 지우고 새 키를 만들어야 한다. 키 자동 회전은 켜지 않았다.
- 탈퇴 연동(결정 11)은 지시서대로 이번 범위가 아니다.
- 이메일 가입은 확인 메일을 거치므로 게임 로그인 요청은 같은 탭에서 10분 안에 로그인할 때만 이어진다. 늦으면 게임에서 다시 시작한다.
- 같은 회원이 두 로그인 수단을 동시에 해제하는 경합은 서버 확인과 라이브러리 확인 사이에 막지 못할 수 있다(화면은 한 번에 하나만 보냄). 그래도 비밀번호 재설정으로 이메일 로그인을 다시 만들 수 있다.
- Better Auth 기본 속도 제한으로 `/sign-in/social`은 IP당 10초 3회다. 토큰 끝점은 IP당 분당 120회(게임 서버 한 대가 모든 이용자의 교환을 보내므로 기본값보다 높였다).
- 사이트 기획 `docs/기획/공통-계정과-게임-연결.md`의 상태 문구는 고치지 않았다(배포 뒤 갱신 대상).
- `tests/security-review/review_http.mjs`의 기존 실패(4절)는 별도 정리 대상이다.
