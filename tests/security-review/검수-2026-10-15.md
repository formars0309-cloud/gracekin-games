# 회원 커뮤니티 독립 보안 검수

- 검수 대상: `community-server` 및 `community-members` 작업자의 구현 중 변경 사항. 해당 워크트리 원본은 수정하지 않았다.
- 공개 배포·공개 계정 생성 없이, 독립 임시 데이터 폴더와 임시 포트에서 실행했다.
- 실행: `node tests/security-review/review_http.mjs <백엔드 워크트리 경로>`
- 실행 결과: 실제 HTTP 59개 확인 통과. 실행 종료 때 검수용 서버·DB·임시 정적 파일을 모두 정리한다. 쿠키·비밀번호·인증키·응답 본문은 보고서나 로그에 남기지 않는다.

## 실제 HTTP 실험

| 경계 | 확인 결과 |
| --- | --- |
| 가입·세션 | 두 계정의 실제 가입, HttpOnly·SameSite=Lax 쿠키와 가입 후 세션 확인 |
| 글·댓글 | 다른 계정에서 공유 조회, 작성자 ID 위조 무시, 임의 UUID 생성 확인 |
| 소유권 | 다른 회원의 글·댓글 수정·삭제는 403 |
| 게임 분리 | 타게임 글 조회·변경과 댓글 변경은 404, 타게임 목록에는 원래 게임 글이 없음 |
| CSRF·요청 형식 | Origin 누락·다른 Origin·cross-site 표시·Host 위조는 403, JSON 이외 본문은 415 |
| 입력·부하 | 공백 닉네임·회원 공지 작성은 422, 길이 헤더 없는 70KB 요청은 413, 인증·조회 제한은 429 |
| 검색·XSS | SQL 검색 문자열은 검색값으로 처리, XSS 문자열은 JSON 원문으로 전달 |
| 개인정보 | 공개 커뮤니티 응답에 email·token·password·hash·salt 필드 없음 |
| 파일·저장 | 비밀번호 비평문, 인증키와 SQLite 파일 권한 0600 |
| 지속성 | 같은 데이터 폴더로 서버를 재시작한 후 세션·글·댓글 유지 |
| 로그아웃 | 이전 쿠키의 세션 무효화, 다시 로그인 성공 |
| 정적 공개 범위 | 서버·설정·DB·설치 모듈·인계 문서와 인코딩 경로 탈출 및 symlink 우회는 404 |

XSS 문자열의 JSON 보존은 브라우저에서 스크립트가 실행되지 않는다는 결과와 다르다. 브라우저 실행 여부와 시각·접근성 검수는 프런트 작업자 및 조율자의 통합 검수에서 확인한다.

## 정적 코드 검토

- SQL 값은 준비된 쿼리 바인딩으로 전달한다. 테이블명·조건 문자열은 서버가 정의한다.
- 세션은 Better Auth에 조회하고, 변경 권한은 서버에서 세션 사용자와 원본 작성자를 비교한다.
- 오류 처리와 인증 로거는 비밀번호·쿠키·인증키·오류 객체를 출력하지 않는다.
- 프런트는 사용자 글·댓글·닉네임을 `textContent`로 렌더링한다. 같은 출처 `/api` 단일 요청 헬퍼와 게임·게시판 응답 경계를 사용한다.
- 글·인증·삭제 중복 클릭 방지와 목록 조회 순서 번호를 확인했다. 네트워크 실패 때 작성 입력은 보존한다.
- 발견·수정 확인: 성공 로그아웃 후 초안이 다음 계정에게 보일 수 있는 경로를 전달했다. 프런트 `fabb47d`는 성공 로그아웃 때 글·댓글·계정 입력을 정리하고, 세션 재조회에서 초안 소유자와 새 사용자 ID가 다르면 초안을 비운다. 401·일시 연결 실패 때는 초안을 보존한다. 이 변경을 독립 정적 재검수했으며, 브라우저 재현·수정 확인은 프런트 작업자가 수행했다.
- 프런트 `fabb47d`에 사이트 검증기를 읽기 실행하여 1,154개 확인 통과했다.

## 한계

- 실행 시점의 작업 중 파일을 대상으로 한 검사다. 통합된 최종 커밋에서도 같은 HTTP 검수와 사이트 검증을 실행해야 한다.
- 인증 응답에서 사용자 자신의 이메일을 반환하는 동작과 비회원도 읽는 공개 커뮤니티 응답을 구분했다.
- 운영 HTTPS·실제 역방향 프록시·다중 인스턴스·메일 인증·복구 메일은 이번 로컬 실험 범위에 없다. 기본 속도 제한은 실제 접속 IP를 사용하므로 운영 프록시 환경의 IP 전달·제한 정책은 배포 전에 별도로 확인한다.
- 정적 검사와 제한된 HTTP 실험의 통과가 모든 보안 위험의 부재를 보장하지 않는다.
