# 캐릭터 그림 파이프라인

정본은 `docs/기획/캐릭터-구현-계약.md`다. 내장 이미지 편집 도구로 기준 몸 위에 한 가지 부품만 덧그린 원본에서 납품 부품을 추출한다. 생성 호출은 이 스크립트에 포함하지 않는다. API 키가 필요 없다.

## 원본과 생성 지시

원본·중간 파일은 저장소 밖 `/Users/app/orca/projects/gracekin-games/.handoff/캐릭터-구현/그림-작업/`에 둔다. 기존 시안 폴더는 읽기만 했다.

- `base.png`: 기존 1024×1536 기준 몸을 0.86배(881×1321)로 줄여 (72, 162)에 놓은 공용 정본. 불투명 머리 경계는 원본 y≈260이다.
- `{race}.png`: 인간을 제외한 종족 9종 편집 원본. `moon-first.png`는 정렬 탈락본으로 사용하지 않는다.
- `h1-front.png`~`h8-front.png`: 앞머리 편집 원본.
- `h{2,4,5,8}-back.png`: 긴 머리 뒤층을 별도로 편집한 원본. 앞층 이미지와 차이를 내서 뒤층으로 나누는 방식이 아니다.
- `{job}.png`: 직업 10벌 편집 원본.
- `recipes.json`: 실제 편집에 쓴 공통 조건과 부품별 지시. 원본마다 항상 같은 기준 몸을 편집 대상으로 사용했다. `elf`는 긴 귀로 바꾸되 몸·얼굴·옷·상단 여백은 그대로 두라는 조건으로 편집했다. `moon`은 3화소 정렬 오차 때문에 피부색만 바꾸는 조건으로 다시 편집했다.

## 실행

작업 폴더에 가상 환경을 만들고 `requirements.txt`를 설치한다. 저장소 루트에서 실행한다.

```sh
python3 -m venv --system-site-packages /저장소밖/그림-작업/venv
/저장소밖/그림-작업/venv/bin/pip install -r scripts/character-art/requirements.txt
python3 scripts/character-art/prepare.py /기존/부품/base.png /저장소밖/그림-작업/base.png
/저장소밖/그림-작업/venv/bin/python scripts/character-art/pipeline.py --work /저장소밖/그림-작업
/저장소밖/그림-작업/venv/bin/python -m unittest discover -s scripts/character-art -p 'test_*.py'
node --test test/character-art.test.js
python3 scripts/character-art/edge_audit.py
/저장소밖/그림-작업/venv/bin/python scripts/character-art/edge_proofs.py
```

`--root`와 `--report`로 출력 경로를 바꿀 수 있다. `--proof-only`는 기존 납품 부품에서 확인판만 다시 만든다. 확인판의 한글 글꼴은 macOS의 애플 산돌고딕을 사용하며 없으면 Pillow 기본 글꼴을 사용한다.

## 추출과 정렬

- 투명 배경의 숨은 RGB를 0으로 정리하고, 알파 40 미만을 0, 248 이상을 255로 맞춘다. 차이는 회색 배경에 합성한 결과로 계산한다.
- 색 차이 34 이상인 연결 영역과 새 알파를 찾고, 작은 먼지와 끊어진 조각을 제거한다. 경계를 넓히더라도 기준 몸과 차이가 12 이하인 화소는 부품에 넣지 않는다. 이 조건이 회색 속옷 가장자리의 재등장을 막는다.
- 동물 귀와 용 뿔은 `ears`, 꼬리·날개는 `back`으로 분리한다. 용의 비늘 두피가 귀 층에 들어가지 않도록 뿔 윤곽과 색을 따로 지정했다. 요정 날개·꼬리는 기준 몸 바깥에 보이는 영역만 남겨 몸과 팔을 덮지 않는다.
- 원본 종족의 발·종아리 사각 영역 `[300,1250,660,1468]`에서 불투명 윤곽을 양방향 거리로 비교한다. 최대 2화소를 넘으면 빌드를 중단한다. 장식이 겹치는 영역을 피한 원본 정렬 검사다. 납품 몸은 y700 아래 전체 알파를 기준과 다시 비교하고 한 화소라도 다르면 중단한다.
- 모든 몸은 회색 기본 의복을 공유한다. 일반 종족의 아랫몸은 기준 몸을 그대로 보존하고, 고정 피부 종족은 피부의 색·무늬만 옮긴 뒤 기준 알파를 보존한다.

## 마스크와 색 이동

회색조 마스크는 피부·홍채의 해부 영역, 앞·뒤 머리의 실제 추출 영역, 옷 천의 수동 지정 영역에서 만든다. 얼굴을 큰 사각형으로 제외하지 않으며 눈썹 모양만 제외한다. 저채도 올리브·하늘색 옷도 수동 지정 영역 안에서 잡는다. 룬대장장이의 허리띠·주머니·공구는 별도 윤곽으로 제외한다. 마스크는 원본에서 한 번 확정하며 선택한 팔레트 색으로 영역을 재추론하지 않는다.

`pipeline.recolor(image, mask, target)`가 계약 4-3의 파이썬 정본이다.

1. 마스크>0, 원본 알파>0, 명도>0.22, 채도>0.12인 화소만 선택한다.
2. 그 화소들의 채도와 명도 중앙값을 구한다. 짝수 개는 가운데 두 값의 평균이다.
3. 목표 HSV에 `s/m_s × max(s_t,0.04)`, `v/m_v × v_t`를 적용하고 0~1로 제한한다.
4. 마스크/255 비율로 원래 RGB와 혼합한다. 원래 알파는 보존하며 마지막에 반올림한다.

화면 구현도 같은 중앙값·대상 제외 조건·반올림을 써야 한다. `test_pipeline.py`에는 선·무채색·투명·빈 마스크·부분 마스크·명암 비율·저채도 목표색을 확인하는 수치 예제가 있다.

색상 마스크 파일은 RGB 세 채널이 같은 불투명 회색조 WebP다. 화면에서 마스크의 빨간 채널을 강도로 읽는다. **마스크 알파를 강도로 읽으면 안 된다.** 원본 부품 자체의 알파는 별도로 보존한다.

납품은 512×768 WebP 82개이며, 파일당 150,000바이트·전체 6,000,000바이트 한도를 검사한다. 확인판 JPG 합계는 3,000,000바이트 한도로 검사한다. 원본 1024판과 중간 파일은 커밋하지 않는다.

## 2차: 짙은 피부의 머리 경계 정리

원본의 밝은 피부와 머리 선이 섞인 화소는 차분 임계값만으로 모두 걸러지지 않았다. 얇은 가닥의 알파를 깎으면 머리가 끊어지므로 `edge_cleanup.restore_outline`에서 알파를 그대로 두고 RGB만 가까운 어두운 선 색으로 바꾼다. 원본 1024판과 최종 512판에 모두 적용한다. 머리 앞·뒤 12개 층 전체의 경계 안쪽 3.5납품화소를 정리한다. 귀·뿔·꼬리·날개는 몸의 피부와 색이 비슷한 접점 경계만 정리한다. 노란 크림색 뿔은 피부색과 구분하며, 고정 피부 용인은 청록색 몸을 비교 기준으로 삼는다.

정리한 머리와 종족 부속은 **무손실 WebP**로 저장해 손실 압축의 색 번짐이 재발하지 않게 한다. 머리 마스크는 투명 알파와 중복으로 흐려지지 않도록 부품이 있는 경계까지 흰색을 채운다. 금색 머리끈의 수동 제외 영역은 유지한다.

`edge_audit.py`는 실제 납품 WebP를 다시 디코딩하고, 피부에 인접한 머리 경계 및 종족 부속 경계에 밝은 기준 피부 유사색이 남았는지 검사한다. 이 검사는 `test/character-art.test.js`에서 실행된다. `npm test` 환경에도 Python 3와 Pillow가 필요하며, `CHARACTER_ART_PYTHON`으로 사용할 파이썬을 지정할 수 있다. 이 회귀 검사 자체에는 NumPy나 SciPy가 필요 없다.

`edge_proofs.py`는 s1·s6의 머리 8종, 긴 머리 뒤층, 종족 귀·뿔·꼬리·날개 확대 확인판을 만든다. `--before /이전/그림폴더`를 주면 h1·s6 수정 전후 비교판도 만든다. 고정 피부 두 종족은 s1·s6 요청에도 원래 피부가 그대로 보인다.
